# 接地标准（grounding.md）

本标准约束两件事：(a) 语料库文件本身怎么写；(b) 蒸馏出的 skill 怎么说话。
锚点规则移植自 `optimization-paper-collection/_EXTRACT.md`（用户自有的、已验证
可行的规范），数学声明纪律来自 autoresearch-optimization 的固定研究顺序约定。

## 1. 验证层级（每条语料必须标注其一）

| 层级 | 含义 | 使用规则 |
|------|------|---------|
| `verified-local` | 已与本地确定性工件交叉核对（注明工件路径） | 可直接引用，含 DOI/URL |
| `model-knowledge (high)` | 教科书级共识，但元数据（卷号/页码/确切 venue）未核对 | 可引用结论；**写进论文前必须核对元数据**；语料中故意省略卷号页码，防止编造的精确数字看起来可信 |
| `需核对` | 怀疑有出入的具体细节 | 引用时必须连同此标记一起说出来 |

**原则：编造的常数比空字段更糟，因为它看起来可信、能活过审查。**
（_EXTRACT.md 原话的转述；该文件同时规定：不在来源里的字段写 `not stated`，
绝不按领域惯例或相似论文的做法推断补全。）

## 2. 锚点规则

- 语料库中每条实质声明注明来源定位：`(Thm 3.1)`、`(§2.2)`、`(DOI …)`、
  `(sources.json: src-more-2009-benchmarking)`。
- 暂时给不出定位的教科书级结论，标 `(unanchored)` 而不是删掉——
  `(unanchored)` 是诚实信号，无标记的声明才是违规。
- 蒸馏出的 skill 在回答中引用结论时，带语料 ID（`[DFO-R3]`），
  使用户可以一跳回到语料核查。

## 3. 数学声明纪律（对 skill 的输出约束）

1. **一律最小化形式**：所有问题陈述为 min f(x)；最大化通过取负转化。
   （用户固定约定。）
2. 任何**收敛速率 / 复杂度界 / 定理**必须同时给出：
   - 适用假设（凸性？L-光滑？噪声模型？维度？）
   - 语料结果 ID
   - proved-in-source vs cited-by-source 标注
3. 速率不带精确常数——语料库故意只存**定性速率 + 假设 + 出处**。
   需要精确常数时，skill 的正确回答是「常数需查原文 [ID]，语料记录的定性结论是…」。
   （教训实例：Nesterov 1983 的领先常数在不同转述中就不一致，
   本地条目 `nesterov-1983-accelerated-gradient.md` 自己都标了 verify。）
4. 维度因子不许吞掉：zeroth-order 速率里的 n 或 √n 因子是该领域的核心事实，
   省略它就是胡说。
5. 噪声模型不许混用：确定性噪声 / 有界噪声 / 随机噪声下的保证互不迁移，
   引用时必须声明是哪种。

## 4. 语料封闭原则（对蒸馏过程的约束）

- 蒸馏期间**零网搜**。语料不足 ⇒ 写入 skill 的诚实边界（「语料库截至 YYYY-MM-DD
  未覆盖 X」），不准从模型记忆补。
- skill 中出现的每个（作者, 年份）对必须存在于 `01-canon.md`。
- 05-failure-modes.md 中列出的陷阱必须整体移植进 skill 的「绝不做」清单。

## 5. 为什么这么严

2026-07-25 的专业审计（autoresearch-optimization/docs/reviews/）批评 #7：
「文献对象缺少段落定位、文本哈希、证据质量分级、entailment 状态」。此前的
team 胡说，机制正是：验证门只查论文**存在**，没人查论文**内容**；加上检索
断粮，agent 用参数记忆填空。本标准把两个洞一起堵：内容必须有锚点，
来源必须在语料内。
