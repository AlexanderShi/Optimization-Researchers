### S094 · Improving branch-and-cut performance by random sampling (Mathematical Programming Computation 2016, DOI 10.1007/s12532-015-0096-0)
**Read level**: full. pp. 1-17 read closely (text, Algorithm 1, Tables 1-7); appendix Table 8 (pp. 18-21) and the references (pp. 17-18) skimmed.
**Role**: core · **Co-authors**: Andrea Lodi, Michele Monaci, Domenico Salvagnin, Andrea Tramontani (CPLEX Optimization, IBM; p. 1) · **Position in trajectory**: the erraticism and sampling line of SKILL.md's trajectory (2010-2016); builds on the authors' own "Exploiting erraticism in search" ([10], p. 3) and moves from selecting one of several sample runs to merging what all root samples found; partly funded by the Padova project on exploiting randomness in MILP (p. 17); the only paper of this batch with a vendor co-author and a vendor testbed.

- **D1 Problem and entry**: Entered from a measured anomaly in the tool. Danna's 2008 example: the same CPLEX 11 release solved 10teams in 0 nodes on Linux and in 1,426 nodes on AIX, later explained as imperfect tie-breaking (p. 2). Among the sources of variability the authors take the "obvious" first one, dual degeneracy of the first LP relaxation: the simplex returns an arbitrary optimal basis, and that basis feeds Gomory-type cuts, rounding heuristics and branching (pp. 2-3); it is studied first because it is met first, right after preprocessing (p. 3). Before any algorithm, §2 shows that the variability is not CPLEX-specific: 10 row and column permutations per MIPLIB 2010 instance on CPLEX 12.5.0, GUROBI 5.1 and XPRESS 23 give comparable variability scores (standard deviation over mean), with little agreement per instance between solvers, explained by problem difficulty and preprocessing differences (p. 5, Fig. 1 p. 6).
- **D2 Core idea**: The "best" optimal basis cannot be characterized inside a real solver, since a basis good for cuts can be bad for heuristics and the components are heuristic themselves (pp. 5-6). So sample the optimal face: run the default root cut loop and primal heuristics from K-1 different optimal bases, pool all cuts and solutions, and start one final run from the enriched root (Algorithm 1 `ksample`, p. 7). What changes is only the starting basis of the root loop, plus the pooling; separators, heuristics and branching stay the solver's defaults (p. 3, p. 7). One parameter steers between two goals: a large K for stability, a small K for speed (p. 4, p. 7). For simplicity, random pivots on the optimal face are replaced by the public CPLEX random-seed parameter CPX_PARAM_RANDOMSEED, available since 12.5.0 (p. 8).
- **D3 Problem class and data model**: General MIP min{c^T x : Ax >= b, x >= 0, x_j integer for j in I} with the structure of A not exploited (p. 1). The device presumes dual-degenerate root LPs, which the authors call usual (p. 2, p. 5). Test sets: the MIPLIB 2010 benchmark and primal sets, 121 instances (p. 7); bley_xl1, ex9 and ex10 removed because preprocessing once disables probing and makes them pathological for both arms (p. 9); glass4 (seeds gave slightly different optimal values) and three infeasible instances left out of the root statistics, which cover 117 instances, 79 benchmark and 38 primal (pp. 9-10); glass4 left out of the tree runs, 120 instances (p. 11). Then a CPLEX-internal testbed of 3,221 public and commercial models (p. 12). No correctness argument is needed beyond preprocessing once, so that cuts and solutions from all runs live in the same space (p. 8).
- **D4 Algorithm and implementation design**: Research code in C++ on the CPLEX 12.5.0 callable library (p. 7). Preprocess once; K-1 root-only runs with different seeds collect cuts and feasible solutions; the final run starts from scratch, without presolve, and receives the best solution and the pooled cuts through callbacks at the end of its root node, which simulates a parallel version in which sample information arrives only after the root (pp. 8-9). Every arm runs traditional branch-and-cut (dynamic search off), no preprocessing and one thread, and the baseline `cpxdef` is the same code with K = 1 (p. 9). Product version in CPLEX 12.5.1: K = 2, two concurrent cut loops (possibly rooted at two different optimal bases) with random diversification, synchronized deterministically by sharing solutions and cuts, and a final step that collects and filters both (p. 12); K > 2 was tried and degraded performance, because overhead grows with K while the diversification gain saturates (p. 12). No theorem or proof (n/a); the root measure igap follows Berthold's primal-heuristic measure (p. 9).
- **D5 Computational evaluation**: The cluster is shared, so deterministic ticks replace wall-clock: limit 10^7 ticks (about 3 hours), shifted geometric means with shifts 10^3 ticks and 10 nodes (p. 8). Root (K = 10, 10 seeds per instance, seeds for the samples derived from the final run's seed): average integrality gap 56.91% to 35.81% and its per-instance standard deviation 7.08% to 4.19%; primal gap 51.10% to 27.80%; dual gap nearly unchanged, 15.07% to 14.59% (Table 1, p. 10). Tree (5 seeds): about 15% fewer ticks and 25% fewer nodes in every seed (Table 2, p. 11); the spread of ticks across seeds falls by more than half on the whole set but not on the subset both arms solve (p. 11). Time accounting is argued both ways: crediting 0 ticks to instances solved during sampling would favour ksample, dropping them would be unfair to it, so the sampling root that solved the instance is charged (pp. 10-11); sampling overhead is ignored in §4 and measured in §5 with a real parallel version (footnote 1, p. 11). Product test (CPLEX 12.5.1, 3,221 models, 10,000 s, 6 GB tree memory, 12-core Xeon E5430 at 2.66 GHz): classes [n,10k] and [n,10k) defined through both compared solvers to avoid bias, an "affected" subset whose solution paths differ, time-limit hits counted per side, and a named bias of the 10,000 s convention against the solver with fewer timeouts (pp. 13-14). Five seeds (Tables 3-7, pp. 14-16): time ratios 0.97-0.99 on all models and larger gains on harder classes, the gain on [100,10k] ranging from 1.02x to 1.16x by seed (p. 14). Losses are printed but not discussed: ksample solves one instance fewer than cpxdef in seeds 2 and 3 (104 vs 105, 106 vs 107; Table 2, p. 11), although p. 4 says it solves more; 2-sample hits the time limit more often than no-sample in seeds 4 and 5 (11/17 and 10/13 on [n,10k]; Tables 6-7, p. 16). No statistical test; the word "significant" (pp. 11, 17) is used without one.
- **D6 Positioning**: Credits Danna 2008 for naming performance variability and the MIPLIB 2010 paper for the tie-breaking explanation, and points to the Lodi-Tramontani tutorial (p. 2). Places the scheme beside restart strategies from SAT (Gomes et al.), the authors' own bet-and-run selection [10], Achterberg's 2010 cut filtering through an alternative optimal LP solution, Carvajal et al.'s CutsComm (whose authors found cut sharing not very helpful in their setting) and the ParaSCIP racing ramp-up (p. 3). No critique of other work; the novelty is narrowed to the basis-selection source (p. 3).
- **D7 Writing and rhetoric**: A labelled "Our contribution." paragraph that concedes variability and then turns it into an opportunity (p. 3); the two uses of K as a two-item list (p. 4); the move into the CPLEX 12.5.1 default announced in the introduction and repeated, as the result of impressive results, in the conclusions (pp. 4, 17). Hedges sit in parentheses and scare quotes: a "(hopefully)" stabilized root (p. 7), a "better" root node (p. 11). No theorems; the tables carry the argument.
- **D8 Contribution and limits**: Algorithmic and industrial: a root-sampling scheme, a stability study and a product default (pp. 4, 12, 17). The adoption is the authors' statement, made with an IBM co-author (p. 1); no release note is cited. Limits are stated specifically: variability in the branching tree is untouched and named as the main open question (pp. 11, 17); the stabilized, large-K version may not pay in running time because of synchronization and threads taken from other work (p. 4); K > 2 is not worth its overhead in CPLEX (p. 12); preprocessing once only approximates a default CPLEX run (p. 9).

**Method links**:
- Method 3 ✅ evidence: the spread is measured before it is used (10 permutations on 3 solvers, p. 5; 10 seeds per instance at the root, p. 9), seeds sit in every table (Tables 2-7, pp. 11-16), and only then is the spread exploited (pp. 3-4, 7). There is no null-content placebo arm; the seed-only baseline cpxdef over the same seeds is the control (p. 9). The device uses a public solver parameter rather than internal basis loading (p. 8), which bears on the critics' point under Method 3's limitations.
- Method 3 ⚠ variant (step 4): instead of betting on one randomized run, as bet-and-run does, all short runs are merged into one root (pp. 3, 7); where it does not pay is printed: tree stability (p. 11), K > 2 in the product (p. 12).
- Method 4 ✅ evidence: classes defined by both compared solvers to avoid bias (p. 13); the baseline is the same code with K = 1 and identical settings (dynamic search off, one thread, no preprocessing; p. 9); exclusions listed with reasons (p. 9); sampling-time accounting argued in both directions (pp. 10-11); the bias of the time-limit convention named (p. 13).
- Method 6 ✅ evidence: the solver's own cut loop and heuristics do the work and only the starting basis changes (pp. 3, 7); the seed parameter replaces random pivots for simplicity (p. 8).
- Method 2 ⚠ variant: separators and heuristics are left alone and the point the loop starts from (the root basis) is changed (pp. 2-3, 7); the motive is variance, not a stalling loop.
- new-pattern candidate: one knob, two goals (K steers between stabilization and speed; pp. 4, 7, 12).
- new-pattern candidate: honest sequential simulation of a parallel scheme (pp. 9-12).
- new-pattern candidate: public prototype, then vendor default on the vendor's testbed (pp. 1, 4, 7, 12-17).

**Transferable techniques**:
- (D2) Give the scheme one parameter that moves it between two goals: a large sample count to study and reduce variability, a small one for the shipped default (pp. 4, 7, 12).
- (D4) Preprocess once and give every sample and the final run that same model, so that cuts and incumbents from different runs live in one space (p. 8).
- (D5) Simulate a parallel scheme sequentially without flattering it: restart the final run from scratch, inject the pooled information only where a parallel version would have it (end of root, through callbacks), and charge time with a rule that neither credits zero ticks nor drops the instances solved during sampling (pp. 9-11).
- (D5) Before proposing a variance remedy, show the variance is solver-independent: 10 row and column permutations per instance on three solvers, the per-instance variability score (standard deviation over mean), pairwise scatter plots (p. 5, Fig. 1 p. 6).
- (D5) Root-node stability table: integrality, primal and dual gaps against known optima, with the mean and the mean per-instance standard deviation over 10 seeds (pp. 9-10).
- (D5) Vendor-style class reporting: [n,10k] (solved by at least one arm, at least n seconds for one) and [n,10k) (solved by both), the "affected" subset with differing node and iteration counts, time-limit hits per side, all repeated for 5 seeds (pp. 13-14).
- (D5) On a shared cluster report deterministic ticks and state the shifts of the geometric means (10^3 ticks, 10 nodes) (p. 8).

**Quotes**:
- "a good strategy is to sample the optimal face of the (initial) LP relaxation" (p. 7)
- "This confirms that reducing variability during enumeration is still an open issue." (p. 11)

### S011 · Redesigning Benders decomposition for large-scale facility location (Management Science 2017, DOI 10.1287/mnsc.2016.2461)
**Read level**: full. pp. 1-19 read closely (models, cut derivations, Algorithm 1 with Lemma 3.1 and Theorem 3.1, implementation §4, results §5, conclusions) and Tables 2-5 (pp. 23-25); the references (pp. 20-22) skimmed. The text is the author preprint dated February 11, 2016 (p. 1).
**Role**: core · **Co-authors**: Ivana Ljubić (ESSEC), Markus Sinnl (University of Vienna) (p. 1) · **Position in trajectory**: the thinning-out line of SKILL.md's trajectory (2014-2020); WWTF project ICT15-014 with Ljubić and Sinnl (p. 20); the in-out loop comes from Fischetti and Salvagnin 2010 ([13], p. 12) and local branching and proximity search are reused as sub-MIP heuristics (p. 16).

- **D1 Problem and entry**: Entered from scale. Location models from business analytics and the Internet of Things carry millions of allocation variables, general-purpose MILP solvers struggle with them, and Lagrangian relaxation is generally preferred (pp. 1-2). The working hypothesis, stated in the abstract, is that exact decomposition schemes proposed decades ago and dropped soon after need a redesign for today's hardware and software (p. 1), framed as rediscovering "sleeping beauties" (p. 2). For linear UFL, Benders had been studied (Cornuéjols, Nemhauser and Wolsey; Magnanti and Wong) and then left for 30+ years without a computational study (p. 6). The quadratic variant qUFL enters as a standard test problem of MINLP methods and as a subproblem of power-distribution design (pp. 2, 4).
- **D2 Core idea**: Remove the allocation variables x_ij, which the authors call the bottleneck for MIP solvers, and replace them by one continuous variable w_j per customer (the fat model) or a single w_sum (the slim model), bounded below by (generalized) Benders cuts separated on the fly at every node of a stock branch-and-cut (p. 5, pp. 10-11). Changed: the formulation, by projection, and the root cut loop, by in-out stabilization (§4.2, pp. 12-14). Kept: CPLEX 12.6 as the framework for node LPs, primal heuristics, general MILP cuts, branching and the cut pool (p. 11), and Kelley's loop at the non-root nodes (p. 14). Why: a sound Lagrangian code is far from trivial, so a simpler approach with far fewer variables on an off-the-shelf solver was chosen (p. 19).
- **D3 Problem class and data model**: UFL with linear allocation costs c_ij >= 0 and every customer allocatable to every facility (c_ij set to infinity otherwise) (p. 3); qUFL with unit demands, c_ij > 0 and costs c_ij x_ij^2, whose compact baseline is the Günlük-Linderoth perspective (second-order cone) model (5)-(11) (p. 4). Master: binaries y_i with at least 2 open facilities; the single-facility case is preprocessed, and for linear instances with n <= 1000 all 1- and 2-facility solutions are enumerated (p. 5). The GB cuts assume convexity and constraint qualifications (p. 5); the QP derivation assumes y* > 0, near-zero entries being handled in §4.1 (p. 7, pp. 11-12). Data: UFLLIB instances M* (100 x 100 to 2000 x 2000) and Körkel-Ghosh instances with n = m in {250, 500, 750} and cost subclasses a, b, c (pp. 16-17); ORLIB instances with zero allocation costs replaced by 10^-5 (p. 17); random qUFL instances of Günlük et al. and Günlük-Linderoth, plus new ones up to 2000 facilities and 10000 customers (p. 18). Uncapacitated only: the capacitated case is called not immediate (p. 19).
- **D4 Algorithm and implementation design**: Proof devices: the GB cut from a subgradient assembled from Lagrangian multipliers under KKT conditions, after Geoffrion (eq. 18, p. 5). For linear costs the subproblem is a continuous knapsack solved by Dantzig's critical-item rule and certified by equal primal and dual cost (p. 6); the cut becomes w + sum_{i<k} (c_k - c_i) y_i >= c_k, so only n distinct cuts exist per customer (p. 7). For quadratic costs, an ad hoc QP routine (Algorithm 1, p. 9) is proved correct by a monotonicity lemma on the multiplier beta (Lemma 3.1) and a KKT check (Theorem 3.1) (p. 10); it is written out so that the results can be reproduced (p. 8). A projection argument shows fat and slim masters give the same bound (p. 11). Loop design: in-out at the root with the stabilizer y~ = (1,...,1) moved halfway towards each LP optimum, separation at lambda y* + (1 - lambda) y~ + delta (1,...,1), lambda = 0.2 and delta = 2 epsilon, then lambda = 1 after 5 iterations without bound improvement, delta = 0 (plain Kelley) after 5 more, abort and drop slack cuts after 5 more, slack cuts also dropped every 5th iteration (pp. 12-13); it runs as a preprocessing function, so it changes only the root formulation and bound (p. 14). In the tree: Kelley through the user-cut callback, at most 20 rounds per node (2,000 at the root), cuts added as local so that CPLEX can purge them, which mattered for linear costs (p. 14). Integer master points: one aggregated optimality cut (45) in the lazy-constraint callback instead of many per-customer cuts (p. 15). Heuristics: threshold rounding in O(sigma log sigma + sigma m) time (p. 15); local branching with radius 5 then 10, then proximity search, 5,000 ticks per call (p. 16); for qUFL only fixed-threshold rounding, since the method needed no more (p. 16). Numerics: perspective strengthening skipped when y*_i < epsilon = 10^-5 or y*_i > 1 - epsilon; the 2 epsilon trick (separate at y* + 2 epsilon, cuts always valid, violation slightly underestimated) (p. 12); CPX_PARAM_EPINT = 0, EPGAP and EPRHS at 10^-9, internal tolerance 10^-9 (p. 16); a validity test after Margot: fix the incumbent, perturb 80% of its entries by 10^-9 to 10^-1, separate, add the cuts, re-solve, 10,000 times, dump the model on infeasibility; it caught tolerance issues in earlier versions (p. 16).
- **D5 Computational evaluation**: Xeon E3-1220V2 at 3.10 GHz with 16 GB, wall-clock seconds, 4 threads; basic settings, with local branching and proximity search parameters left untuned (p. 16). Trace evidence on one instance first: gs250a-1 (qUFL, 250 x 250, single thread), all three loops calling exactly the same GB separator (p. 13). Fat model: Kelley stopped after 15,000 s still at the root with bound 1,781.04 and over 100,000 cuts; Kelley+ (the 2 epsilon trick) took 948.86 s for the root and finished at 978.53 s; in-out took 0.19 s for the root with 748 cuts and finished at 0.41 s after 6 nodes (pp. 13-14). Slim model: Kelley stopped after 500 nodes (8,208.67 s); Kelley+ finished at 100.66 s; in-out took 0.04 s for the root with 4 cuts and finished at 0.06 s after 11 nodes (p. 14; Fig. 1 p. 13). Fat against slim on MT1 (2000 x 2000, 4 threads; Fig. 2, p. 15), and the choice per cost class: slim for quadratic costs, fat for linear costs, where a weaker root bound means many nodes and Kelley's single cut per call recomputes node bounds poorly (p. 14). Linear UFL: branch-up-first (CPX_PARAM_BRDIR = 1) to keep node files small under 16 GB (p. 17); seven previously unsolved instances solved, e.g. 2500-10 in 824.76 s (Table 1, p. 17); 50 KG instances still out of reach, where modified local branching (variants A and B, four concurrent single-thread runs with different seeds, best solution kept) improves 22 best-known values, matches 22 and stays worse on 6 by less than 0.04% (p. 18, Table 2 p. 23). qUFL: against the perspective model run with CPX_PARAM_MIQCPSTRAT = 1, which worked much better than the default, speed-ups of up to four orders of magnitude, the perspective model hitting the memory limit from n, m >= 200 (Table 3, p. 18, p. 24); slim beats fat at scale, average root gaps below 0.04%, the largest instances in about 5 minutes (Table 4, p. 18, p. 25); every KG instance solved as qUFL, the hardest (MT1) in 81.99 s against 4,889.77 s and 10,675 nodes for the linear code (pp. 18-19; Table 5 p. 25). No seeds or repetitions are mentioned for the exact runs; tables per instance or per class, no performance profiles.
- **D6 Positioning**: Measured against the Lagrangian state of the art: Posta et al.'s cooperative method (a metaheuristic for upper bounds, a bundle-solved Lagrangian for lower bounds) and Beltran-Royo et al.'s semi-Lagrangian relaxation, compared through instances solved and best-known values from the literature (pp. 3, 17). In-out credited to Applegate et al., Ben-Ameur and Neto, Fischetti and Salvagnin, and Naoum-Sawaya and Elhedhli (p. 12); bundle methods named as the stronger alternative, known to beat Kelley by a large margin in the equivalent Lagrangian-dual setting (p. 12); the 2 epsilon trick credited to many authors including Ben-Ameur and Neto, and related to Grossmann and Lee's perturbed perspective inequalities (p. 12); QP routines from Hochbaum-Hong and Patriksson-Strömberg (p. 8); Margot for the cut test (p. 16). The critique targets a community habit, not a paper: attention to the polyhedral strength of cuts while Kelley's loop is taken for granted (p. 12).
- **D7 Writing and rhetoric**: A working hypothesis in the abstract (p. 1); scare-quoted coinages ("thinning out", "sleeping beauties", "perspective costs"; pp. 1-2, 8); surprise marked twice, qUFL turning out easier than linear UFL (p. 3, p. 18); the key ingredient flagged in so many words at the head of §4.2 (p. 12); colloquial asides, such as MIP people's Pavlov's aversion to aggregated formulations (p. 11) and resisting the temptation to apply the perspective strengthening (p. 12); an ellipsoid-method analogy arguing that weak cuts can serve a sound loop (p. 12); the potential impact as two bullets (p. 19).
- **D8 Contribution and limits**: Algorithmic and computational: 7 open UFLLIB instances solved, 22 best-known values improved, qUFL instances with up to 40 million variables and 20 million second-order cone constraints solved (pp. 2-3, 19). Limits stated concretely: big-data instances arising in practice still cannot be solved directly (p. 2); 50 linear KG instances remain open (p. 17); Kelley is kept in the tree because a better loop inside CPLEX is not immediate (p. 14); no real bundle method was implemented (p. 12); the capacitated case is not immediate (p. 19). Future work: connected facility location, ring-star, median cycle and traveling purchaser problems; convex MINLP solvers; nonlinear stochastic programming (p. 19).

**Method links**:
- Method 1 ✅ evidence: the allocation variables are projected out (pp. 1, 5), then the w_j are aggregated into w_sum (pp. 10-11); fat and slim are run on the same instances and chosen per cost class by measurement (pp. 13-15).
- Method 2 ✅ evidence: the loop's convergence is put down to the choice of the point to cut, not to cut strength (p. 12); in-out with the stabilizer started at all ones and moved halfway (p. 12); all compared loops call the same separator (p. 13); the 2 epsilon perturbation alone rescues Kelley (pp. 13-14); stabilization at the root only, with the reason (p. 14).
- Method 6 ✅ evidence: a stock MILP solver plus one plugged-in separator as a quick shot, which already solved the open instances 2500-10 and 3000-100 in under 15 minutes each on a PC (p. 11); a simple in-out variant instead of a bundle method (p. 12); no qUFL-specific heuristics because none were needed (p. 16); his own sub-MIP heuristics run through the solver (p. 16).
- Method 4 ✅ evidence (partial): the compact baseline runs with the CPLEX setting that suits it best (MIQCPSTRAT = 1, p. 18) while the new code runs with basic, untuned settings (p. 16). Comparisons with the Lagrangian literature go through solved status and best-known values, not a common harness (pp. 17-18).
- Method 3 ⚠ variant: seeds appear only as a resource (four concurrent seeded single-thread runs, best solution kept; p. 18); no seeds are mentioned for the exact runs (p. 16). With speed-ups of orders of magnitude this does not threaten the conclusions.
- Outside the numbered methods: Research Taste mark 1 ✅ (open instances fall to a first plug-in separator on a PC, p. 11) and mark 4 ✅ (a discarded classical method redone with today's technology, pp. 1-2, 6); Research Heuristic 1 ✅ (the slim model against the reflex to disaggregate, p. 11; loop design against the habit of judging cuts by polyhedral strength, p. 12); Research Heuristic 8 ✅ (traces on one instance before any table, Fig. 1 p. 13); Research Heuristic 10 ✅ (the Margot-style validity test, p. 16).
- new-pattern candidate: closed-form subproblem oracle with a proof (pp. 6-10).
- new-pattern candidate: numerically safe by construction (pp. 11-12, 16; also S016 pp. 19-21).

**Transferable techniques**:
- (D4) In-out root loop with its constants: y~ := (1,...,1); each iteration y~ := (y~ + y*)/2 and separate at lambda y* + (1 - lambda) y~ + delta (1,...,1) with lambda = 0.2, delta = 2 epsilon; after 5 iterations without bound improvement set lambda = 1, after 5 more delta = 0, after 5 more stop and drop slack cuts; drop slack cuts every 5th iteration (pp. 12-13).
- (D4) When the Benders subproblem is a continuous knapsack, sort the costs, find the critical item and write the cut in closed form; only n distinct cuts exist per customer (pp. 6-7).
- (D4) Inside a separator, replace a general QP solver by a small exact routine with a proof (truncate the violated bounds and re-solve on the residual set; Algorithm 1, Lemma 3.1, Theorem 3.1; pp. 8-10).
- (D4) Near degenerate values, skip a numerically risky strengthening (perspective off for y*_i < 10^-5 or > 1 - 10^-5) and separate at y* + 2 epsilon, which keeps cuts valid and also helps plain Kelley (p. 12).
- (D4) For integer master points add one aggregated optimality cut in the lazy callback instead of flooding the pool with per-customer cuts (p. 15); add tree cuts as local so the solver can purge them, and cap rounds per node (20; 2,000 at the root) (p. 14).
- (D4) Cut-validity stress test: fix the incumbent, perturb 80% of its entries by 10^-9 to 10^-1, separate, add, re-solve, 10,000 times, and dump the model on failure (p. 16).
- (D5) One-instance trace figure: the same separator under three point-selection policies, log time axis, active cuts at the end of the root and of the run (Fig. 1, p. 13); then fat against slim on a second instance (Fig. 2, p. 15).
- (D5) Run the compact baseline with the solver option that suits it best, and say so (MIQCPSTRAT = 1, p. 18).

### S016 · A new general-purpose algorithm for mixed-integer bilevel linear programs (Operations Research 2017, DOI 10.1287/opre.2017.1650)
**Read level**: full. File pp. 3-37 read closely (model, assumptions, FUB cuts, preprocessing, Theorems 1-6, separation MILPs, Algorithm 1, implementation, every computational subsection, Tables 1-6); Appendix A with Algorithm 2 and Theorem 7 (pp. 37-40) read; repository cover sheets (pp. 1-2) and the references (pp. 40-43) skimmed. The text is the accepted manuscript OPRE-2016-07-379.R3 (pp. 1-3).
**Role**: core · **Co-authors**: Ivana Ljubić, Michele Monaci, Markus Sinnl (p. 3) · **Position in trajectory**: extends the authors' IPCO 2016 intersection-cut solver for bilevel programs (Fischetti et al. 2016b; p. 6, p. 42); same WWTF project as S011 (p. 40); the paper SKILL.md cites for the claim to beat problem-specific methods and for comparisons with rivals' published times.

- **D1 Problem and entry**: Entered from applications with hierarchical decision makers (energy pricing, airline and telecom pricing, transportation, infrastructure defense, machine learning; p. 4) and from the scarcity of generic solvers, although the formulation dates from 1973 and the problem is NP-hard even with LP levels and Σ2-hard as a MIBLP (pp. 4-5). The direct entry is the authors' own 2016 solver, a branch-and-bound built on a MILP solver that handles every issue not specific to bilevel programs (p. 6). The obstacle named is that the high-point relaxation (HPR) can give arbitrarily weak bounds, so deep cuts are needed early in the tree (p. 10).
- **D2 Core idea**: Keep the 2016 scheme (branch-and-cut on the HPR, with bilevel feasibility checked by solving the follower MILP; Appendix Algorithm 2, p. 39) and add: (i) locally valid follower upper-bound (FUB) cuts from a worst-case restriction of the follower at the node's variable bounds (Theorem 1, p. 11); (ii) follower preprocessing that fixes follower variables whose value is forced for every leader decision (Theorem 2, pp. 11-12); (iii) new intersection-cut (IC) families from other bilevel-free sets: Xu's set X(Δŷ), extended by one unit under integer slacks (Theorems 3-4, pp. 13-14), enlarged by facet removal (Theorem 5, Corollaries 1-2, pp. 14-15), and hypercube ICs that need no integer slacks (Theorem 6, p. 16); (iv) separation by auxiliary MILPs that choose the bilevel-free set with the most removable facets (SEP2, (28)-(35), pp. 17-18; XU, (36)-(40), p. 18); (v) a numerically safe IC derivation (Algorithm 1, pp. 19-20). The default, MIX++, separates both IC types and adds FUB cuts and preprocessing (pp. 29, 31-32).
- **D3 Problem class and data model**: Optimistic mixed-integer bilevel linear programs, integer and continuous variables at both levels (pp. 3, 5). Assumption 1: continuous leader variables may not appear in the follower problem (J_F ⊆ J_x), needed for finite convergence (p. 8); Assumption 2 (bounded HPR, finite optima) adopted to simplify the presentation (p. 8); Assumption 3 (Ax + By - b integer on HPR solutions) needed only by some ICs (p. 8); d integer after scaling (p. 17). No literature instance with continuous leader variables satisfying Assumption 1 was found, so every tested leader is integer (p. 8, p. 22). Testbed: 874 instances in ten classes, 307 general bilevel and 567 interdiction (p. 22, Table 1 p. 25), including a MIPLIB class built from binary MIPLIB 3.0 instances by declaring the first Y% of the variables follower variables (p. 23); interdiction instances are solved as general bilevel programs, without their structure (p. 22). The authors warn that one public instance repository has wrong coefficients and point to the correct source (pp. 22-23).
- **D4 Algorithm and implementation design**: Proof devices: a restriction of the follower overestimates the value function (Theorem 1, p. 11); a dominance argument for fixing, where the optimistic setting forces strict sign conditions and leaves variables with d_j = 0 free (pp. 11-12); an improving-direction argument (Theorem 3, after Xu, pp. 13-14); integer slacks turn "interior" into the closed set (Theorem 4, p. 14); a half-space test with variable bounds removes facets (Corollary 1, p. 15); integrality of the linking leader variables gives the hypercube (Theorem 6, p. 16); finiteness by domain reduction (Theorem 7, p. 40). IC derivation through the disjunctive interpretation (Glover; Glover and Klingman): project the basic variables out of each disjunction term, normalize to right-hand side 1, take the coefficient-wise maximum, clip the coefficients of integer variables at 1; validity rests on the original data, not on tableau precision, so numerical error can only reduce violation (pp. 18-20). Implementation on CPLEX 12.6.3: CPLEX presolve off on the HPR so that LP bases can be read, with the bilevel fixing applied instead (p. 20); tolerances 10^-9 (p. 20); opportunistic parallel mode, each thread with its own copy of the follower MILP (p. 20); CPLEX cuts left at their default, CPLEX heuristics off because each heuristic solution costs a follower solve (p. 21); branching priorities 2 for leader variables that appear in the follower, 1 for other leader variables, 0 for follower variables (p. 21); the lazy-constraint callback solves the follower at x*, cuts a bilevel-infeasible point with an IC, and passes (x*, ŷ) to a quick feasibility check that yields good incumbents early (p. 21); the user-cut callback separates FUB cuts once per node and ICs for at most max node cuts = 20 rounds, discarding cuts whose coefficient dynamism exceeds 10^6 or whose violation is below 10^-6 (|rhs| + 1) (p. 21, p. 25).
- **D5 Computational evaluation**: C code on a Xeon E5-2670v2 at 2.5 GHz with 12 GB, wall-clock seconds, 4 threads, limit 3,600 s (p. 22). Ablation against the authors' own 2016 settings SEP1 and SEP2: cumulative speed-up charts with the shifted ratio (t + 1)/(t' + 1) on the 50 DENEGRE instances (Fig. 2, pp. 26-27), where FUB cuts give up to 2-3 orders of magnitude with a few small slow-downs on instances solved in seconds, and preprocessing gives at least 10x on about 40-50% of the instances (p. 26). On MIPLIB, final-gap charts with gaps capped at 100% and no solution counted as 100%: SEP2 solves about 34%, with FUB cuts 39%, with preprocessing or both 42% (pp. 27-28, Fig. 3). IC families compared by Dolan-Moré profiles restricted to the instances every setting solves (55 of 107 general, 353 of 567 interdiction), which the text says are mostly solved within seconds (p. 29); MIX called robust, with SEP2 slightly better on interdiction and the overhead of two ICs named (p. 29); preprocessing has no effect on interdiction because Theorem 2 never applies there (p. 29). Hypercube ICs on XUWANG-LARGE: FUB cuts plus preprocessing about 2-3x faster (Table 2, p. 33). Literature comparisons: DENEGRE against the best SEP1 variant (Table 3, pp. 33-35); XUWANG against the times Xu and Wang reported for a 2.4 GHz desktop, with a hardware factor of 2-5x whose basis is not given (p. 34; Table 4 p. 36); INTER-KP2 and INTER-CLIQUE against the times Tang et al. reported for a 3.30 GHz PC with CPLEX 12.5 (pp. 34-36; Table 5 p. 36); MIPLIB against SEP2 on the same machine (Table 6, pp. 36-38), three optimal values obtained by a more aggressive setting and marked (p. 38). No seeds, no repetitions and no significance test are mentioned, under a nondeterministic parallel mode (p. 20). Losses visible in the tables but not named in the text (my reading of the extracted tables): MIX++ needs 2.6 s against 1.4 s reported by Xu and Wang at n1 = 10 (Table 4, p. 36); a 40-fold slowdown against SEP1 on miblp-20-20-50-0110-10-10, 73 s against 2,927 s (Table 3, p. 35); in Table 6 MIX++ ends with a lower bound below SEP2's on five instances (air05-0.9, l152lav-0.5, l152lav-0.9, nw04-0.5, nw04-0.9) and with no feasible solution on four where SEP2 has one (cap6000-0.9, mitre-0.5, mitre-0.9, p0548-0.5) (p. 38), while the text says the final lower bound is strictly better for all but three instances (p. 37).
- **D6 Positioning**: Reviews generic MIBLP methods (Moore and Bard; DeNegre and Ralphs' MibS, which needs pure integer levels; Xu and Wang's multi-way branching; Xu's watermelon algorithm; Caramia and Mari; parametric integer programming; Tang et al. for zero-sum problems) and names the authors' own 2016 solver the state of the art and the main reference (pp. 8-10). Credits Balas for ICs (pp. 7, 12), Xu (2012) for the polyhedron of Theorem 3, adding a short proof for completeness (p. 13), and Glover and Glover-Klingman for the disjunctive interpretation (pp. 18-19). Distinguishes the cuts from Audet et al.'s disjunctive cuts for continuous bilevel programs (p. 10). Contrasts with DeNegre, who had to switch solver cuts off (p. 21). Leaves out methods designed for nonlinear bilevel programs, because the comparison would be biased towards the authors' MIBLP-specific code and no implementation is public (p. 33).
- **D7 Writing and rhetoric**: Contributions as a bullet list in the introduction (p. 7); superlatives for scope (by far the most extensive study in the MIBLP literature, pp. 22, 37) and outcome (consistently outperforms, often by a large margin; pp. 3, 37); an implementation section justified by reproducibility (p. 20); every new ingredient comes with a short theorem and proof (pp. 11-16); hedges are rare ("hopefully" deep ICs, p. 13).
- **D8 Contribution and limits**: Algorithmic contribution with light theory (valid local cuts, a fixing rule, IC families, separation MILPs) plus software: solver, instances and optimal values are released (pp. 3, 7, 22, 37; Fischetti et al. 2017 at msinnl.github.io, p. 42; availability not checked here). Limits: continuous leader variables inside the follower are excluded and untested (pp. 8, 22); without integer slacks only hypercube ICs apply (pp. 16, 34); IC effectiveness decays when applied repeatedly to the same LP, hence the round limit (p. 21); CPLEX heuristics are off (p. 21). Future work: specialize the approach to interdiction structure, extend it to nonlinear settings (p. 37). The headline of more than 300 previously unsolved instances (p. 3) includes classes never tested before (Table 1 caption, p. 25); on the classes with earlier results, Table 1 shows 238 more instances solved (my sum, p. 25).

**Transferable techniques**:
- (D4) For any value-function constraint d^T y <= Φ(x), derive a locally valid cut at each node by restricting the inner problem to its worst case over the node's bounds and solving that MILP once per node (Theorem 1, p. 11; once per node, p. 21).
- (D4) Fix inner variables whose optimal value is forced whatever the outer decision (positive cost and non-negative column: lower bound; the mirror case: upper bound), with strict signs in the optimistic case (Theorem 2, pp. 11-12).
- (D4) Choose the convex set behind an intersection cut by an auxiliary MILP that maximizes the number of removable facets (pp. 17-18).
- (D4) Derive intersection cuts in a numerically safe way: compute coefficients from the original rows rather than tableau entries, so precision errors cost violation only; clip integer-variable coefficients at 1; drop cuts with dynamism above 10^6 or relative violation below 10^-6 (|rhs| + 1) (pp. 19-21).
- (D4) In the lazy-constraint callback, turn every rejected candidate into a repaired solution (solve the inner problem at x*, check the outer constraints) and offer it as an incumbent (p. 21).
- (D4) Branch first on outer variables that link to the inner problem (priorities 2, 1, 0; p. 21).
- (D5) Ablate each new ingredient by toggles on the previous best code (+F, +P, ++), with cumulative speed-up charts using a 1 s shift and final-gap charts for the unsolved instances (pp. 26-28).
- (D5) State which instances a performance profile contains, and that most of them are easy (p. 29).
- (D8) Release the solver, the instances and their optimal values with the paper (pp. 3, 7, 22, 42).
