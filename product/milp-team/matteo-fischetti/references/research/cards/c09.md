# Batch c09 · Matteo Fischetti · core

**Batch intent**: Three journal papers published in 2017, all from the period the skill calls "thinning out" (2014-2020): the node-only Steiner model written for the DIMACS 11 challenge (S040), orbital shrinking (S097), and real-time train rescheduling with a stock solver (S059). ### S040 · Thinning out Steiner trees: a node-based model for uniform edge costs (Math. Program. Comput. 2017, DOI 10.1007/s12532-016-0111-0)
**Read level**: full, on the preprint (the DIMACS 11 version, per the work-list note the author PDF thinning_out_Steiner_trees_dimacs11.pdf). Main text pp. 1-19 and references pp. 20-21 read in full. The appendix of detailed results, pp. 22-51 (Tables 7-54), skimmed: its prose (pp. 22, 49) and every caption read; Tables 7, 9-11, 37-39 and 44-54 read row by row; the other appendix tables (8, 12-36, 40-43) by caption and by counting their timeouts and memouts. The journal version was not read.
**Role**: core · **Coauthors**: M. Leitner, I. Ljubić, M. Luipersbeck, M. Sinnl (University of Vienna), M. Resch (TU Vienna), M. Monaci, D. Salvagnin (DEI Padua) (p. 1) · **Place in trajectory**: written for the 11th DIMACS Implementation Challenge, whose best bounds "as of August 1, 2014" are the yardstick (ref. [7], p. 20; p. 49). The fallback (x, y)-model is the 2006 prize-collecting Steiner tree model of Ljubić, ..., Fischetti (ref. [19], pp. 13, 15), carded as S014 in batch c04. SKILL.md lists the node-only model as Method 1 practice.

- **D1 Problem and entry point**: The entry is a set of public instances "still unsolved by state-of-the-art branch-and-cut codes", and the field's usual response (enrich the polyhedral description, add more sophisticated separation and branching) is turned round: "we investigate the opposite viewpoint, and try to make the solution method as simple as possible while working on the modeling side" (p. 1). The working hypothesis is over-modelling (Quotes, p. 1). The problem is cast as two decisions, choosing the nodes and connecting them, the second "just trivial" once the first is taken (p. 2). The target class is uniform edge costs, where edge-variable models carry many equivalent trees spanning the same node set; for "very dense graphs, or those containing a lot of symmetries" the node model is said to win clearly (pp. 2, 19). All variants (STP, PCSTP, NWSTP, MWCS) are covered by one generalised PCSTP with a possibly empty set of real terminals (p. 2).
  - Transferable: state the over-modelling hypothesis as the testable claim of the paper and name the instance class where it should hold (here uniform costs), instead of claiming a better model in general (pp. 1-2).
- **D2 Core idea and algorithm design**: Drop the edge variables. Binary node variables y_v; the uniform edge cost c is shifted into node costs c̃_v = c − p_v; objective Σ c̃_v y_v + (P − c); connectivity by node-separator inequalities y(N) ≥ y_i + y_j − 1 for every pair of terminals and every (i, j) separator N (model (1)-(4), p. 4). Compared with the node model for MWCS in [1], the graph stays undirected and the root variables go, "to keep the number of variables as small as possible" (p. 4). Added to the model: node-degree inequalities (5), which are "not implied by (2)" and improve the bound, their strengthening to minimal separators and their lifting for potential terminals, and the 2-cycle inequalities (6) (pp. 4-5). The algorithm is kept simple: no separation of fractional points in the default code, only lazy cuts on integer points (p. 5). The effort goes into the primal side instead: local branching with restarts, recombination, and a Benders-like set-covering heuristic (pp. 7-11). For the pure STP the model "can therefore be interpreted as set covering problem with an exponential number of elements to be covered", which the CFT set-covering heuristic exploits (pp. 6-7, 10-11). Non-uniform instances use the (x, y)-model of [19], and a filter chooses the model and the heuristics from graph features (pp. 12-14).
  - Transferable: when a decision splits into "which nodes" and "how to connect them", and connecting is easy once the nodes are fixed, model only the first decision and enforce the second lazily (pp. 2, 4-5).
- **D3 Problem class and data model**: Undirected graph, real terminals T_r (possibly empty), edge costs c ≥ 0, node revenues p ≥ 0 (Definition 1, p. 2). Potential terminals T_p are the nodes with p_v > 0 and an adjacent edge strictly cheaper than p_v (Definition 2, p. 3), justified by the observation that an optimal solution exists in which zero-revenue nodes, and nodes whose cheapest edge costs strictly more than their revenue, are not leaves (pp. 2-3). The y-model assumes uniform edge costs c_e = c (p. 4); the general case is left to "a simple edge splitting mechanism (possibly to be applied on the fly)", proposed in the conclusion and not tested (p. 19). Single-node solutions are preprocessed away, so Σ y_v ≥ 2 (p. 4). Problems run: STP, (rooted) PCSTP, MWCS (through its transformation into a PCSTP with uniform edge costs, p. 17) and degree-constrained STP (p. 12). Libraries: the hard unsolved SteinLib instances (PUC, I640, GAPS, SP, LIN and others) and the nontrivial MWCS instances posted for the DIMACS challenge (p. 12; appendix pp. 22-51). Structure exploited: uniform costs; the set-covering structure of the pure STP (pp. 6-7); bipartite graphs with a large share of terminals, where "most connectivity constraints are automatically satisfied" (p. 11); hypercube symmetry, where after removing the terminal variables a single orbit holds all remaining variables (p. 15). Correctness rests on cutting off every infeasible integer point, including those found by CPLEX's own heuristics, in a LazyCutCallback (p. 5).
  - Transferable: before writing the model, prove which nodes can be leaves of some optimal solution and give the terminal role only to them (pp. 2-3).
- **D4 Algorithm and implementation design**: (a) Separation. For an integer point ỹ, Algorithm 1 deletes the edges inside C_i ∪ A(C_i), runs a BFS from j in which nodes of A(C_i) are never queued, and returns N = A(C_i) ∩ R_j; Proposition 1 proves that N is a minimal (i, j) separator found in O(|E|), via Lemma 1 (a separator is minimal iff each of its nodes touches both components; taken from Golumbic [14]) (pp. 5-6). Fractional separation by max flow on a node-split digraph is described and switched off as "rather time consuming" (p. 5). (b) Framework (Algorithm 2, pp. 7-8): initialization heuristics; a local-branching phase with multiple restarts and changed seeds; a global cut pool added to the model before each B&C re-execution, because its presence at the root "triggers a more powerful preprocessing" and general-purpose {0,1/2}-cuts (p. 7); every ten iterations a recombination B&C on the subgraph induced by the union of the best solutions (p. 7); a final B&C from the pool and the best solution. (c) Local branching (Algorithm 3, pp. 8-9): the asymmetric constraint (7), which counts only nodes removed from the reference solution, with radius 10 to 20 "after some preliminary tests"; per call a solution limit and a deterministic time limit; the radius grows by r_delta after a failure and is reset after a success, and the phase stops at r_max or MaxIter. (d) Benders-like heuristic (Algorithm 4, pp. 9-11): a set-covering relaxation is extracted from the current model (fixed variables projected out, only rows y(S) ≥ 1 kept) and solved by CFT [5, 6]; its solution is repaired by fixing its ones (asymmetric local branching with r = 0) and a short B&C; the violated cuts are added and the loop repeats. Diversification: rows and columns shuffled at random, 20% of the fixings skipped at random; the B&C runs single-threaded so that different seeds run in parallel on separate cores (p. 11). For non-uniform bipartite instances, a "blurred" CFT works on node revenues minus the average cost of adjacent edges with edge costs set to 0, while the repair uses the original costs (pp. 11-12). (e) A filter on |E|/|V| < 3 (sparse), |T|/|V| > 0.4, uniformity, bipartiteness and a weight range below 10 picks the model, the tailing-off setting and the initialization heuristic (Tables 1-2, pp. 13-14). (f) (x, y)-model details: aggregated asymmetry constraints, stronger than the disaggregated ones of [19]; max-flow cuts added one terminal at a time with capacity updates, choosing the cut-set nearer the terminal; branching when the bound stalls instead of separating at length; for the PCSTP cuts only for terminals with y_i ≥ 0.5 (p. 15). Local search accepts non-decreasing moves on (almost) uniform instances, "due to existence of many symmetric solutions" (p. 14). (g) On hypercubes one Steiner node could be fixed to 1 without loss of generality; this was deliberately not done (p. 15).
  - Transferable: re-add every globally valid lazy cut to the explicit model before each restart, so that presolve and the solver's general-purpose cuts can see it (p. 7).
- **D5 Computational evaluation**: Protocol: every nontrivial DIMACS instance is first run with the exact B&C (no sophisticated heuristics, no local branching), one hour, a fixed seed; those left unsolved are "difficult" and get the heuristic framework, one hour, 10 independent seeds (p. 12). Hardware: a cluster of 20-core 2.3 GHz nodes with 64 GB, with up to five simultaneous 4-core runs per node, "which however implies a significant slowdown due to shared memory" (p. 12). CPLEX 12.6 with a 16 GB memory limit in the main text (p. 12) and 12 GB in the appendix, which also gives a DIMACS benchmark score of 360.070111 trees/second (p. 22). Wall-clock seconds (p. 12). Results: Table 3, "very preliminary" PUC results with the TURNI set-covering binary run off-line once for 60 s (1800 s for hc11u), repairs of 0.03-6.68 s, new best values on 5 of 7 instances (p. 16). Table 4: GAPS s1-s5 solved to optimality by the y-model in 0.03-30.06 s, while the (x, y)-model ends with gaps of 1.19%, 2.39% and 3.02% after 7,200 s on s3-s5; two SP instances solved for the first time, w13c29 at 507 (previous 508) and w23c23 at 689 (previous 694), in 0.61 s and 196.19 s against 167.17 s and 1,114.00 s (p. 17). The larger Table 4 instances are "very erratic" (seconds to hundreds of seconds by seed), yet the table is "a single run, with a default seed value of 0" (p. 16). Table 5, MWCS, best of five seeds: the y-model wins on drosa001/005/0075, HCMV and lymph and loses on the three mice instances (mice 1: 3,758.1 s against 1.2 s) (p. 17). Table 6: improved values within one hour on PUC and I640 (BEST, AVG and STD over 10 runs; Diff against the DIMACS bounds, e.g. −682 on hc12p), plus longer runs with 4 to 16 threads (hc12u 2256) (p. 18). The appendix prints every nontrivial instance, failures included. By my count of its tables, the y-model B&C ends in "memout" on 7 of 13 PUCN instances (Table 7, p. 22) and on 7 of 18 PCSTP PUCNU instances (Table 39, p. 42); the heuristic is worse than the previous best on 10 of 15 I640 STP instances (Diff +1 to +60, p. 49), on 11 of 13 LIN instances and on cc12-2p (+2947) (p. 50). Table 6 lists only the improvements, as its caption says (p. 18).
  - Transferable: define "difficult" by a fixed-seed run of the plain exact code before any heuristic run, then report best, mean and standard deviation over 10 seeds on every difficult instance (pp. 12, 18, 49).
- **D6 Positioning**: Against the polyhedral-enrichment strategy (p. 1). The node-based lineage is credited: Backes et al. [3] proposed the first node-based MWCS model, which [1] showed to give arbitrarily bad bounds and improved by node separators (p. 3). The toolbox is mostly the authors' own: of the 21 references, 10 carry Fischetti's name (local branching [11], proximity search [13], multiple restarts [12], {0,1/2}-cuts [2, 4], CFT [5, 6], TURNI [16, 17], the 2006 PCSTP framework [19]) and two more are by the Vienna co-authors ([1], [18]) (pp. 20-21). Local branching is presented as "in the spirit of large-neighborhood search metaheuristics" (pp. 7-8) and of "a primal nature" (p. 9). What the authors changed in the (x, y)-model of [19] is stated (p. 15). The yardstick is the DIMACS best-bounds file [7] (pp. 18, 49).
  - Transferable: when an existing model is the fallback, state exactly what you changed in it (here the aggregated asymmetry constraints and the cut-set side), so that the comparison is not with a weakened rival (p. 15).
- **D7 Writing and rhetoric**: The abstract frames the paper as "the opposite viewpoint", names a working hypothesis, coins the "thinning out" metaphor and hedges: "Even though we do not claim our approach can work well in all cases" (p. 1); "the (in)famous hypercube ones" (p. 1). Surprise is flagged ("To our pleasant surprise", p. 16). Preliminary numbers are printed as such ahead of the better final ones (pp. 16, 18). Metaphors: an "agile framework" (pp. 1, 19), a "blurred" relaxation (p. 11). A one-paragraph conclusion repeats the metaphor and claims that the approach "in some cases converts very hard problems into trivial-to-solve ones" (p. 19). The detail sits in a 30-page appendix (pp. 22-51).
  - Transferable: print the numbers of the first, over-simplified version next to the final ones; they show that the idea works before the engineering (pp. 16, 18).
- **D8 Contribution and limits**: Contribution at three levels: a model (node-based, for uniform costs), an algorithmic framework, and improved or first optimal values on hard SteinLib instances (pp. 1, 16-18). Limits stated: no claim for all cases (p. 1); fractional separation too slow (p. 5); on very large uniform instances even the LP relaxation takes "an exceedingly large computing time", hence the dual heuristic (p. 10); the CFT code is sequential (p. 11); one-hour values improve with more time and threads (p. 18). Limits visible only in the tables: the memouts of the y-model (pp. 22, 42), its losses on mice (p. 17), the heuristic's worse values on LIN and I640 (pp. 49-50). Future direction: edge splitting for general costs (p. 19).

**Method links**: Method 1 evidence ✅: the thin model is the paper's thesis (p. 1); the filter picks the model that fits the instance class (step 2: y-model for uniform costs, (x, y)-model otherwise, Tables 1-2, pp. 13-14), and the thin and fat models are measured on the same instances (step 4, Tables 4-5, p. 17). The record also shows where the thin model loses (mice, p. 17; memouts, pp. 22, 42), so the model choice is per class, as step 4 says. For the heuristic the model is thinned further, the set-covering "blurred" relaxation without connectivity (step 2: "for heuristics a weaker model may win", pp. 10-12). Method 6 evidence ✅: stock CPLEX 12.6 does most of the work, with one LazyCutCallback, no fractional separation and the cut pool re-added so that CPLEX's presolve and {0,1/2}-cuts act (steps 1 and 3, pp. 5, 7); local branching uses the MIP solver as a black box (p. 7); the first set-covering test used the existing TURNI binary off-line through text files before CFT was written into the code (step 3, smallest code first, p. 16). Method 3 variant ⚠: variability is exploited (restarts with new seeds, shuffling, random skipping of fixings, seeds on parallel cores, pp. 7, 11) and reported (BEST/AVG/STD over 10 seeds, pp. 18, 49; best of five, p. 17), but there is no placebo arm, and Table 4 is one run with seed 0 although its larger instances are called "very erratic" (p. 16). Method 4 evidence ✅: difficulty is defined in advance by a fixed-seed run of the plain exact code (step 3, p. 12); the thin and fat models run in the same framework, and the fat (x, y)-model gets two hours in Table 4 (step 1, p. 17); the appendix prints every nontrivial instance, losses included (step 6, pp. 22-51). Lapses: Table 6 shows only improvements (p. 18), the yardstick is a best-bounds file from other codes and machines (pp. 18, 49), and shared nodes slow the runs (p. 12). Method 2 variant ⚠: the cut loop is shortened (no fractional separation in the y-model, p. 5; branching on tailing-off in the (x, y)-model, p. 15) and the separated cut-set is changed (one terminal at a time with capacity updates, cut-sets near the terminal, p. 15); the separated point is not moved. Heuristic 1 evidence ✅: the WLOG symmetry-breaking fixing on hypercubes is declined because symmetry "can even be of help when heuristics come into play" (p. 15). Heuristic 3 evidence ✅: the pure-STP model is recognised as a set-covering problem and his own set-covering heuristic CFT is brought in (pp. 6-7, 10-11). Heuristic 2 variant ⚠: the Benders-like heuristic is local branching centred on an infeasible relaxation solution instead of a feasible incumbent (pp. 9-10). Research Taste mark 1 evidence ✅: previously unsolved instances proved optimal in seconds (pp. 1, 17). Common Misreading 5 variant ⚠: by 2014 the authors themselves present local branching as a primal, LNS-like component (pp. 7-9), so the misreading concerns the 2003 framing only. New-pattern candidates (my labels): *inexact model to search, true model to accept* (pp. 10-12; the same shape in S059 below, and per their cards in S023, "blurring", batch c07, and S164, "decouple the search LP from the certificate LP", batch c13); *own toolbox as building blocks* (pp. 7-11, 16, 20-21).
**Transferable techniques**:
- Shift a uniform edge cost into node costs (c̃_v = c − p_v) and model connectivity with node variables only (p. 4).
- Separate only infeasible integer points, in linear time: BFS from j that never queues the neighbours of i's component returns a minimal violated separator (Algorithm 1, Proposition 1, pp. 5-6).
- Keep a global pool of lazily separated cuts and re-add it before each B&C restart, so that presolve and the solver's general cuts work on an explicit formulation (p. 7).
- Run asymmetric local branching with a small radius (10-20), a solution limit and a deterministic time limit per call; enlarge the radius after a failure and reset it after a success (pp. 8-9).
- Every ten local-branching iterations, solve a B&C on the subgraph induced by the union of the best solutions found (p. 7).
- Benders-like repair: solve a relaxation heuristically, fix the variables it selects, repair with a short B&C, feed the violated cuts back into the relaxation, repeat (Algorithm 4, pp. 9-11).
- Make a deterministic heuristic seed-dependent by shuffling rows and columns and skipping 20% of the fixings at random, then run seeds in parallel, one per core (p. 11).
- Encode "the model that fits the instance" as an explicit filter on cheap instance features (sparsity, terminal ratio, uniformity, bipartiteness, weight range) (Tables 1-2, pp. 13-14).
- On (almost) uniform instances with many symmetric solutions, let local search accept non-decreasing moves (p. 14).
- Prototype with an existing binary off-line, through text files, before embedding the component (p. 16).
- Give the rival model the longer time limit when the claim is that your model is faster (two hours, Table 4, p. 17).
**Quotes**:
- "Our working hypothesis is instead that the extreme hardness of some classes of instances mainly comes from over-modeling, and that some instances can become quite easy to solve when a simpler model is considered." (p. 1)
- "one can think of the relaxation as a “blurred” version of the original problem, which retains some of its main features but is not bothered by too many details (namely, connectivity conditions) that would overload the model." (p. 11)

### S059 · Using a general-purpose mixed-integer linear programming solver for the practical solution of real-time train rescheduling (European Journal of Operational Research 2017, DOI 10.1016/j.ejor.2017.04.057)
**Read level**: full, on the preprint (the author preprint dated February 5, 2017). The whole text pp. 1-15: introduction, model description, Tables 1-2, conclusions, the appendix model (pp. 12-13) and the references. The boldface marks of Tables 1-2 are lost in the extraction, so the counts of target-meeting runs are taken from the prose, and my own counts from the extracted tables are marked as mine. The journal version was not read.
**Role**: core · **Coauthors**: M. Monaci (then DEI, University of Bologna, p. 1) · **Place in trajectory**: an industrial feasibility study for Alstom Ferroviaria, which opened international collaborations around its ICONIS dispatching system in 2013 (p. 2). It applies the erraticism result of 2014 as a resource (Fischetti and Monaci 2014, p. 5). SKILL.md cites the related train-rescheduling deck TRI16 for Method 1 and Inner Tension 3. The experiments run on a processor launched in 2011 (p. 7).

- **D1 Problem and entry point**: An industrial question, posed as a feasibility study: can a modern general-purpose MILP solver, given the improved technology, do real-time rescheduling in a practically effective way (p. 2). Rescheduling must return a conflict-free schedule within 2 to 10 seconds after the event is detected (p. 2); Alstom set 2, 5 and 10 seconds for small, medium and large instances on "any reasonable hardware", even a local cluster of tens of PCs (p. 2). The literature says that direct MILP solving is not suitable for real time (Lamorgese and Mannino 2015; Lamorgese et al. 2016), and the authors check whether that still holds with CPLEX 12.6.2 (p. 4). It does: even with 10 PCs, feasible solutions within the target time come on only 13 of 29 instances (p. 5). The answer to the question is given "essentially in the affirmative" (p. 2), after the preprocessing of D2.
  - Transferable: turn a partner's need into one yes/no question about the stock solver, and measure the plain solver against the actual time limits before designing anything (pp. 2, 4-5).
- **D2 Core idea**: Two heuristic preprocessing steps on top of an unchanged standard model and an unchanged solver. (i) A "possibly invalid" upper bound z_ω ≤ UB_ω on the variable that gives the maximum delay: the bound makes the solver's own presolve and propagation tighten the domains of many variables, fix many binaries and reduce the big-M coefficients (p. 6; Quotes). Infeasible values of UB_ω are detected "almost immediately" by presolve, so the code tries increasing values until one is feasible (p. 6). (ii) Route fixing: each train keeps its ideal route (no rerouting) or one route chosen at random (p. 7). Unchanged: the alternative-graph MILP of Mascis and Pacciarelli and of D'Ariano et al. (pp. 3, 12-13), CPLEX, its default mode with cuts (p. 7). How the two steps were found: a number of ideas were implemented and tested, and once the time limits were met the authors went back and removed features (Quotes, p. 5) until "the performance boost was due to just two very simple preprocessing operations" (p. 5). Their own longest-path infeasibility check for UB_ω was removed because the solver's internal preprocessing "was equally fast" (pp. 6-7).
  - Transferable: test how sensitive the solver is to bounds on single variables; a bound on an aggregate variable (here the maximum delay) can propagate through the whole model (p. 6).
- **D3 Problem class and data model**: Event-based job-shop MILP (Balas 1969) on an alternative graph with big-M disjunctions: binary y selecting exactly one route per train, binary x for the unknown precedences between incompatible arc pairs, continuous times t and delays z, and z_ω, the delay at the dummy end node, equal to the maximum delay; the objective is the average delay (pp. 3, 12-13). Data: 29 Alstom instances of simulated disruptions on a line near London, 10 small (15-minute horizon), 9 medium (30) and 10 large (60), with up to 41 trains even in the small ones (p. 2); 32 to 90 trains and 40 to 128 alternative routes per instance (Table 1, p. 4); the MILP files were provided by D'Ariano et al. (2014) (p. 12). Instance 28 is removed because none of the 20 one-hour CPLEX runs found a feasible solution (p. 5). The rationale for the bound is a property of the data: the objective naturally drives z_ω towards its smallest possible value, "This is in fact what happens in the Alstom's instances" (p. 6). The bound and the route fixing are heuristic restrictions (pp. 6-7): by construction every solution found is feasible for the original model (my reading; the paper does not spell it out), while optimality is given up, the abstract promising "(almost) optimal solutions" (p. 1).
  - Transferable: if the objective pulls an aggregate variable towards its minimum, a tight heuristic bound on it costs little solution quality and buys a lot of propagation (p. 6).
- **D4 Algorithm and implementation design**: UB_ω is tried in the sequence 600, 900, 1200, 2000, 2500, 3000, 4000, 5000, +∞; each CPLEX call gets the remaining wall-clock time, and the next value is tried only when CPLEX proves the model infeasible (p. 8). With 8 PCs the first value was feasible on 2/3 of the instances; at most 7 values were needed, and the preprocessing time was always below 0.2 s and is included in the reported times (p. 8). Parallelism: N_PC independent computers solve the same instance without communication, the best solution at the time limit is taken (pp. 7-8); communication is excluded because synchronisation "could even result into a slow-down" (p. 8). One run index s drives three diversifiers: it is CPLEX's random seed (CPX_PARAM_RANDOMSEED); odd s selects aggressive presolve (CPX_PARAM_PRESLVND = 3); s ∈ {1, 8} fixes no route, s = 2 the ideal routes, s = 3 to 7 random routes seeded by s (p. 8). Multi-thread runs use CPLEX's opportunistic parallel mode, "as this is most appropriate in a real-time setting where speed is more important than reproducibility of the results" (p. 7). No proof or invariant beyond the restriction property.
  - Transferable: let one run index set the solver's seed, a model-level restriction and a presolve option, so that k independent machines explore k different restricted models (p. 8).
- **D5 Computational evaluation**: Baseline (Table 1, pp. 4-5): CPLEX 12.6.2 in default settings and in a "heuristic version" with all cut generation disabled, which "proved to be more effective"; each run with 10 seeds, the best of 10 reported to simulate 10 parallel PCs that all stop when one finishes; one-hour limit; quad-core Xeon E3-1220V2 at 3.1 GHz. Even the heuristic version finds a feasible solution within the target time on only 13 of 29 instances, and a speed-up of "1-2 orders of magnitude" would be needed (p. 5). Method runs: quad-core i7-2820QM at 2.3 GHz, launched in 2011, while seventh-generation i7 processors are "about twice as fast" (p. 7); N_PC ∈ {1, 4, 8}, 1 or 4 threads per PC, the single-thread option because it gets faster memory access and turbo boost (p. 9). Metric: ratio of the best value found within the limit to the best known value (p. 8; Table 2, p. 10). "50% Faster PC" columns are the results after 3, 7 and 15 s on the same hardware (pp. 8-9). Ablation arm "cpx 8/cpx 4": 8 PCs with 4 threads, all CPLEX parameters as in the method, preprocessing and path fixing off (p. 9). Results: with N_PC = 1 (s = 1, the bound without route fixing) a feasible solution within the limit in 16 cases, against 13 for the heuristic CPLEX on 10 PCs (p. 9); with 8 standard PCs, 26 instances, and "In only 3 cases the ratio is about 2", which Alstom's experts consider acceptable (p. 9); in the faster setting with 8 four-thread PCs all 28 instances, against 12 of 28 without the two features (p. 9). More PCs can give a worse solution under opportunistic parallelism (instance 16, p. 9). The rival method of D'Ariano et al. (2014) solves all instances within 30 s on a Core 2 Duo, but reports only the time to its best solution (9 s on average), so "a direct comparison with our approach is not possible" (p. 11). My checks of the extracted tables: the 8-PC, 4-thread standard-PC column of Table 2 also shows ratios of 3.62 (instance 23) and 84.16 (instance 27), which the "only 3 cases" sentence does not mention (pp. 9-10); rows 14 and 29 of Table 1 have identical sizes and best value (52 trains, 59 routes, 8529 and 15181 columns and rows, 10.75), although they belong to different horizon classes, and the text does not comment (p. 4). No tuning set separate from the 28 instances is mentioned for the UB_ω sequence or the seed scheme (p. 8).

**Transferable techniques**:
- Measure the stock solver first, in default and in a heuristic setting, k seeds each, and read best-of-k as what k parallel machines would get (pp. 4-5).
- Look for the one variable bound that drives presolve; impose it heuristically and walk a fixed ladder of values upward (600, 900, ..., 5000, +∞), each call getting the remaining time (pp. 6, 8).
- Drop your own checks when the solver's presolve detects the same thing as fast (pp. 6-7).
- Diversify independent parallel runs with one index that sets the solver seed, the model restriction (route fixing) and a presolve option (p. 8).
- After the first working version, disable or simplify features one at a time until only those that matter remain (p. 5).
- Ablate with the same parameters and hardware, only your features off (p. 9).
- Under very short time limits, compare single-thread and multi-thread runs (memory access, turbo boost) (p. 9).
- To show what a faster processor would deliver, report the values reached at proportionally longer limits on your hardware, labelled as such (pp. 8-9).

### S097 · Orbital shrinking: Theory and applications (Discrete Applied Mathematics 2017, DOI 10.1016/j.dam.2017.01.015)
**Read level**: full, on the preprint (the author manuscript, "Noname manuscript No.", p. 1). The whole text pp. 1-28: §§1-8 with all proofs, Tables 1-8, Figure 1 (its data series are in the text layer, p. 9), acknowledgements and references (pp. 27-28; the extraction ends inside reference 39, p. 28). The journal version was not read.
**Role**: core · **Coauthors**: L. Liberti (IBM T.J. Watson Research Center and LIX, École Polytechnique), D. Salvagnin (DEI Padova), T. Walsh (NICTA and UNSW) (p. 1) · **Place in trajectory**: extends preliminary papers by the same authors, Fischetti and Liberti (ISCO 2012), Salvagnin and Walsh (CP 2012) and Salvagnin (CPAIOR 2013) (p. 2; refs. 4, 36, 37, pp. 27-28). SKILL.md lists it as Method 1 practice and dates to 2011 the orbital-shrinking rule fitted on its evaluation instances (Method 4 lapses); that rule is still in this manuscript of the 2017 paper (pp. 9-12). The keyword list includes MINLP (p. 2).

- **D1 Problem and entry point**: The reflex is to destroy symmetry, by artificial symmetry-breaking conditions or by search strategies such as isomorphism pruning and orbital branching, in both the MIP and CP communities (abstract p. 1; p. 2). The paper inverts it: symmetry is "a positive feature of our model", to be preserved and broken "only as a last resort" (p. 2; Quotes, p. 1). The acknowledgements trace the work to a question by Mauro Diligenti: "Why do you discrete optimization guys hate symmetry and want to destroy it?" (p. 27). The problem is posed as finding a relaxation, the "formulation modulo a group" (p. 4), and then an exact method built on it (p. 2).
  - Transferable: when the field treats a property as a curse, ask what relaxation or reformulation that property gives for free if it is kept (pp. 2, 4).
- **D2 Core idea**: Replace the variables of each orbit of (a subgroup of) the formulation group by one variable z_ω, their sum, integer if the orbit is integer; substitute x_j → z_ω/|ω| in the constraints C1 (convex in V1) and C2 (functions of orbit sums), and in the objective; drop C3 (p. 4). The result has one variable per variable orbit and one constraint per constraint orbit (p. 6). It is a relaxation (Theorem 1), exact for convex problems (Corollary 1, credited to [7]) and when the orbit sums of an optimal solution are divisible by the orbit sizes (Corollary 2) (pp. 5-6). Exactness in general comes from a decomposition "akin to a logic-based Benders decomposition", where the master aggregates instead of splitting variables (p. 11): the shrunken model is the master, the disaggregation problem R(z*) the slave, and a rejected z* is removed by a nogood cut or by branching (pp. 12-13). The slave is a pure feasibility problem, "so a CP solver may be a better choice", hence a hybrid MIP/CP method (p. 13); a variant moves the continuous variables' objective into the slave (p. 13). The subgroup is the knob between bound and speed (pp. 8-11).
  - Transferable: when a relaxation is generated by a group, use the subgroup lattice (here a chain built from generators) as the dial between bound quality and solving time (p. 8).
- **D3 Problem class and data model**: P is a MINLP whose objective is assumed convex "Without loss of generality" (p. 3). The symmetry group is the formulation group: the variable permutations that leave the formulation unchanged up to a reordering of the constraints, computed from a DAG of the expressions with nauty or saucy (p. 3). Orbits never mix integer and continuous variables (p. 3). The partition (V1, V2), (C1, C2, C3) requires C1 convex in V1 once V2 is fixed and C2 to be functions of the orbit sums of the pointwise stabilizer G_P[V2] (p. 4). Convexity is load-bearing (Example 1, p. 7). Test sets: 39 symmetric MILPs from Margot's website (p. 7), of which 23 change bound with the subgroup (pp. 8-9); multi-activity shift scheduling instances from [1, 2, 32], derived from a real-world store, 1 to 10 working activities with 10 instances each, 96 slots of 15 minutes, identical employees (pp. 13, 18); multiple knapsack "spanner" instances generated after Pisinger [31], n ∈ {30, 40, 50} items and m ∈ {3, ..., 6} identical knapsacks, 10 per pair, 120 in all, "available from the authors upon request" (pp. 21, 23).
  - Transferable: next to the relaxation theorem, state the exactness condition that can be checked after solving (orbit sums divisible by the orbit sizes, Corollary 2, p. 6).
- **D4 Algorithm and implementation design**: Proofs: Lemma 1, Σ_{π∈G} f(π(j)) = (|G|/|ω|) Σ_{l∈ω} f(l), by a bijection between the stabilizer G[j] and T_jl and the orbit-stabilizer theorem (pp. 4-5); Lemma 2, the group average of a feasible x* equals its orbit averages (p. 5); Lemma 3, orbit sums are invariant under G (p. 5); Theorem 1, the averaged point satisfies C1 by convexity in V1 and C2 by invariance, z* is integral as a sum of integers, and the objective does not increase by convexity of f, the averaged solutions having equal cost by symmetry (pp. 5-6); Example 1, a nonempty set (x1 − x2)(x2 − x1) ≤ −1 whose substitution gives the empty set {z | 0 ≤ −1} (p. 7). Subgroup choice: generators sorted by decreasing |fix(π)|, because a large fixed set makes the subgroup "likely to remain valid" after branching fixes variables (p. 8); the chain G_0 ⊂ ... ⊂ G_k = G gives bound and time "mostly monotonically decreasing" in ℓ (Figure 1, sts81, pp. 8-9); ℓ hand-picked per instance by three prioritised criteria (bound strictly above the LP, low time with a penalty beyond 10 s, else a mid-range bound) (p. 9); the incidence (8)-(9) of orbits with constraint supports, low incidence meaning orbits "orthogonal" to the constraints (pp. 10-11); the automatic rule takes the ℓ whose relative incidence is closest to 0.82, the mean of the hand-picks (standard deviation 0.17) (p. 11). Tools: bash, GAP, AMPL and ROSE build the relaxation automatically (p. 7). Decomposition: branching on integral z converges because the tree has finite depth for bounded z; a cache of recently checked z* avoids repeated checks (pp. 12-13); R(z*) keeps the symmetry of P (p. 13); CPLEX dual reductions are disabled, "otherwise the decomposition would not be correct", and callbacks implement the scheme (pp. 18-19; also p. 25). Shift scheduling: a MIP master per shift type with the extended flow formulation of the regular constraint and cardinality constraints (pp. 15-16); a CP checker with gcc, regular and lexicographic-order constraints (pp. 16-17); two custom propagators (cardinality-based symmetry breaking, shift length) gave "reductions of 2−3 orders of magnitude" in nodes and time on hard instances, one instance going from 6 minutes to 10^-5 s and from 765,026 nodes to 1 (p. 17); three phases: the aggregated model by CPLEX in default settings with its solution pool, a repair heuristic on every aggregated solution within 20% of the aggregated optimum (stop if the gap is below 1%), then the hybrid search (pp. 18-19); CP branching by increasing time period "after some trial-and-error"; when the LP is integral, branch on w first, then y; once w is fixed, CP with a fail limit of 1000 prunes nodes (p. 19). Multiple knapsack: the master is one knapsack of capacity mC with a general-integer variable per item type (p. 22); the slave is bin packing, either a compact CP model (global binpacking constraint, CDBF branching, symmetry-breaking order (40)) or the extended Gilmore-Gomory model BPcg solved by CP or by MIP (pp. 22-23); BPcg's LP relaxation "was sufficient in most cases to detect infeasibility", and a Benders nogood from LP duality would be available but was not implemented (p. 25).
  - Transferable: to prove that a symmetry-based reformulation is a relaxation, average an arbitrary feasible point over the group and check each constraint class (pp. 4-6).
- **D5 Computational evaluation**: §4: Core 2 Duo at 1.4 GHz with 3 GB, CPLEX 12.2 (p. 7). With the whole group the bound is no better than the LP on 31 of 39 instances and no better than CPLEX's root bound on the other 8 (p. 8; Quotes). Relaxations are capped at 1800 s (p. 8); the 16 instances whose bound does not depend on ℓ are discarded (p. 8). Table 1 gives the hand-picked subgroups (p. 10); Table 2 the automatic ones, with "cpx t", the time CPLEX 12.2 in default settings needs on the original model to reach the same bound (pp. 11-12). By my count of Table 2, the automatic rule gives a bound strictly above the LP on 13 of the 23 instances, equal to it on 8, and hits the 1800 s limit on 2 (cod105, cod93), where the text says "often stronger than the LP bound" (pp. 11-12); on cod83 CPLEX reaches the same bound faster (9.54 s against 16.78 s, p. 12). The rule is fitted on the hand-picks for the same 23 instances on which Table 2 reports it (pp. 9-12). §6: C++, CPLEX 12.2 and Gecode 3.7.3 on a Core i5 at 2.66 GHz with 8 GB, one core per process, one hour, stop at a gap of 1% (pp. 18-19). Baselines: cpx-reg, the explicit regular-language model of [1], run by the authors; grammar, the implicit model of [2], with numbers copied from [2], "obtained on a different machine and, more importantly, with an older version of CPLEX", meant as a reference only (p. 19). Solved within the hour (my sums of Table 3): hybrid 60 of 100, cpx-reg 28, grammar 98 (p. 20); hybrid wins against cpx-reg, grammar wins beyond two activities (p. 19). Hybrid's average final gaps stay below 3%, it needs about a tenth of cpx-reg's variables, and it explores nodes "more than two order of magnitude faster" (p. 20); in Table 4 the exception is the one-activity class, where cpx-reg is faster per node (21.99 against 10.36 nodes per second; my reading, p. 20). The repair heuristic alone reaches an average gap below 10% on almost all classes in about a minute (Table 5, pp. 20-21). The shrunken MIP is sometimes faster than the original LP and gives a better bound (182.54 in 0.12 s against 142.48 in 0.26 s) (p. 21). §7: CPLEX 12.4, Gecode 3.7.3, the same PC, one hour; shifted geometric means of nodes and times, the shift not given (p. 23); no specialised knapsack or bin-packing code, since the same standard packages in all methods allow "a clearer comparison" (p. 23). Solved: natural model cpxorig 65 of 120, identical items aggregated cpx 82 (Table 6, p. 24); BPstd 110, BPcgCP 115, BPcgMIP 120 (Table 7, p. 25), with node counts for the master only, as declared (p. 25); the shrunken relaxation closes 42.8% to 76.7% of the integrality gap in at most 0.031 s (Table 8, p. 26). No experiment reports seeds or repeated runs (pp. 7-26), and no pure-CP method is run, although the abstract claims speed-ups over "pure MIP or CP approaches" (pp. 1, 19, 23-25).
  - Transferable: price a new relaxation by the time the stock solver needs on the original model to reach the same bound (the "cpx t" column, pp. 11-12).
- **D6 Positioning**: Against the symmetry-breaking literature: Margot's isomorphism pruning and orbits [20-22], orbital branching [27], symmetry in CP [9] (pp. 2, 4). Corollary 1 is credited as already proved by Gatermann and Parrilo [7] (p. 6). The decomposition is credited as akin to logic-based Benders (Hooker and Ottosson [13]) and to a problem-specific approach of Linderoth, Margot and Thain [19] (p. 11); Mittelmann and Salvagnin [26] used the extended variant with the roles of MIP and CP swapped (p. 13). The grammar model [2] is called "the current state-of-the-art" for multi-activity shift scheduling (p. 15) and is kept as the baseline that wins (pp. 19-20). The paper places itself "squarely in the mathematical programming field" while using MIP/CP integration [25, 12] (p. 2). The novelty claim is narrow: "the framework itself is not entirely new", the novelty being that it is driven by the automatically detected symmetry group (p. 27).
  - Transferable: claim the narrowest novelty that is true, here the automatic driver and not the decomposition (p. 27).
- **D7 Writing and rhetoric**: A thesis-first, contrarian abstract (p. 1); a coined phrase, "formulation modulo a group" (p. 4); intuition labelled as such ("Again, intuition led our choice for this feature", p. 10; "In our view", p. 8); theory in lemma, theorem, corollary and counterexample, each a few lines (pp. 4-7). Losses are stated in the body with an explanation, "This is somehow expected" (p. 19), but not in the abstract (p. 1). The conclusion recasts the method through the symmetric-cost ATSP: orbital shrinking produces the symmetric TSP model automatically, a preprocessing step "capable of fixing some kind of modeling errors" (p. 26).
  - Transferable: pair a relaxation theorem with a two-line counterexample that shows which assumption carries it (p. 7).
- **D8 Contribution and limits**: Contributions: theory (the relaxation, the exactness corollaries), a general decomposition, two applications (pp. 2, 26-27). Limits: the bound with the whole group is weak (p. 8); the automatic subgroup rule (pp. 9-12, D5); continuous variables make the plain decomposition impractical (p. 13); R(z*) keeps the full symmetry (p. 13); the CP checker can become slow, which needed custom propagators (p. 17); the method loses to the grammar model beyond two activities (p. 19); the LP-duality nogood is left unused (p. 25). Future work: sufficient conditions for exactness, and other symmetric problems (p. 27).

**Method links**: Method 1 evidence ✅: step 3 in its aggregation form, symmetric variables aggregated along orbits instead of breaking the symmetry (pp. 2, 4-6); on multiple knapsack, aggregating identical items alone lifts the solved count from 65 to 82 (p. 24), the hybrid master needs about a tenth of the explicit model's variables (p. 20), and the ATSP example shows the method fixing a modelling error automatically (p. 26). **Transferable techniques**:
- Get the formulation group automatically: encode the formulation as a DAG and call a graph-automorphism package (nauty, saucy) (pp. 3, 7).
- Build a subgroup chain by adding generators in decreasing order of fixed points, and use it as the bound-versus-time dial (p. 8).
- Score candidate orbit partitions by their incidence with constraint supports; low incidence avoids collapsing a constraint into a mere bound (pp. 10-11).
- Master on the aggregated model, slave as a disaggregation feasibility check (CP for pure feasibility, MIP where its LP detects infeasibility); reject by nogood or by branching on integral variables, and cache checked aggregated solutions (pp. 12-13, 25).
- When a decomposition lives in solver callbacks, switch off the solver features that break its correctness (dual reductions) (pp. 18-19, 25).
- Before the exact hybrid phase, solve the aggregated model, repair every aggregated solution within 20% of its optimum, and stop if the gap is already below 1% (p. 18).
- Branch first on the variables the check needs to be formulated (w), then run the check with a strict fail limit at nodes to prune (p. 19).
- Report the gap closed by the relaxation and its time per instance class (Table 8, p. 26).
- Compare all methods inside the same standard packages when the scheme is general, and say that this is why specialised codes are left out (p. 23).
