### S052 · Proximity search for 0-1 mixed-integer convex programming (Journal of Heuristics 2014, DOI 10.1007/s10732-014-9266-x)
**Read level**: full. I read file pp. 1-26: text, Tables 1-4 and references. Figures 2-4 extracted only as axis ticks and legends, so I read them through the text that describes them (pp. 17-19).
**Role**: core · **Coauthors**: Michele Monaci (DEI Padova, p. 1) · **Place in trajectory**: author preprint dated 31 July 2013 (p. 1). It returns to the heuristic line of 2003-2005: the paper places proximity search as a "dual version" of the authors' local branching (2003), next to the feasibility pump (2005) (p. 7). It was written in the same period and with the same co-author as S055 (revised 21 March 2013, S055 p. 1).

- **D1 Problem and entry point**: Best-bound search with dives is good at proving optimality, but "its effectiveness in providing early feasible solutions of good quality is less clear" (p. 2). Some solvers even reset the objective to zero on very hard instances, because it "interferes with the internal heuristics" (p. 2). The entry: take a feasible x̃ and add the cutoff f(x) ≤ f(x̃) − θ (4). After that "we are free to modify the objective function" (p. 2): minimise the Hamming distance Δ(x, x̃) (5), so that the black-box solver makes the moves of a primal method (p. 3).
  - Transferable: once an explicit cutoff carries the improvement requirement, the objective is free for search guidance. Ask which objective makes the sub-MIP easiest to solve.
- **D2 Core idea**: Change the sub-MIP's objective, not its constraints (p. 3; quote below). Local branching keeps f and imposes Δ(x, x̃) ≤ k. Proximity search swaps the roles of f and Δ (p. 7).
  - The mechanism is named "improved relaxation grip" (p. 5). For small θ the root relaxation x⁰ stays close to x̃, solves fast and is nearly integral, so it steers the solver's internal heuristics.
  - Table 1 (ramos3, x̃ of value 267, 2,187 variables): for θ ≤ 4 at most 6 components are fractional and the LP takes at most 0.04 s. At θ = 121, 1,505 components are fractional and the LP takes 30.91 s (pp. 5-6).
  - Table 2 shows that local branching has the same grip only for small k, and the grip vanishes as k grows (k = ∞: 98.18 s) (pp. 7-8).
  - The trade-off is stated: local branching can take a large improvement in one sub-MIP, while proximity search needs a sequence of calls. A hybrid (local branching with k = 10 first, then proximity search) is proposed but not tested (p. 7).
  - Step 5 re-optimises the continuous variables with the binaries fixed (p. 4). If the solver proves infeasibility for θ, f(x̃) − θ is a valid lower bound (p. 5).
  - Transferable: diagnose a sub-MIP design on one instance before any aggregate. Tabulate the root LP's value histogram, time and iterations against the parameter (θ or k), for your method and for its closest rival (Tables 1-2, pp. 6, 8).
- **D3 Problem class and data model**:
  - Model: a 0-1 MIP min f(x), g(x) ≤ 0, with convex f and g so that the relaxation is polynomially solvable; convexity is "not strictly required" (pp. 1-2). Only binaries enter Δ; general integers are not addressed, and extensions are only sketched (p. 6). A first feasible solution is assumed easy to find; otherwise constraints are softened with penalised slacks (p. 4).
  - Test set: 130 instances in three classes (p. 12):
    - 49 set-covering instances: ORLIB scp* and rail*, four railX*c core problems, and nine MIPLIB 2010 set-covering instances including seymour and the open ex1010-pi, ramos3, sts405 and sts729. rail516 was dropped because it solved within 10 nodes (pp. 12-13).
    - The 25 SNDlib capacitated network-design instances, minus 4 solved during warm-up (p. 13).
    - 60 ramp-loss SVM MIQPs with big-M constraints (10), supplied by J.P. Brooks. Their quadratic objective is moved into a constraint ||w||² ≤ 2q so the objective is linear (pp. 13-14).
  - θ settings: 1 for integer costs; 0.01|f(x̃)| for network design "to avoid numerical precision issues"; 0.001|f(x̃)| for classification (pp. 13-14).
- **D4 Algorithm and implementation design**: Three implementations around CPLEX (pp. 9-11):
  - (4.1) Without recentering. An incumbent callback records each new x̂, declares it infeasible and adds f(x) ≤ f(x̂) − θ as a global cut; Δ stays centred on the first x̃. Because the incumbent is never updated, propagation, variable fixing and the refinement heuristics never run (pp. 9-10).
  - (4.2) With recentering. No callbacks: the solver runs in default mode, stops at the first feasible solution, and the search recentres and restarts. Each restart wastes the previous tree. A policy of restarting only after large moves was not tested because it would add a parameter (p. 10).
  - (4.3) With an incumbent. The cutoff is softened to f(x) ≤ f(x̃) − θ + z, with objective Δ + Mz, so x̃ can be passed as an expensive warm start that triggers RINS. z = 0 at the root because of the penalty M; an aggressive θ would bring the original objective back (p. 11).
  - Rejected and omitted options: an ad-hoc RINS fed with an external x̃ was rejected because it "would contaminate our experiments" (p. 11). ρ = 0 in Δ + ρf (pp. 4-5), and no cutoff is set on the Δ value (p. 5).
  - Settings for (4.3): M = 100,000 and CPX_PARAM_EPAGAP = M/2, so the sub-MIP stops at the first solution with z = 0 (p. 15).
  - Theory: there is no proof beyond the valid-bound remark (p. 5). The primal/dual argument is an analogy with the primal and dual simplex: primal methods suit re-optimisation, as in column generation (pp. 20-21).
  - Transferable: to keep the solver's improvement heuristics alive under a changed objective, soften the cutoff with a slack penalised by a big M and pass the old incumbent as a warm start (p. 11).
- **D5 Computational evaluation**:
  - Setup: C code on CPLEX 12.4, on an Intel i5-750 at 2.67 GHz, single-thread and "without any other concurrent thread" (p. 12). The first x̃ comes from CPLEX after 10, 5,000 or 50,000 nodes depending on the class. It was chosen to be "not unrealistically bad nor too good to be improved", and every algorithm receives the same x̃ (pp. 12-14, 17). Reported times exclude this warm-up (p. 12).
  - Metric: the primal integral P(t_max), after Achterberg-Berthold-Hendel and Berthold (p. 14). It is reported as geometric means shifted by 0.01 at 5-1200 s (p. 12; Table 3, p. 16), together with pairwise curves of the probability of being at least 1% better (pp. 17-19).
  - Ten arms (p. 15): three proximity variants; CPLEX default, heuristic emphasis, no cuts, polishing at every node, and guided dives; the original local-branching code; and an aggressive local branching (k = 10, 20, ...) with recentering and warm start. A zero-objective version of proximity search, not tabulated, gave "a dramatic performance deterioration" (p. 15).
  - Losses are printed. Original local branching overtakes proxy incum in the pairwise metric after about 800 s (p. 19). On scpnrg4 one CPLEX step gains more than many small proximity steps (Fig. 4, p. 19).
  - Incremental test: an external column-generation loop on 7 rail* instances produces 603 nested subinstances, and the loop "is not affected at all by the performance of A". Each heuristic gets 10 s and the same warm start, and wins are counted with ties: proxy incum 489, aggressive local branching 442, the CPLEX variants about 300 (pp. 21-23, Table 4).
  - There are no seeds, no permutations and no statistical test anywhere (pp. 12-23).
  - My reading of Table 3 (p. 16): on set covering, aggressive local branching has the lower primal integral from 120 s onwards (0.773 vs 0.797 at 120 s; 1.974 vs 1.978 at 1200 s). The text's "substantially better than that of all competing methods" (p. 17) holds for network design (0.742 against 1.262 for the next arm at 1200 s) and for classification (1.045 against 1.744). It does not hold for set covering.
  - Transferable: to test a heuristic in a re-optimisation setting, let an external driver generate the sequence of subinstances independently of the heuristic under test. Give every arm the same subinstance and the same warm start, and count wins with ties (pp. 21-22).
- **D6 Positioning**:
  - Novelty is qualified at once: a proximity term "is of course not new", as in augmented Lagrangian and proximal methods (Nocedal-Wright) and in Daniilidis-Lemaréchal for discrete problems (p. 6).
  - The closest relatives are the authors' own local branching and the feasibility pump. Both are read as "dual" versions, and Boland et al.'s proximal reading of the pump is cited (p. 7).
  - Bonami et al.'s MINLP pump differs on two points: the distance is measured to an integer point, and enumeration runs on the original problem rather than on a MILP relaxation (p. 8).
  - RINS and Rothberg's polishing are unrelated methods used as benchmarks (p. 9). A drawback relative to local branching is conceded: "As there is no free lunch" (p. 7).
- **D7 Writing**: The goal is framed as a "computational investigation of pros and cons ... with the aim of exploring diversified ideas and of attracting more research on this topic" (p. 3), and the code as "proof-of-concept implementations" (p. 1). A recurring cleanliness clause explains each omitted variant: "as simple (and clean) as possible" (p. 3), the ρ and θ choices (pp. 4-5), "contaminate" (pp. 10-11). The mechanism gets a name, relaxation grip (p. 5). The conclusion is a list of pros and cons (pp. 23-24). Adoption is self-reported without a reference: "we are confident that proximity search will find soon its way in general-purpose MIP solvers—an implementation in the open-source CBC and GLPK frameworks are already available" (p. 23).
- **D8 Contribution and limits**: The contribution is a general-purpose primal heuristic with three implementations and an evaluation protocol for heuristics. Named limits:
  - the hard cutoff θ, "perhaps the most relevant" drawback, chosen conservatively (p. 23);
  - the method's primal nature, which can trap it in "a long series of small improvements" (p. 23);
  - binaries only (p. 6).

  Future work (p. 24): a hybrid of proximity search, local branching and RINS; MIP-and-refine, in which an ad-hoc heuristic's solution is refined through a possibly weak big-M model; and a proximity objective in pricing, to stabilise branch-and-cut-and-price.

**Method links**:
- Method 6 ✅ evidence: the critical sub-decision, where to move from x̃, is handed to the black-box solver as a sub-MIP with a changed objective (pp. 2-3). The recentering version runs CPLEX "as a black box (with no callbacks)" in its default mode (p. 10). The code is minimal: one cutoff, one objective, at most one callback. This is also direct primary evidence for the skill's Heuristic 2 ("move one piece"): f and Δ swap roles relative to local branching (p. 7).
- Method 4 ✅ evidence:
  - The baselines are what a practitioner would run, including CPLEX's heuristic emphasis, polishing and guided dives, plus the original and an aggressive local branching (p. 15).
  - Every arm gets the same x̃ (p. 17), and in the column-generation test the same subinstance and warm start (p. 22).
  - Extras that would let the implementation rather than the idea decide the result are kept out: ρ, a Δ cutoff, an ad-hoc RINS, a restart policy (pp. 4-5, 10-11). θ is conservative (p. 23).
- Method 3 ⚠ variant: there is a control arm with no proximity content (zero objective instead of Δ, p. 15; not tabulated). There are no seeds or permutations, although four months earlier the same authors had revised the erraticism paper (S055 p. 1).
- Method 1 ✅ evidence (the heuristic side): weak big-M models are said to become effective inside proximity search (p. 24; quote below). The big-M class actually tested, ramp-loss SVM (p. 13), shows the widest margin: primal integral 1.045 for proxy incum against 19.687 for CPLEX default at 1200 s (Table 3, p. 16). This supports the method's line that a polyhedrally weak model can be preferred for heuristics, here in a 2013 Fischetti-Monaci text.
- new-pattern candidate: **one-instance mechanism table across the parameter** (Tables 1-2, pp. 6, 8).
- new-pattern candidate: **frozen-trajectory (open-loop) evaluation** (p. 22; see also S098 p. 18).
- new-pattern candidate: **test where the method's nature should win**: a primal method is tested where re-optimisation favours primal methods, namely column generation (pp. 20-22).

**Transferable techniques**:
- Proximity search: impose the cutoff f(x) ≤ f(x̃) − θ, minimise the Hamming distance to x̃, stop at the first feasible solution, recentre and repeat. Then re-optimise the continuous variables with the binaries fixed (pp. 4, 10).
- Use a soft cutoff with slack z and objective Δ + Mz, so that the old incumbent serves as a warm start and the solver's RINS stays active. Stop with EPAGAP = M/2 (pp. 11, 15).
- On one hard instance, tabulate the root-LP histogram, LP time and iterations against the parameter, for the new method and its rival (pp. 6, 8).
- To compare heuristics, report the primal integral at several horizons together with pairwise "at least 1% better" probability curves (pp. 14, 17-19).
- Build a re-optimisation test bed: an external column-generation driver creates nested subinstances independently of the heuristic under test, and every arm gets the same subinstance and warm start (pp. 21-22).

**Quotes**:
- "instead of modifying the constraints of the MIP at hand with the aim of reducing the search space, we modify the objective function with the aim of easing the search." (p. 3)
- "The good news is that even weak models (notably, those making extensive use of big-M tricks) can become effective when used within a proximity search framework, due to the improved relaxation grip induced by the proximity objective function." (p. 24)

### S055 · Exploiting erraticism in search (Operations Research 2014, DOI 10.1287/opre.2013.1231)
**Read level**: full. I read file pp. 1-13 of the revised manuscript OPRE-2012-05-278(R): text, Tables 1-5 and references.
**Role**: core · **Coauthors**: Michele Monaci (p. 1) · **Place in trajectory**: submitted 25 May 2012 and revised 21 March 2013 (p. 1). It is the paper form of the erraticism argument that the skill's Method 3 quotes from the EURO 2012 deck, and the representative work of the skill's Trajectory row "2010-2016 Erraticism, sampling".

- **D1 Problem and entry point**:
  - Sensitivity to initial conditions is "generally viewed as a drawback"; the paper takes "the opposite viewpoint" (p. 1). The observation is credited to Danna 2008, and its tie-breaking explanation to the MIPLIB 2010 paper (p. 1).
  - The working hypothesis: erraticism follows from the exponential nature of tree search, "a chaotic amplifier", so it is "largely unavoidable" (p. 1).
  - The entry draws on two neighbouring lines, SAT/CP restarts (p. 1) and racing ramp-up in parallel MIP. Racing ramp-up's selection criterion is "not described in full details" and, according to Koch-Ralphs-Shinano, not yet effective. The paper makes the idea sequential and "not driven by the need of avoiding idle processors" (p. 2).
  - Two questions are posed: (i) how to diversify runs without worsening the average run; (ii) how to choose the run to finish, when only a positive correlation with the best run can be hoped for (p. 2; quote below).
- **D2 Core idea**: Bet-and-run (Figure 1, p. 5): solve the first LP; for C clones, apply a randomisation and run each clone for N nodes, stopping if one solves the instance; then pick the "best" clone and run it to the time limit.
  - The value of randomness is measured before the method is designed. 58 medium instances × 100 seeds with CPLEX 12.3 give a virtual method that runs k seeds in parallel and stops at the first finisher. One extra run cuts nodes by about 40% in geometric mean; 100 runs cut them 7× (Table 1, pp. 3-4).
  - Four ways to diversify as an external user (pp. 4-5): RAN0 permutes rows and columns; RAN1 changes the seed; RAN2 re-optimises a copy of the first LP under a random objective; RAN3 does the same with the nonbasic variables of nonzero reduced cost fixed, so the copy returns another vertex of the optimal face.
  - RAN3 keeps preprocessing and the first LP shared across clones, which matters on easy instances (p. 4).
  - Transferable: before building a method that exploits randomness, compute the "best of k seeds" curve (minimum nodes over k runs, k = 1 to 100). It is the ceiling for any exploitation scheme (Table 1, p. 3).
- **D3 Problem class and data model**:
  - Model: general MILP in equality form, with bounds inside Ax = b (pp. 2-3). RAN3 relies on dual degeneracy, "that arises almost invariably in MIP problems" (p. 4). With inequalities, the slacks need handling, and each inequality with a nonzero dual must temporarily become an equality (pp. 4-5).
  - Test set: COR@L (372 instances, minus one pure LP, one that could not be downloaded and three duplicates, leaving 367) and the MIPLIB 2010 benchmark and tree classes plus the instances marked hard (166); 41 instances are in both (p. 7). The 148 instances that the ideal "best" did not solve within 10,000 s are dropped, leaving 344 (p. 7). The preliminary set is 58 medium instances from COR@L and MIPLIB 2010, listed in a footnote (p. 3).
  - Aside: the second seeded run proved buildingenergy optimal for the first time (2,839 CPU s). A rerun with optimality tolerance zero on 8 threads, with that value as the initial upper bound, needed 623,861 more nodes and found the zero-tolerance optimum 33,283.8532, below the 33,285.4433 accepted under default tolerances (p. 4).
- **D4 Algorithm and implementation design**:
  - RAN3 (p. 5): nonbasic variables with zero reduced cost get random costs, uniform in [1, 100] at their upper bound and in [−100, −1] at their lower bound; all other costs stay unchanged. The re-optimisation may use at most 10% of the first LP's pivots, clamped to [10, 100].
  - Clone selection (pp. 5-6) uses eight short-run indicators in priority order: open nodes; bound improvement over the root, in geometric mean; the sums over open nodes of integer-infeasible counts, of depths and of integer infeasibilities; best bound; best incumbent; simplex iterations.
  - An indicator is dropped when its max − min is below θ times its mean (θ = 0.2). The ⌊0.6C⌋ clones best on the first remaining indicator are kept; the second and third indicators break ties. The order favours the unperturbed clone, "so as to select a perturbed clone only when this seems to be really beneficial" (p. 6).
  - Settings: C = 5 clones (the default plus 4) and N = 5 nodes. A root-only variant (N = 1) was worse (pp. 6-7).
  - Hybrid: run default for NR = 500 or 1,000 nodes, and sample clones only if the instance is still unsolved (pp. 8-10).
  - Implementation: CPLEX callbacks, "As external users" (p. 4). Cutting the preprocessing overhead is "hardly achievable without having a direct access to the solver's source code" (p. 8).
  - Theory: no proofs. The one correctness argument is that RAN3's fixing keeps the copy inside the optimal face (p. 4).
  - Transferable: diversify after the first LP by moving to another optimal vertex (random costs on the zero-reduced-cost nonbasic variables, with a pivot cap), so preprocessing and the first solve are paid only once (pp. 4-5).
  - Transferable: select from priority-ordered short-run indicators, discarding indicators by their spread and breaking ties towards the unperturbed run (pp. 5-6).
- **D5 Computational evaluation**:
  - Setup: Intel i5-750 at 2.67 GHz, CPLEX 12.3, single-thread with no concurrent threads (p. 6). "For a fair comparison, all codes use a (possibly dummy) callback function, thus deactivating IBM ILOG Cplex’s proprietary dynamic search" (p. 6). Time limit 10,000 s; geometric means shifted by 0.01 s (pp. 6-7).
  - Arms: default and bet-and-run, plus two ideal oracles reported "for benchmark purposes only" (p. 7). best takes the better of the two arms per instance; ideal takes the best of the 5 clones.
  - Classes are defined by the larger node count of the two arms, a rule in which both arms "play an indistinguishable role" (p. 7). Bet-and-run times include sampling, and Tlast is counted conservatively (p. 8).
  - Results (Table 3, p. 9; text p. 8):
    - Losses on easy classes are printed: +140.3%, +83.5% and +53.0% time for the 10-100, 100-1,000 and 1,000-10,000 node classes.
    - Gains on hard classes: −28.5% time and −51.8% nodes for 10,000-100,000 nodes; −17.9% and −28.6% for ≥ 100,000. Bet-and-run solves 3 more instances.
    - Over all 344 instances: +17.2% time but −18.2% nodes.
  - Hybrid: +5.3% and +3.6% time overall for NR = 500 and 1,000. The 1,000-10,000 node class is the critical one (+76.4% and +79.4%) (pp. 10-12). The authors warn that classes shift between Tables 3-5, so class-by-class comparisons across tables "can be misleading" (p. 10).
  - The preliminary 100-seed runs report nodes and LP iterations instead of time, because the workstation's load varied (p. 3).
  - Bet-and-run is compared with default on one run per instance per arm, with no seeds or permutations (pp. 6-9).
  - My reading of Table 2 (p. 7): the clone choices are uneven. Clone 4 was chosen 92 times, clone 3 27 times and the default clone 0 37 times out of 268. The text says "no significant biasing in the clone choice seems to exist" (p. 7), with neither a test nor an explanation.
  - Transferable: print ideal-oracle ceilings beside the method (the best of the two arms; the best of all clones). The reader then sees how much of the available spread the selection rule captures (pp. 6-7, Table 3).
- **D6 Positioning**:
  - Prior work cited: SAT/CP restarts and heavy tails (Gomes, Selman, Kautz; Huang; Haim-Heule), MIP backdoors (Dilkina et al.), information-based branching (Karzan-Nemhauser-Savelsbergh) and the authors' own backdoor branching (p. 1); grid QAP solving (Anstreicher et al.) and ParaSCIP's racing ramp-up (p. 2).
  - Portfolios and parameter-setting variants are set aside "to investigate pure erraticism" (p. 2).
  - The tone is to credit and extend; there is no polemic.
- **D7 Writing**:
  - The thesis is argued ("we argue", p. 1). The frame is deliberately modest, a "proof-of-concept implementation" (pp. 1, 6, 10), next to an "ambitious goal" (p. 3).
  - Losses are stated as expected: "As expected, for “easy” instances our approach is not beneficial" (p. 8). They are turned into a usage rule: an on/off flag, since users "know in advance" whether their models need much enumeration (p. 8).
  - There is one self-assessment: solving three more instances "is by itself a main accomplishment" (p. 8).
- **D8 Contribution and limits**: The contribution is a viewpoint (exploit variability instead of averaging it away) and an algorithmic framework with a working default. Named limits:
  - the selection rule is "quite unsophisticated" (p. 6);
  - gains fade in the hardest class because the early-search signal is "overtaken by erraticism" (p. 8);
  - overhead hurts easy instances (pp. 8-10);
  - the 148 instances that neither arm solved are outside the evidence (p. 7).

  Future work (p. 10): better diversification given access to the source; machine-learned selection; restarts that reuse primal solutions, cuts and pseudocosts; portfolios; erraticism as a source of early incumbents; NR chosen on the fly from a tree-size estimate (Cornuéjols et al.).

**Method links**:
- Method 3 ✅ evidence: the spread is measured first (100 seeds on 58 instances, single-thread), then exploited (bet-and-run), and the classes where it does not pay are printed (pp. 3-9). The positive-correlation sentence (p. 2) is the paper form of the skill's Heuristic 6. In this file the statement that easy instances do not benefit is on p. 8, with Table 3 on p. 9.
- Method 3 ⚠ variant: the method-versus-default table has no seeds of its own (one run per instance per arm, pp. 7-9), and there is no placebo arm. Variability appears as a resource and as a ceiling (the ideal oracle), not as a control arm.
- Method 4 ✅ evidence:
  - a dummy callback in every arm (p. 6);
  - classes blind to which arm is which (p. 7);
  - exclusions listed with their reasons (p. 7);
  - ideal-oracle ceilings printed (p. 7);
  - a conservative Tlast (p. 8);
  - the baseline's own run kept as one clone (clone 0, p. 7).
- Method 6 ✅ evidence: the potential is measured before the method is built (the best-of-k-seeds table, p. 3; the method's step 4). The black-box limit is stated as the lesson: overhead and diversification are limited without access to the source (pp. 4, 8, 10; step 5).

**Transferable techniques**:
- A best-of-k-seeds table (k = 1, 2, 3, 5, 10, 25, 50, 100) with unsolved counts, nodes and LP iterations, in both geometric and arithmetic means (Table 1, p. 3).
- RAN3 diversification at the first LP's optimal face (pp. 4-5).
- Bet-and-run with C = 5 clones, N = 5 nodes, a ranked list of indicators and the θ = 0.2 discard rule (pp. 5-7).
- A hybrid that runs default for NR nodes before sampling, so easy instances pay no overhead (pp. 8-10).
- Before claiming a new optimum, re-solve with zero optimality tolerance, using the value found as the initial upper bound (p. 4).

**Quotes**:
- "Erraticism is generally viewed as a drawback to be avoided. Instead, we argue that a certain degree of erraticism is unavoidable, as it is related to the exponential nature of tree search that acts as a chaotic amplifier, so one has to cope with it." (p. 1)
- "Therefore, one has to content him/herself with a criterion that gives a positive correlation between the selected run and those that a posteriori behave better than the average." (p. 2)

### S098 · Boosting the feasibility pump (Mathematical Programming Computation 2014, DOI 10.1007/s12532-014-0068-9)
**Read level**: full. I read file pp. 1-32 of an undated author manuscript, whose web references were "Last accessed 24/05/11" (pp. 25-26): text, algorithms and references. The performance profiles (Figures 2-9, pp. 19, 21-22, 28-32) are images without extracted content, so their values come only from the text (pp. 20, 23-24).
**Role**: core (joint; the voice is not Fischetti's alone) · **Coauthors**: Natashia L. Boland, Faramroze G. Engineer and Martin W.P. Savelsbergh (Newcastle); Andrew C. Eberhard and Angelos Tsoukalas (RMIT). Fischetti (Padova) is fourth of six in alphabetical order (p. 1). The text refers to "Fischetti and Salvagnin (2009)" in the third person and calls the pump code "kindly provided by Fischetti and Salvagnin" (p. 18). The line-search design therefore reads as the co-authors' work on the FP 2.0 code base; who did what is not stated. · **Place in trajectory**: an enhancement of his 2005 pump by an outside group with his participation, built on FP 2.0 (2009).

- **D1 Problem and entry point**: Almost all improvements of the feasibility pump (FP) target the projection step: Bertacco et al., Achterberg-Berthold, Hanafi et al., De Santis et al. Fischetti-Salvagnin's propagation rounding is the exception (p. 2). The effort is "lopsided", and anti-cycling mechanisms "undo the work performed by the projection procedure" (pp. 2-3). The entry: put more effort into the transformation (rounding) step and examine all rounded solutions along a line segment through x* (p. 3).
  - Transferable: when a field's improvements all target one half of an alternating method, measure what the neglected half leaves on the table.
- **D2 Core idea**: An integer line search replaces rounding. It rests on four ideas (p. 3): (1) enumerate every distinct rounding along a segment efficiently; (2) use cheap end points; (3) extend the segment beyond its end points and project it back onto the bound box; (4) propagate at chosen times.
  - The end point only has to give "a direction towards feasibility" (p. 10). A conic combination of the constraints violated by the rounded start, weighted by signed distance, replaces analytic centres (p. 11). Weighting by ‖aⁱ‖₂² instead (a steepest-descent direction of a quadratic penalty) brought no improvement (p. 11).
  - Unchanged: FP's projection and its restarts. The line search runs wherever FP rounds (p. 18).
- **D3 Problem class and data model**: General MIP min cx, Ax ≤ b, l ≤ x ≤ u, x_j integer for j ∈ I (p. 4). General integers are handled through the bound box (pp. 12-14). With continuous variables, each explored integer point needs an LP; it is warm-started, since only right-hand sides change, but it "can become expensive" (p. 8). Test set: 1,304 instances from MIPLIB 2003, MIPLIB 2010, COR@L and OR-LIB. 31 were removed for stated reasons: 10 whose LP relaxation took over 30 minutes, 2 with an infeasible LP, and 19 that ran out of memory in one experiment (p. 17).
- **D4 Algorithm and implementation design**:
  - Breakpoints, the points where the rounding of variable i changes, are an initial λ̄ᵢ plus integer multiples of 1/(xᵗᵢ − xˢᵢ) (pp. 6-7).
  - Algorithm 2 sorts all (variable, breakpoint, direction) triples and moves one variable by one unit per step, checking feasibility (pp. 7-8). It is pseudo-polynomial in |xᵗ − xˢ| (p. 8). Once breakpoints are filtered by the bounds through k⁻ and k⁺, it is pseudo-polynomial in |u − l| (pp. 12, 14).
  - A three-binary example shows that extension and projection reach roundings the plain segment cannot (Figure 1, pp. 11-13).
  - With propagation, propRound fixes the start point, and a variable's fixing is propagated only when that variable has no changes left. This gives at most 2|I| propagate calls (pp. 15-16).
  - Prior work credited: Hillier (1969) "does allude" to such an efficient procedure (p. 8). The analytic centre comes from CPLEX's barrier on a zero objective (p. 9), and the weighted centre follows Naoum-Sawaya-Elhedhli (pp. 9-10).
  - Transferable: to enumerate every rounding of a segment, sort the per-variable breakpoints once and walk them with unit changes. Each step changes one coordinate, so feasibility can be updated incrementally (pp. 6-8).
- **D5 Computational evaluation**:
  - Setup: 3.16 GHz Xeon with 64 GB (2 GB per process); CPLEX, version not stated, for the LPs, projections and barrier (p. 17). One FP run per instance from the LP solution, with a 30-minute limit that includes the line searches (p. 18).
  - Shadow design: each line search runs at every rounding, but is "only recorded for analysis purposes", and FP continues as if it had not run (p. 18; quote below).
  - Metric: performance profiles of the percentage improvement over FP. The part of the profile beyond 100% counts the instances where only the variant found a feasible solution (p. 18).
  - Main results (p. 20): FP+ is better than FP on about 40% of instances and finds a solution where FP failed on about 9%. FP+ls(c,[-1,2],y) is better on about 66% and rescues about 12%.
  - A deterioration profile is printed too: worse than FP on 13% of instances (FP+) and 9% (the line search).
  - Cost: FP+ls is 1.22× slower than FP+. The line search took 85,037 s without propagation and 57,055 s with it, because propagation means fewer LP solves (p. 20).
  - Attribution (pp. 23-24):
    - The weighted analytic centre looks best (46% vs 42%). With every variant capped at the conic search's breakpoint count, the three end points perform comparably (p. 23; quote below).
    - A random direction with the same budget still beats FP+ on 36% of instances; the conic direction beats random on 8% more.
    - The analytic-centre variants are 2.5× slower than FP+ (p. 24).
    - Projection onto the bounds matters more than extension, and both matter more without propagation (p. 24).
  - Caveat stated by the authors: the FP+ls statistics were collected along FP+'s trajectory, so neither FP+ nor FP+ls is guaranteed to be no worse than FP (p. 20).
  - Missing: seeds, statistical tests, and any baseline outside the FP family.
  - Transferable: attribute a gain in two steps. First cap every variant at the same search budget (here, breakpoints). Then add a random-direction arm with that budget. What is left is the direction's own contribution (pp. 23-24).
- **D6 Positioning**:
  - The paper sits inside the FP lineage (Fischetti-Glover-Lodi 2005; Bertacco et al.; Achterberg-Berthold; Fischetti-Salvagnin) and the older line-search heuristics (Hillier 1969; Jeroslow-Smith; Faaland-Hillier; Baena-Castro; Naoum-Sawaya-Elhedhli) (pp. 2-3, 8-10).
  - It claims without a source that FP "has become a standard component of state-of-the-art (commercial) solvers" (p. 2).
  - It neither mentions nor cites the proximal reading of the pump by four of its own authors. The text has no "proximal", and the reference list (pp. 25-27) does not include that work. By contrast, Fischetti-Monaci cite it in S052 (p. 7).
- **D7 Writing**: The "primary contribution" sentence lists four numbered ideas, and the introduction already gives the headline numbers (pp. 3-4). Primary and secondary goals of the study are stated before the experiments (p. 17). The close is modest: "a small incremental step forward", with the remaining ideas mostly "variations on a theme" (p. 25). There is one self-assessment: "a combination of innovative ideas and clever engineering" (p. 25).
- **D8 Contribution and limits**: The contribution is an algorithmic enhancement of FP's rounding step at modest cost (p. 24). The named limit is cost: with many breakpoints and many continuous variables, the per-point LPs become "substantial" (p. 25; also p. 8). Future work: solve for the continuous variables at a few chosen breakpoints only; search in several directions or in a "tree-like" manner (p. 25).

**Method links**:
- Method 4 ✅ evidence:
  - the shadow design gives every line-search variant the same FP+ iterates (p. 18);
  - one code base, with the arms as options (FP versus FP+ is a switch, p. 18);
  - exclusions listed with their reasons (p. 17);
  - a deterioration profile beside the improvement profile (p. 20).

  Gaps: the CPLEX version is not stated (p. 17), and no rival pump variant, such as the objective pump, is run.
- Method 3 ⚠ variant: a random-direction arm with a matched budget does the job of a placebo arm. It is used to attribute the gain to the volume of search versus its direction, not to measure variability; there are no seeds (pp. 23-24).
- Note for the synthesis (a heuristic, not a Method): the skill's Heuristic 9 cites this paper as following the co-authors' proximal recasting of the pump. This text never refers to that work (D6), so the link rests on authorship alone.
- new-pattern candidate: **frozen-trajectory (open-loop) evaluation** (p. 18; S052 p. 22).
- new-pattern candidate: **matched-budget attribution with a random control** (pp. 23-24).

**Transferable techniques**:
- A breakpoint walk that enumerates all roundings along a segment, one unit change per step (pp. 6-8).
- A cheap feasibility direction: the violated rows, weighted by signed distance (p. 11).
- Extension with α ∈ [−1, 2], plus projection onto the bounds by filtering breakpoints (pp. 12, 14, 17).
- Propagate a variable only after its last change on the line, which gives at most 2|I| propagations (p. 16).
- Shadow evaluation: run the component along an unchanged baseline trajectory (p. 18).
- A budget-matched ablation with a random-direction control (pp. 23-24).

**Quotes**:
- "After the integer line search has been executed, FP proceeds as if the execution of the integer line search did not take place. This allows for a fair comparison between the different line searches as the FP trajectory is not altered." (p. 18)
- "Thus, the performance difference observed earlier is not caused by the choice of end points, but by the difference in number of rounded solutions explored." (p. 23)

### S023 · Benders decomposition without separability: A computational study for capacitated facility location problems (European Journal of Operational Research 2016, DOI 10.1016/j.ejor.2016.03.002)
**Read level**: full. I read file pp. 1-28 of the preprint submitted to Elsevier on 7 February 2016: text, Tables 1-5 and references. Figures 1-2 extracted only as axis labels, so I read them through the text (pp. 18, 20).
**Role**: core · **Coauthors**: Ivana Ljubić (ESSEC) and Markus Sinnl (Vienna); Fischetti is the corresponding author (p. 1) · **Place in trajectory**: the capacitated and congested companion of the facility-location Benders redesign. That paper ([14], "submitted" in 2015, p. 24) is the Manag. Sci. 2017 paper in the skill's Signature Work. This one carries its in-out root loop over to a slave that does not decompose.

- **D1 Problem and entry point**:
  - The question is whether Benders helps "even without separability", when the slave is as large as the original problem (p. 1).
  - Applying Benders to CFL follows the "recipe" (keep the integer variables, relax the continuous ones), yet since Wentges (1996) Benders "was not considered the solution method of choice" (p. 3).
  - The goal is to provide "guidelines for a modern implementation" based on MIP technology "not available back in the 70’s and 80’s" (p. 3). The paper treats both linear multiple-source CFL and congested CFL with convex quadratic congestion and a p-median constraint (pp. 2-5).
  - Transferable: take a classical decomposition that the literature has abandoned and ask what it is worth when implemented as callbacks in a current solver, a setting its original authors lacked.
- **D2 Core idea**:
  - Project all allocation variables out. The master in y has one variable w for the objective and the aggregate-capacity constraint Σⱼ sⱼyⱼ ≥ Σᵢ dᵢ. This constraint acts "as a global feasibility cut", so no Benders feasibility cuts are needed (p. 8).
  - Why a non-separable slave can still pay: with y fixed, preprocessing turns the linking constraints xᵢⱼ ≤ yⱼ into variable bounds and the SOC constraints into ordinary quadratic ones. The slave "can be orders of magnitude faster" than the relaxation with y free (pp. 8-9).
  - The diagnosis blames the root loop, not the cut (p. 10; quote below). Cut selection is kept basic: no Pareto-optimal cuts (p. 9). The root loop is stabilised by an in-out scheme run before branch-and-cut (pp. 10-11).
- **D3 Problem class and data model**:
  - Assumptions for the cut derivation: f and g differentiable and convex; S = {y : Ay ≤ b} a nonempty polytope; each X(y) nonempty, closed and bounded (p. 6). Constraint qualifications are needed for the subgradient formula, and infeasible y can be handled by a feasibility function (p. 7).
  - Linear CFL is multiple-source; single-source is "a variant not covered" (p. 4).
  - Congested CFL takes F(t) = at + b, so the congestion cost is quadratic. The compact baseline is the perspective reformulation with SOC constraints vⱼ² ≤ zⱼyⱼ (pp. 4-6).
  - Instances (pp. 14-15):
    - 12 cap* instances from the OR-Library (1,000 customers × 100 facilities); the smaller ones are dropped as trivial.
    - 75 smaller and 120 larger GK instances from the Görtz-Klose generator.
    - 100 i* instances (Avella-Boccia).
    - 445 p* instances in test beds A, B and C, up to 2,000 facilities × 4,000 customers, never solved to optimality before.
  - Congested runs use 60 i*-based instances: 5 sizes × 4 instances × π ∈ {0.4, 0.6, 0.8}, with p = ⌊π|J|⌋ (pp. 21-22).
- **D4 Algorithm and implementation design**:
  - Cut derivation: add copies q with y − q = 0, imposed as bounds. The subgradient is then the reduced-cost vector r* of those bounds, and the cut is w ≥ Φ(y*) + Σⱼ r*ⱼ(yⱼ − y*ⱼ) (eqs. 27-31, pp. 7-8). The toy example Φ(y) = |y| shows that even an LP's value function is nonlinear (p. 7).
  - For linear CFL, the assignment duals u* are fixed and the cut coefficients recomputed from |J| continuous knapsacks solved by sorting; this is valid for any u (pp. 9-10).
  - The slave is solved by the general LP solver (dual simplex) rather than a transportation code, because of its warm start (p. 9).
  - In-out loop (pp. 10-11):
    - ỹ starts at argmax Σⱼ yⱼ over S, computed by barrier without crossover. Each round sets ỹ = αỹ + (1 − α)y* and separates the point λy* + (1 − λ)ỹ.
    - After 5 non-improving rounds, λ is set to 1 (Kelley); after 5 more, the loop stops and slack cuts are purged. Slack cuts are also purged every 5th round.
    - Parameters: α = 0.5 and λ = 0.2 for congested CFL, taken from [14]. For linear CFL, α = 0.9 and λ = 0.1, so consecutive separation points stay close and the dual-simplex slave warm-starts quickly. This does not help the congested slave, which barrier solves from scratch (p. 11).
  - "Blurring": uncapacitated, combinatorial Benders cuts for fractional points, and exact capacitated cuts only for integer incumbents. It pays on "just a few instances" (p. 11).
  - Implementation on CPLEX 12.6.1 (pp. 12-14):
    - Threads are reset to the hardware's 4, in opportunistic mode, with one slave clone per thread. Four parallel copies of the in-out loop run with perturbed α and λ; the first to finish wins, and all cuts are pooled (p. 12).
    - Settings: aggressive internal cuts, full strong branching, pure best-bound search and RINS at every node. Separation can take over 90% of the time, so the defaults are "inappropriate" (p. 12).
    - Per node, at most 20 consecutive separation calls (100 at the root). Separation gives up once K ≥ 2 and the slave's primal value is below the incumbent, and fractional points are not separated while separation exceeds 50% of the time (p. 13).
    - Integer candidates are always separated in the lazy-constraint callback, "To ensure correctness" (p. 13).
    - Two restarts after the root reload the saved cuts as static cuts (p. 13).
    - Tolerances: master EPINT = 0, EPRHS = 1e-7, EPGAP = 1e-6; slave EPRHS = EPGAP = 1e-9; CALCQCPDUALS = 2 for the congested slave (pp. 13-14).
  - Transferable: derive generalised Benders cuts without problem-specific derivatives. Fix copy variables through bounds and read the cut from their reduced costs (pp. 7-8).
  - Transferable: choose the stabilisation parameters by the oracle's cost structure. Keep separation points close together when the slave warm-starts (dual simplex); use the standard values when it solves from scratch (barrier) (p. 11).
- **D5 Computational evaluation**:
  - Setup: a cluster of Xeon E3-1220V2 at 3.1 GHz with 16 GB; 4-thread wall-clock times; time limit 50,000 s (p. 14). The baseline is CPLEX 12.6.1 on the compact or perspective model with EPGAP = 1e-6, as in the Benders master, and all other parameters at default (pp. 14, 22). Gaps are measured against the best value found by Benders (p. 14).
  - cap*: Benders is an order of magnitude faster than CPLEX, and blurred Benders 10-90× faster despite up to ten times more nodes (p. 16; Table 1, p. 17).
  - i*:
    - CPLEX 12.6.1 "Surprisingly" solves all of them (p. 17). Benders beats CPLEX except at 1,000 × 1,000 with r = 15 (p. 17).
    - Against the literature, Benders often beats Avella-Boccia's B&C&P and is often slower than Görtz-Klose's Lagrangian B&B. Their difficulty patterns in r run opposite to each other (pp. 17-18).
    - Average times exclude unsolved cases, following [17] (p. 17).
  - GK:
    - At the root, Benders needs at most 170 s while CPLEX needs over an hour on 13 instances, and the root gaps are "almost identical" (p. 18; Fig. 1, p. 20).
    - At 50,000 s Benders does not close every instance that Görtz-Klose solved: 38 optimal, average gap 0.08%, maximum 0.4% (pp. 18-19).
    - Only the 120 larger GK instances are reported; the 75 smaller ones are described (p. 15) but no results are given for them (pp. 18-19).
  - p*: optimality is proven for 210 of 445 instances. Stopped after 10 nodes and used as a heuristic, Benders gives smaller gaps in less time than Guastaroba-Speranza's kernel search on all three test beds (p. 20; Fig. 2, p. 21).
  - Congested CFL: Benders solves 45 of 60, the rest ending at gaps ≤ 0.3%. The perspective model solves 21, hits the time limit on 23 with gaps up to 35%, and fails for memory on 16 (p. 22). Removing the cardinality constraint barely changes Benders (Table 5, p. 22).
  - Reporting caveats:
    - Rival methods are compared through their published times on other machines and older CPLEX versions, scaled by Linpack Mflop/s (pp. 16-17, 20). For Görtz-Klose, CPLEX 8.0 is said to be "not much slower" than 12.6.1 as an LP solver, without evidence (p. 16).
    - There is one nondeterministic run per instance and no seeds (pp. 12, 14).
    - No Kelley-versus-in-out ablation is reported. The stabilisation claim rests on [14] and on the root gaps (pp. 11, 18).
  - Transferable: show the effect of the projection at the root, separately from the tree. Give root-time profiles and root gaps for the decomposition against the compact model on the same machine (Fig. 1; pp. 18, 20).
- **D6 Positioning**:
  - Rivals: the exact state of the art is Avella-Boccia's B&C&P and Görtz-Klose's Lagrangian B&B; the heuristic one is Avella et al. and Guastaroba-Speranza (pp. 2-3).
  - The paper revises how the field explains slow Benders convergence: "many authors attributed slow convergence to dual degeneracy, hence focused on how to select a “best possible” Benders cut" (p. 10). Magnanti-Wong, Van Roy, Wentges and Naoum-Sawaya-Elhedhli represent the cut-selection line (p. 9).
  - Stabilisation credit: bundle methods (Lemaréchal-Nemirovskii-Nesterov) are named as the reference. The in-out variant is "very much in the spirit of" Ben-Ameur-Neto, Fischetti-Salvagnin and Naoum-Sawaya-Elhedhli, following the authors' own UFL paper [14] (p. 10).
  - The only exact rival that stays competitive is described as itself "relatively simple" (p. 23).
- **D7 Writing**:
  - The abstract is led by the question, and its outcome is hedged: "comparable and sometimes even better" (p. 1). The diagnosis is one sentence, "the real culprit" (p. 10).
  - Restraint in tuning is stated twice: p. 17, and "not tweaked for the specific application at hand" (pp. 22-23). Surprise is admitted ("Surprisingly", p. 17).
  - The closing claims are strong. Benders "can be considered one of the state-of-the-art solution approaches for CFL", and for congested CFL "Benders clearly qualifies as the best-available solution method" (p. 23). The only comparator in the congested case, though, is the perspective model in CPLEX, as no earlier computational study exists (p. 21).
  - On the p* set: "This is the first attempt to solve the largest instances of this class to provable optimality" (p. 15).
- **D8 Contribution and limits**: The contributions are computational and algorithmic guidelines plus a simplified generalised Benders cut. Named limits:
  - the non-decomposable slave penalises Benders "intrinsically" against the Lagrangian B&B (p. 23);
  - "the last per-mills of the gap" remain hard to close (p. 18);
  - blurring pays only where capacities are loose (pp. 11, 16);
  - the 1,000 × 1,000 instances with r = 15 are a weak spot (p. 17).

  The conclusion names no future work (pp. 22-23).

**Method links**:
- Method 2 ✅ evidence (primary, joint): the slow-convergence diagnosis moves from the cut to the root loop (p. 10). An in-out query point with a Kelley fallback runs before branching, with the same separator throughout (pp. 10-11), and the lineage is credited (p. 10). This goes beyond the UFL showcase instance: on 120 GK instances the stabilised root reaches root gaps "almost identical" to CPLEX's (p. 18). The paper has no Kelley arm, however, so the loop's share of the gain is asserted here, not measured.
- Method 2 ⚠ variant: the stabilisation parameters are set by what makes the oracle cheap, namely separation points close together for a warm-started LP slave (p. 11).
- Method 1 ✅ evidence: the allocation variables are projected out and the master is thin. The gain at the root shows up where many allocation variables are removed (p. 18).
- Method 6 ✅ evidence: the stock LP solver serves as the slave instead of a specialised code (p. 9). Plain CPLEX on the compact model is a reported baseline, and a strong one: it solves all i* instances (pp. 16-17).
- Method 6 ⚠ variant: what is tested is a fully engineered callback package with the defaults overridden (p. 12), not the smallest code with the extras off.
- Method 3 ⚠ variant: the spread is exploited as a parallel race of perturbed root loops whose cuts are pooled (p. 12). The protocol has no seeds and runs nondeterministic 4-thread jobs (pp. 12, 14). This also contradicts the skill's "single-threaded" blind-spot line for this paper.
- Method 4 ✅ evidence: the new method is deliberately untuned ("not the intention", p. 17; "not tweaked", pp. 22-23), and both arms use the same EPGAP on the same machine (pp. 14, 22).
- Method 4 ✗ contradiction (a dated lapse): rival methods are judged by their published times on other hardware and older CPLEX versions, scaled by Linpack (pp. 16-17, 20). This is the kind of lapse the skill already lists for the 2017 bilevel study.

**Transferable techniques**:
- The copy-variable trick for generalised Benders cuts: y − q = 0 imposed as bounds, with the cut read from their reduced costs (pp. 7-8).
- An aggregate-capacity constraint in the master in place of Benders feasibility cuts (p. 8).
- For stability, recompute the cut coefficients through Lagrangian knapsacks with the assignment duals fixed (pp. 9-10).
- An in-out root loop with a 5 + 5 non-improving-rounds rule and slack purging, whose parameters are set by the slave's warm start (pp. 10-11).
- Race the root loop across threads with perturbed parameters, and pool all the cuts (p. 12).
- A node give-up rule based on the slave's primal value, and a 50% time cap on fractional separation (p. 13).
- Separate every integer candidate in the lazy-constraint callback (p. 13).
- Two root restarts that reload the saved cuts as static cuts (p. 13).
- Slave tolerances tighter than the master's (1e-9 against 1e-7 and 1e-6) (p. 13).
