## 1. Proof devices (PD)

| # | Technique | How to use | Cards |
|---|---|---|---|
| PD1 | Hardness to justify a cheap rule | When a component must solve a selection problem exactly (a minimal infeasibility explanation, a redundancy test), prove it hard by a reduction from a known hard problem, measure the literature's heuristic, and keep the cheapest rule on data already computed | [R004 p. 11; D004 p. 188; D030 p. 3; D004 p. 100] |
| PD2 | A certificate that survives relaxation | The left side of a Farkas aggregation does not depend on the local bounds, so relax bounds one at a time while the right side stays negative; for a bound-exceeding LP use the dual solution and keep the bound exceeded | [R004 pp. 12–13; D004 pp. 188–191; R008 pp. 8–9] |
| PD3 | Exchange arguments | To show a column dominated, move the surplus from one column to the other and check every row and the objective; the same device proves best-first search optimal in nodes | [R021 pp. 44–45; D004 p. 89] |
| PD4 | Fixed-LP argument | For a dual reduction on a MIP, fix the integers at an optimal solution and apply LP duality to the continuous remainder, using dual bounds that do not depend on the right-hand side | [R021 pp. 58–59] |
| PD5 | Undetermined coefficients | To derive an implied relation, write the target relation and both source rows as implications on the binary, scale them, match coefficients and read off the validity conditions | [D022 p. 6; D023 pp. 6–7] *(co-signed)* |
| PD6 | Two-direction lemma from an arbitrary point of the local box | To recognise a subtree without restrictions, prove that it is unrestricted if and only if every constraint is locally redundant, and test that at the node | [R010 p. 4] *(co-signed)* |
| PD7 | Counterexample that motivates a limit | Before capping a propagation loop, build the smallest system that reduces forever (two rows suffice) and set a minimum relative bound change against slow ping-pong chains | [R021 p. 11; D004 pp. 100–101] |
| PD8 | Validity by construction | Generate every cut as an MIR inequality of an aggregation of original rows, so that a wrong detection can only make cuts weak or dense, never invalid | [D011 pp. 7–9, 35; R013 pp. 3, 27] *(co-signed)* |
| PD9 | Termination by growth or ordering | Show at least one new row per iteration of a finite cycle matrix, or a well-founded ordering for term normalisation | [D020 p. 9; D004 p. 236] |
| PD10 | Class generalisation by construction | Define the class by what remains after fixing the integers (an LP), then prove the parent classes are special cases by constructing the residual LP for each | [R012 pp. 5–6; D004 pp. 27–28] |
| PD11 | Exactness condition for a filter | Prove when a cheap filter is exact (here: when all McCormick inequalities hold at the LP point), then state what the solver does when the condition fails | [D023 pp. 11–13; D022 pp. 9–10] *(co-signed)* |

## 2. Design moves (DM)

| # | Technique | How to use | Cards |
|---|---|---|---|
| DM1 | Incumbents as settings of one family, with the map drawn | Before running anything, express the rival rules as values of one new parameter and draw which value gives which old rule; the baselines are then the same code | [R002 p. 8; D004 p. 82; R006 p. 5; D010 p. 18] |
| DM2 | Budgets in solver-internal units | Cap expensive components in units of the solver's own work: strong-branching iterations relative to node-LP iterations, useless probings and fixings, touched non-zeros scaled by success, work and success ratios, a capped conflict pool, call frequency and rounds for a separator | [R002 p. 6; D004 pp. 78–80, 171; R021 pp. 49, 64, 66; D022 p. 10; D023 p. 13] |
| DM3 | Normalise heterogeneous scores before weighting | Divide each score by its current average over the candidates, map it with x/(x+1), only then weight; test a product score against the weighted sum at several weights | [D004 pp. 76, 81; D010 p. 18] |
| DM4 | Correct a biased cheap estimate and keep contaminated observations out | Correct limited-iteration gains with a ratio of sums under exponential forgetting (not a mean of ratios); exclude infeasible children and children changed by node preprocessing or local cuts from the statistic | [R001 pp. 8–9] *(co-signed)* |
| DM5 | A detector with a numeric fit, used twice | Give a structure detector a fit measure (minority votes per arc, averaged over arcs), drop elements above one threshold and switch the whole component off above another | [D011 pp. 11, 19–20; R013 p. 10] *(co-signed)* |
| DM6 | Compute only the missing input for an existing routine | Implement a structure-specific cut family as an aggregation for the solver's existing c-MIR: compute the weights and multipliers only, and inherit bound substitution, rounding and validity | [D011 pp. 3, 23] *(co-signed)* |
| DM7 | A minimal exported summary when modularity hides a view | When plugins hide the column view, require every handler to export the two lock counts per variable; they suffice for dual fixing and guide rounding, branching and later product records | [D010 p. 14; R017 p. 4; D023 p. 8] |
| DM8 | A mandatory correctness callback, optional speed callbacks | Make a handler's feasibility check alone give a correct (if enumerative) solver; presolve, propagation, relaxation and branching are optional speed | [R003 p. 9; R009 p. 5; D010 pp. 7–8] |
| DM9 | Degrade on numerical trouble | On an unstable LP, retry with other LP settings; if that fails, drop the node's LP bound and continue by branching instead of aborting | [R003 p. 20; D004 p. 48] |
| DM10 | Numerical safeguards | Split wide bit vectors into 16-bit words with carries; in presolve clean tiny coefficients within a tolerance budget, demand a minimum bound change, use gcd heuristics, a Markowitz-type pivot test and multiplier caps | [R008 p. 5; R009 p. 12; D010 p. 34; R021 pp. 9, 11, 15, 25, 33; D030 p. 7] |
| DM11 | Count a linearization before adding it | Count the rows and auxiliary variables a linearization needs; above what the LP can carry, propagate only (a 64-bit shift-left would need 30,944 inequalities and 20,929 auxiliary variables) | [R009 p. 12; D010 p. 34; R008 pp. 6–7] |
| DM12 | Seed conflicts from the dual ray; move non-binary bound changes to the conflict side | Start the conflict graph from the bounds the LP infeasibility proof uses; to keep set-covering conflicts, move non-binary bound changes to the conflict side of the cut | [R004 pp. 11–15; D004 pp. 189–192] |
| DM13 | Import a habit in restricted form, with the reason | Re-decide a source field's default for the target: restart once after the root when at least 5 % of the integers were fixed, because root fixings can trigger more presolving at the cost of a second root LP | [R012 p. 11; R009 p. 9; D004 p. 174] |
| DM14 | Mirror a pruning rule for a new task | Turn a pruning condition into its mirror for a new question (unrestricted subtrees for counting all solutions) and switch off what could cut off or double-count solutions | [R010 pp. 4–5; R012 p. 14; D008] *(co-signed)* |
| DM15 | Blend the objective into a distance with a decaying weight; key the cycle test on the full state | Mix the objective into the pump's distance with a geometrically decaying weight, normalised by both norms; when the direction depends on a schedule, a revisit is a cycle only if (point, weight) repeats within a tolerance | [R006 p. 5] *(co-signed)* |
| DM16 | Skip, warm-start and order a sequence of related LPs | In bound tightening by min and max of each variable, skip bounds already attained by a seen feasible point, warm-start from the previous optimum, and take next the variable closest to a bound | [D026 pp. 6–7] *(co-signed; the text names it "Achterberg's heuristic", p. 7)* |
| DM17 | Lazy rows for correctness only; the repair heuristic's output used twice | Put only the rows an incomplete model needs for correctness into a lazy callback and leave performance cuts to the host solver; the repair heuristic's solution is both incumbent and seed of the next lazy rows | [D020 pp. 9–11] *(co-signed)* |
| DM18 | Necessary-condition pruning before separation | Derive from the current LP point a cheap necessary condition for violation (a sign test per row and bound factor; a projected check) and build only the candidates that pass | [D022 pp. 7–10; D023 pp. 9–13] *(co-signed)* |
| DM19 | Collect, then apply | Make an order-dependent reduction deterministic under parallelism by gathering candidates in parallel and applying them in one sequential pass | [R021 p. 52] *(co-signed)* |
| DM20 | Cheap pre-screens for pairwise comparisons | Rule out most pairs before the linear scan: bit signatures of supports, two-level hashing on support then normalised coefficients, lexicographic sorting of crowded bins | [D004 p. 154; R021 p. 45; D030 p. 5] |
| DM21 | Broadcast once, ship bound changes, checkpoint primitive nodes | In a distributed solver, broadcast the presolved instance once, send subproblems as bound-change lists, and checkpoint only the subtree roots held by the coordinator | [R014 pp. 6, 8–9] *(co-signed; Shinano first)* |
| DM22 | Lock test for safe rounding | Round a variable down only if it has no down-locks and up only if it has no up-locks, so that no row can be violated; pair the constructive rounding with an improvement step aimed at its bias | [R017 pp. 4–5] *(co-signed)* |

## 3. Experiment and evaluation protocols (EP)

| # | Technique | How to use | Cards |
|---|---|---|---|
| EP1 | Knock out from the full default, in the main solve only | Switch the feature off in the master solve and keep it on in sub-MIPs, whose heuristic decisions depend on it; where a change acts through model size, say that no clean benchmark exists | [R021 pp. 5, 21; D011 p. 29; D010 pp. 18–21] |
| EP2 | Shifted geometric means with the shift stated; time-outs at the limit, bias stated | Report ratios of shifted geometric means (thesis: 10 s and 100 nodes; Gurobi era: 1 s) and say that scoring time-outs at the limit favours the failing runs | [D004 pp. 333, 335–336; D010 p. 28; D030 p. 11; D021 p. 2] |
| EP3 | Weight single-class sets as pseudo-instances | In the summary total, count each mixed set per instance and each single-class set as a few pseudo-instances, so that no class dominates | [D004 p. 336] |
| EP4 | Brackets by the slower run; affected models by iteration counts | Group models by the slower run's time (≥ 0, 1, 10, 100, 1,000 s), give time-outs per side, counts ≥ 10 % faster and slower, shifted-geometric-mean ratios and the affected subset (iteration count changed); discuss ≥ 10 s; no affected figure where both sides time out | [R013 p. 27; D030 p. 11; R021 pp. 5–6; D022 p. 11; D023 p. 14] |
| EP5 | Control subsets | Read each claim also on the subset that removes its confound: both-solved for failures, equal path (same nodes and simplex iterations) for a pure per-node cost, all-optimal for time-limit censoring, same path across thread counts for hardware effects | [R004 pp. 17, 19; D004 pp. 339–340; D022 p. 13; D023 p. 17; D029 pp. 17, 20] |
| EP6 | Refuse conclusions on small affected sets; recheck before switching a default | Treat a few dozen affected models as anecdotal; about 200 are not enough for a 3–4 % effect; recheck a small-set gain for performance variability before changing the default | [R021 pp. 19, 22, 40, 42; D011 pp. 34–35; R013 p. 27] |
| EP7 | Interacting families: all off, one off, one on alone | For cuts or heuristics, run all off, each one off, each one on alone (and the default); compare the sum of single knock-outs with all off as a measure of overlap | [D004 pp. 125, 142; R017 pp. 6–7] |
| EP8 | Locate the cost | Split the time into basic, switching and component time and print the objects produced; or report the component's share of total time as a distribution per setting; for parallel runs, phase time against resource share *(co-signed)* | [R004 pp. 16–18; D022 p. 13; D023 pp. 17–18; R020 p. 13; D017 TR pp. 13–15] |
| EP9 | Measure by the job | Report heuristics at gap targets beside time to optimality; use the primal integral, normalised by the all-off run, for what primal heuristics are for | [D004 pp. 143–146; R017 pp. 5–7] |
| EP10 | Write the test-set rule | Select by an effort window on a reference solver, by a frozen older version plus a reference solver, or by other solvers, dropping and counting instances with disagreeing answers; purge with a deliberately weakened solver; print numbered suitability criteria with their exclusion counts | [R003 p. 24; R004 p. 16; D004 pp. 333–334; D010 p. 21; R012 p. 13; R005 p. 3; D021 pp. 25–26, 31–36] |
| EP11 | Sweep and read points | Plot each setting as a point (mean nodes, mean time) and name the knee, not the fewest-node setting; to diagnose a fixed threshold, measure the quantity it thresholds across the set | [R002 pp. 11–13, 20] |
| EP12 | Oracle agreement quotients | At every node solve all candidates and record the score quotient and the position quotient of the chosen one, over the whole tree and the top ten levels | [R001 pp. 13–14] *(co-signed)* |
| EP13 | Formulation factorials | Write formulation variants that keep the optimum and the LP bound as a factorial, collapse variants presolve maps to the same model, report sizes after preprocessing, and use the slowest-to-fastest ratio as a robustness number | [R011 pp. 5–8] *(co-signed)* |
| EP14 | Two codes, one algorithm | Implement the same algorithm in a second, independent solver and compare directions and brackets, not absolute numbers | [D023 pp. 21–22; D022 p. 14; D011 pp. 29–37] *(co-signed)* |
| EP15 | Scalability grids with a deliberate worst-case family | Benchmark over a grid of size and density with many generated instances per point, keep easy points for correctness, add one family the method is not built for, and state limits as unsolved counts per point | [D020 pp. 12–18] *(co-signed)* |
| EP16 | Exact-arithmetic checks | Recheck floating-point LP bases in rational arithmetic, check returned solutions against the original file in exact arithmetic, make primal values reliable by an exact LP re-solve with the integers fixed, and exclude inconsistent answers across solvers | [R005 pp. 5–6; D013 pp. 10–12; D021 pp. 22–23] *(co-signed)* |
| EP17 | Detector against ground truth before speed | Before any timing, run the detector on instances whose structure is known, with and without presolve, and name the cause of each failure | [D011 pp. 21–23; R013 pp. 17–19] *(co-signed)* |
| EP18 | Repeat nondeterministic runs; count instances solved in every run | Run each nondeterministic configuration several times (five in the parallel study), print every run, and summarise with the number of instances solved in all runs beside the speed-up | [D029 p. 20; R018 pp. 19–21] *(co-signed; Shinano first)* |
| EP19 | Fair yardstick | Give the baseline equal gap tolerances and the same LP solver, switch off a component only one code uses heavily, pick the strongest of several baselines, compare only the MIP part when you borrow the rival's LP solver | [R001 p. 11; R003 p. 24; R004 p. 16; D004 pp. 313, 317, 334, 391; R011 p. 5] |
| EP20 | Look at the hardest bracket separately | Report the ≥ 1,000 s bracket on its own: a 4 % average can hide 25 % on the hardest models | [R021 p. 24] *(co-signed)* |
| EP21 | Easy and hard parts judged by different measures | Split instances into easy (solved by at least one setting) and hard (solved by none) and judge the hard part by closed gaps rather than time-outs | [D011 pp. 29, 31, 33] *(co-signed)* |

## 4. Writing moves (WM)

| # | Technique | How to use | Cards |
|---|---|---|---|
| WM1 | Fix a percentage's meaning once and keep one table layout | State once that positive values are worse (+100 % = twice as long when the feature is off) and use the same summary layout in every chapter | [D004 pp. 16, 83] |
| WM2 | The loss beside the gain | Put the time loss next to the node gain in the abstract; when it is not there, give it in the body with numbers | [R004 p. 2; D022 p. 11; D023 pp. 15–16] |
| WM3 | Hedge where the counts are small, trust where they are large | Put the hedge in the paragraph of the result it qualifies when the affected counts are small, and say why a large set can be trusted | [D011 pp. 34–35; R013 p. 27] |
| WM4 | Label claims without a table | Mark explanations as "a possible explanation" and unmeasured claims as such | [D004 pp. 69, 88, 93, 95, 142, 154, 191] |
| WM5 | Print refuted impressions, losing defaults and losing trajectories | Put a refuted expectation or a losing default next to the table that refutes it, and include a losing instance among the plotted trajectories | [D004 pp. 96, 114, 177; R006 pp. 7–9] |
| WM6 | Each rule as a diff of the previous one | Present the new rule against its baseline as a feature-difference table and each algorithm box as a diff of the previous one | [R001 pp. 6, 9] *(co-signed)* |
| WM7 | Credits per component; independent discovery named | Credit joint chapters and student contributions in the text, and name independent discoveries of the same idea | [D004 pp. 75, 115, 132, 179, 199] |
| WM8 | State the exact model, build and versions; post the model files | Give the exact formulation, the code version or commit and the library versions, and post the model files with the report | [R011 pp. 5, 8; D023 p. 13; D004 pp. 333, 391–392] |
| WM9 | Reconcile before release (neutral lesson from the reading) | Before release, reconcile tables, text and abstract, and print the numbers a verdict rests on next to the verdict | 08 §7.4 (house rule: no work is named) |
