### R001 · Branching on History Information (ZIB-Report 02-32, Zuse Institute Berlin 2002, no DOI; urn:nbn:de:0297-zib-6990)

**Read level**: full. I read all 16 file pages, references included. Figure 5 (file pp. 14–15, scatter plots of predictions against realized gains) is garbled in the text layer, so it is read only from its caption and from the discussion on p. 14.

**Role**: core · **Coauthors**: Thorsten Koch, Alexander Martin. The cover (p. 1) names only Achterberg and Koch; the title page (p. 2) adds Martin (TU Darmstadt). · **Position in trajectory**:
- This is the earliest work in the batch, dated 7 October 2002 (p. 2).
- It is implemented in SIP, "a state-of-the-art MIP solver" (abstract, p. 2), with CPLEX as the embedded LP solver (p. 11).
- It already defines "unreliable" variables, with a threshold ηrel (p. 9), the idea that R002 turns into reliability branching. R002 does not cite this report (R002 D6).

- **D1 Problem & entry**:
  - The entry is the branching step of LP-based branch-and-bound (p. 3).
  - All rules are framed as cheap estimates of full strong branching, whose computation times "are prohibitive" (p. 5).
  - The concrete gap is the cold start of pseudocosts: at first there is no information and the scores are almost identical, just "where the branching decisions are usually the most crucial" (p. 6).
  - Hybrid pseudocost branching [LS99] answers this only for uninitialized pseudocosts (pp. 6–7).
  - The problem is put as a prediction task: decide "the quantities for the prediction and how to initialize and update them" (p. 7).
  - Not in the text: any learning experiment. SKILL.md (H1) traces the rule, through later talks, to learners inside SIP. This report presents it only as "a modification of pseudocost branching" (abstract, p. 2), and a search of the file for "learn" finds nothing.

- **D2 Core idea & algorithm design**: history values (7) replace pseudocosts (p. 8). For each variable and direction, the value comes from the first case that applies:
  1. real branchings exist: the pseudocost-based value, times a dynamic scaling factor;
  2. only strong-branching values exist: the strong-branching-based value, times its own scaling factor;
  3. neither: the class value, else the global value (pp. 8–9).

  Table 1 (p. 9) lists the changes against hybrid pseudocost branching:
  - three hierarchy levels (variable, class, global) instead of two;
  - infeasible children, and children where node preprocessing or strengthening cuts were applied, do not update the history (p. 9);
  - strong-branching values are stored apart from the values of solved subproblems and are rescaled dynamically;
  - strong branching is applied to "unreliable" entries (η⁺ + η̃⁺ < ηrel), not only to uninitialized ones (p. 9);
  - candidates are evaluated in decreasing history score, uninitialized ones first, instead of by fractionality;
  - the number of simplex iterations, the number of initializations per node and ηrel are adjusted dynamically, from the ratio of branching time to LP time and from node depth (pp. 9–10).

  What stays the same: the score function (3) with factor µ (p. 4), branching on variables (p. 4), and the λ-stop of the candidate loop, which now also has a minimum number of candidates (Algorithm 3.1, p. 10).

  Why: a large history value "is on average a more reliable indication of a large gain" than a large pseudocost (p. 14).

- **D3 Problem class & data model**:
  - The problem is a general MIP, min cᵀx, Ax ≤ b, x ∈ Z^I × R^(N\I) (p. 2).
  - Only variables are branched on; more complex branching is left to special cases (p. 4).
  - Variable classes are formed from the variable names in the model. If that fails, they come from objective coefficient, bounds and matrix entries. A link to ZIMPL is planned so that classes "come out naturally" (p. 8 fn. 2).
  - ηrel depends on the number of integer variables |I| (p. 9).
  - Test structures: MIPLIB 3.0 plus six randomly generated arborescence-flow instances from [Pfe00] (p. 11). This aflow family is 6 of the 22 instances, and the improvement is "significant" on it and on gesa2_o, qiu and rout (p. 13), so one generated family weighs heavily in the set.
  - No correctness argument is needed: the rule only orders candidates.

- **D4 Algorithm & implementation design**: proofs: n/a. The design devices:
  - **Scaling factor.** Limited-iteration strong branching underestimates the gain, so a correction is needed (p. 8). The factor is α = g/p, a ratio of exponentially weighted sums of realized gains g and predictions p. The forgetting weight τ is capped at τmax = 0.995 (p. 8 fn. 1; the formula for τ is garbled in the text layer). A ratio of averages is chosen over an average of ratios, because in the latter a quotient with a near-zero denominator "could easily dominate" (p. 8 fn. 1).
  - **Excluding contaminated observations.** Observations from infeasible children, and from children changed by node preprocessing or strengthening cuts, are not used (p. 9).
  - **Effort control.** Strong-branching effort is raised at the upper nodes, and the parameters follow the measured ratio of branching time to LP-solving time (pp. 9–10).
  - **Implementation.** SIP, with CPLEX as the LP solver (p. 11).

- **D5 Computational evaluation**: four layers, from the claim down to the mechanism.
  1. **Performance** (Table 2, p. 11).
     - Setup: SIP hybrid pseudocost, SIP history and CPLEX 7.5. Nodes and seconds are given per instance, with arithmetic totals; time-outs at 3,600 s are marked ">". One Alpha 21264 (750 MHz, 2 GB). CPLEX's gap tolerances are set to SIP's: absolute 10⁻¹⁰, relative 0 (p. 11).
     - Totals: 12,966.7 s (pseudocost), 3,533.5 s (history), 12,342.1 s (CPLEX).
     - Test-set rule (p. 10): MIPLIB 3.0 instances on which CPLEX 7.5 needs more than 1,000 nodes *and which SIP with history branching solves within 3,600 s*. Every excluded instance is listed by name (fn. 3–4). The stated mitigation: CPLEX solves none of the excluded hard instances within an hour (p. 10).
     - My recount of Table 2: history uses fewer nodes than pseudocost on 19 of 22 instances and less time on 15 of 22. It is slower on bell3a, bell5, blend2, pk1, rgn, stein27 and stein45; the text says only "For nearly all instances" (p. 11).
     - Four instances (rout, gesa2_o, aflow.40.50, aflow.30.50) make up 10,006.8 s of the baseline's 12,966.7 s.
     - My computed unshifted geometric means are 90.7 s, 55.1 s and 80.2 s. That is a factor of 1.65 between the two SIP rules, against 3.67 for the totals.
  2. **Isolation** (Table 3, p. 12).
     - Setup: cuts, heuristics, node selection and branching interact (p. 11). So the optimal solution is supplied in advance, root cuts are generated once by SIP and then switched off, and only nodes are counted. Five rules are run: random, most infeasible, full strong, pseudocost and history (p. 12).
     - Full strong branching needs by far the fewest nodes except on bell5 and misc07. History beats pseudocost except on bell3a and bell5 (p. 13).
     - Most infeasible does worse than random in the table: > 31,298,181 against > 13,455,872 nodes, with 9 against 6 instances marked ">". The text does not comment on this (p. 12).
  3. **Oracle agreement** (Table 4, p. 13).
     - Setup: at every node all candidates are solved. For the chosen candidate, the score quotient ξ (from the text, s_selected/s_max; (8) is garbled) and the position quotient ρ are recorded. (9) is also garbled; it reads as 1 − (pos − 1)/(|C| − 1). Both are set to 1.0 when there is one candidate or all candidates tie (pp. 13–14).
     - Whole tree: pseudocost ξ 0.497, ρ 0.764; history ξ 0.585, ρ 0.795.
     - Top 10 depth levels: pseudocost 0.526 / 0.746; history 0.784 / 0.900 (p. 13).
     - Large node differences go with large differences in the top-level quotients (p. 14).
  4. **Predictor calibration** (Figure 5, pp. 14–15): predicted against realized gains on aflow.40.50, with average lines.

  Not reported: variability (seeds or reruns), and an ablation of the six Table 1 changes.

- **D6 Positioning**:
  - The rule is "a modification of pseudocost branching", today's state of the art (abstract, p. 2).
  - Credits: pseudocosts to [BGG+71] (p. 5), hybrid pseudocost to [LS99] (p. 6), and the surveys [LP79] and [LS99] (p. 4).
  - Hybrid pseudocost is the only SIP baseline, because it "almost always" beats the standard version [LS99, Mar98, CPL01] (p. 7).
  - Strong branching is "invented by [CPL01] (see also [ABCC95])" (p. 5). Yet the reference list dates [ABCC95] to March 1995 and [CPL01], the CPLEX 7.5 manual, to 2001 (p. 15).
  - Earlier rules are re-expressed, as estimates of full strong branching, rather than criticized.
  - There are 13 references (pp. 15–16).

- **D7 Writing & rhetoric**:
  - The abstract leads with the claim: "computational results that show the superiority" (p. 2).
  - Each rule is an algorithm box written as a diff of the one before ("describes the changes to Algorithm 2.1", p. 6).

- **D8 Contribution & limits**:
  - The contribution is an algorithmic rule plus an empirical study in one solver (p. 15).
  - The conclusion credits three causes jointly (gain prediction, dynamic parameter adjustment, and more strong branching high in the tree) without separating them (p. 15).
  - There is no limitations section. The only future work is in a footnote: link SIP to ZIMPL for variable classes (p. 8 fn. 2).
  - This card's own reading adds three limits: the test-set rule depends on the method under study (p. 10), four instances dominate the totals (p. 11), and every instance is a single run.

**Method links**:
- Method 3 ⚠ variant: the 2002 rule is a bundle of six changes plus adaptive parameters (Table 1, p. 9; pp. 8–10). It is evaluated as a whole against one baseline: no parameter family, no sweep. This is the "before" state that Method 3's evidence cites; R002 cuts it down to one reliability parameter (R002 p. 8).
- Method 2 ✅ evidence: nodes and time appear side by side for every instance (Table 2, p. 11), and strong-branching effort is tied to the ratio of branching time to LP time and to depth (pp. 9–10). Variant detail: this is a relative-time budget, not an iteration unit.
- Method 5 ✗ contradiction (2002 era): the test set is filtered by the code under study, "SIP using history branching solves in less than 3600 CPU seconds" (p. 10). The CPLEX check on the excluded instances partly offsets this (p. 10). In 2004, CPLEX alone selects (R002 p. 9).
- Method 4 ⚠ variant: a pairwise comparison of one rule against another, not a knock-out from a default. It is reported as arithmetic totals with time-outs at the limit (p. 11): no means, no brackets, and four instances dominate the totals (D5).
- Method 1 ⚠ variant (loose): variable classes are grouped by model names first (p. 8 fn. 2), against Method 1's rule of "matrix, not names". The purpose differs: aggregating history, not gating a default.
- Heuristics (not counted as methods):
  - H2 ✅: score and position quotients (pp. 13–14).
  - H3 ✅: gap tolerances matched to CPLEX (p. 11).
  - H10 ⚠: the time losses are visible in Table 2 but not named (p. 11).
  - H1: the origin is not visible in the text (D1).
  - Warning sign 3 ✅, in the data only: most infeasible does worse than random (Table 3, p. 12).
- New-pattern candidates:
  - "state and justify the control conditions": the isolation run (pp. 11–12); R002 argues for the opposite control (R002 p. 9).
  - "clean the samples of an online estimator" (p. 8 fn. 1; p. 9).
  - "random rule as floor baseline" (Table 3, p. 12; R002 Table 1, p. 17).

**Transferable techniques**:
- (D5) **Isolation run for a search rule**: supply the optimal solution as the cutoff, generate root cuts once and freeze them, and switch off all further cut generation. Then compare rules by node counts, with random as the floor and full strong branching as the ceiling (pp. 11–12).
- (D5) **Oracle agreement**: at every node, solve the child LPs of all candidates. Record the score quotient s_selected/s_max and the position quotient 1 − (pos − 1)/(|C| − 1), and set both to 1.0 when there is one candidate or all scores tie. Report them over the whole tree and over the top 10 depth levels, where decisions matter most (pp. 13–14, Table 4).
- (D5) **Calibration plot**: for one instance, plot each predictor's value against the realized gain, with average lines, to show which predictor is monotone and sharp (p. 14, Figure 5).
- (D4) **Correcting a biased cheap estimate**: correct limited-iteration strong-branching gains with α = Σgain / Σprediction under exponential forgetting (τmax = 0.995). Use a ratio of sums, not a mean of ratios, so that near-zero predictions cannot dominate (p. 8 fn. 1).
- (D4) **Clean observations**: keep contaminated observations out of a learned per-variable statistic. That means infeasible children, and children whose LP was changed by node preprocessing or local cuts (p. 9).
- (D5) **Fair comparison**: set the reference solver's gap tolerances to your own (CPLEX absolute mipgap 10⁻¹⁰, relative 0). List every excluded instance by name, under the rule that excluded it (pp. 10–11).
- (D7) **Presenting the rule**: write the new rule against its baseline as a feature-difference table (Table 1, p. 9), and make each algorithm box a diff of the previous one (p. 6).

**Quotes**:
- "In updating the history values, we ignore branching results, where one of the subproblems is infeasible or where node preprocessing or strengthening cuts where applied at the child nodes, because this would lead to unfair large gain values in comparison to other nodes." (p. 9)
- "A problem with the numbers given in Table 2 are the complex interrelations between cutting plane generation, primal heuristics, node selection, and branching variable selection." (p. 11)

### R002 · Branching rules revisited (ZIB-Report 04-13, Zuse Institute Berlin 2004, no DOI; urn:nbn:de:0297-zib-7886)

**Read level**: full.
- I read the main text and the references (file pp. 1–16) in full.
- I read through the summary Tables 1–4 (pp. 17–20) and all per-instance Tables 5–44 (pp. 21–60), and cross-checked them against Tables 1–3 with a script.
- Figures 1–4 (pp. 8, 11, 14) are read from their extracted labels and from the text. Figure 5 (p. 15, two tree drawings) has no text layer beyond its caption.
- The bold "winner" marks of Tables 2–3 (p. 10) are lost in the text layer.

**Role**: core · **Coauthors**: Thorsten Koch, Alexander Martin · **Position in trajectory**:
- Dated 5 May 2004 (p. 2).
- Still implemented in SIP, with CPLEX 9.0 as the LP solver and CPXstrongbranch() for strong branching (p. 9).
- The report version of the ORL 2005 article (D001, not read here).
- It generalizes R001's "unreliable" idea (R001 p. 9), but does not cite R001.

- **D1 Problem & entry**:
  - Popular branching rules are read as fast estimates of full strong branching (p. 6).
  - Two weaknesses are named:
    - Pseudocost branching takes the decisions high in the tree, where "the decisions have the largest impact", with pseudocost values that "aren't useful yet" (p. 6).
    - Hybrid strong/pseudocost branching uses strong branching only up to a fixed depth d (p. 6). Pseudocost branching with strong-branching initialization [10] uses it only on uninitialized pseudocosts (p. 7).
  - The problem is posed as a generalization that "contains many of the known branching rules as special cases" (pp. 2–3).

- **D2 Core idea & algorithm design**:
  - **The rule (Algorithm 3, p. 7).** Reliability branching applies strong branching to every candidate whose pseudocosts are unreliable, min{η⁻, η⁺} < ηrel, with at most γ dual simplex iterations per child. The strong-branching gains update the pseudocosts and the current score. The loop stops after λ score updates without a new maximum.
  - **Against strong-branching initialization:** the threshold ηrel replaces 1 (p. 7).
  - **Against the hybrid rule:** a per-variable reliability test replaces the fixed depth (pp. 6–7).
  - **What stays the same:** the score function (3) with µ = 1/6 (p. 4), candidates ordered by pseudocost score, the look-ahead λ, and the iteration limit γ = 2γ̄ (p. 6).
  - **Against R001's history branching** (my comparison of the two texts):
    - Dropped: the class and global hierarchy, the separate strong-branching history with its scaling factors, and the dynamic parameter control (R001 pp. 8–10).
    - Kept: the reliability idea (R001 p. 9), and the exclusion of infeasible children from the pseudocost sums (p. 5). In R001's baseline an infeasible child still updated the pseudocosts (R001 p. 6).
  - *Inferred*: the scaling factors became unnecessary. R001 needed them because limited-iteration gains underestimate (R001 p. 8). Here γ = 2γ̄ "only protects from unexpected long simplex runs", and "on average the candidate LPs will be solved to optimality" (p. 6).

- **D3 Problem class & data model**:
  - General MIP (1) (p. 2), branching on variables only (p. 4). An infeasible child needs "special treatment", which the text does not specify (p. 4).
  - Uninitialized pseudocosts are set to the average of the initialized ones, or to 1 when none is initialized (p. 5).
  - The environment is cut-and-branch: default SIP with cuts at the root only, chosen because there "the influence of the branching strategy is emphasized best" (p. 9).
  - Test set: 24 instances from MIPLIB 2003 [1] (the authors' own library) and from Mittelmann's benchmark collection [14]. They were selected because CPLEX 9.0 needs at least 5,000 nodes and at most one hour on them (p. 9).
  - The text does not say which instance comes from which source. By name, the families cluster: four ran*, three mas*, three neos* and two swath* (Table 2, p. 18). The families are not weighted.

- **D4 Algorithm & implementation design**: proofs: n/a. The structural device is that the rules are parameter settings of one family (Figure 1 and text, p. 8):
  - d = 0 or ηrel = 0 gives pseudocost branching.
  - ηrel = 1 gives strong-branching initialization.
  - d = ηrel = ∞ gives strong branching.
  - λ = ∞ turns strong branching into full strong branching.
  - "ηrel ∈ [4, 8]" gives the best-performing rules (p. 8).

  Implementation details:
  - The look-ahead counter resets at each new best candidate. Because candidates are ordered by pseudocost, λ = 4 usually finds the overall best one (p. 12).
  - Strong-branching children that are infeasible or cut off are not generated and not counted as nodes. For full strong branching this lowers the node counts by up to a factor of 1/2 (p. 10 fn. 3).
  - Six "dynamic reliability" settings (ηrel = 4–16 up to 4–128) appear only in the per-instance Tables 14, 15 and 21–24 (pp. 30–31, 37–40). The text never defines how ηrel moves within the range.

- **D5 Computational evaluation**:
  - **Setup.**
    - Hardware: one 833 MHz Alpha 21264 (4 MB cache, 2 GB RAM), with a 3,600 s time limit (p. 9).
    - Reference run: CPLEX 9.0 with SIP's gap tolerances (absolute 10⁻¹⁰, relative 0), run on SIP's preprocessed and cut models ("CPLEX/SIP cuts"). Both codes then do pure branch-and-bound on the same problems (pp. 9–10). The stated purpose is to verify that SIP's branch-and-bound environment "is state-of-the-art" (p. 9).
    - Control: the optimal solution is deliberately not supplied, because finding feasible solutions fast is a desirable property of a branching rule. Footnote 1 lists four ways an early incumbent changes a run (p. 9):
      1. cutoffs come earlier;
      2. the dual simplex stops earlier, in strong branching too;
      3. node selection moves from depth-first towards best-first, which makes reliability branching behave more like the hybrid rule;
      4. diving changes, and diving updates the pseudocosts.
    - Grid (Table 1, p. 17): random, most infeasible, pseudocost and full strong branching. Then, for each λ ∈ {4, 8, ∞}: hybrid with d ∈ {5, 10, 15, 20}, reliability with ηrel ∈ {1, 4, 8, 16, 32}, and strong branching. Then CPLEX. That makes 34 SIP settings. With the 6 dynamic settings that appear only in the appendix, there are 40 per-instance tables of 24 instances each (pp. 21–60).
    - Measures: totals and plain (unshifted) geometric means of nodes, time and strong-branching calls, plus a count of fails. The conclusions rest on the geometric mean, which "common sense" makes "a fair criterion" (p. 10). Time-outs enter it at 3,600 s (Table 3, p. 19).
    - Figures: geometric-mean nodes against geometric-mean time for every setting (Figure 2, p. 11), and nodes and time against the number of strong-branching evaluations on a log axis (Figures 3–4, p. 14).
  - **Results** (Table 1, p. 17; geometric-mean times):

    - (16, 4) has the lowest total time: 10,782.6 s against 11,132.7 s.

    - Reliability (1, 4), which is the rule of [10], ties CPLEX (216.4 against 215.8 s). This is what the "state-of-the-art" check amounts to.
  - **Variability.** Every setting is a single run; there are no seeds. One repeat exists by accident:
    - Table 7 (p. 23) is the full-strong-branching run without a time limit (p. 12).
    - On the 22 instances solved within the limit, its node counts are identical to Table 2.
    - Its times differ from Table 3 (p. 19) by −3.2 % to +7.1 %. The largest gap is mas74: 3,087.1 s against 3,306.4 s. 8 of the 22 instances differ by more than 2 % (my script comparison).
    - All other appendix tables reproduce Table 3 exactly.
  - **Other checks by script** (pp. 21–60):
    - All solved runs agree on the optimum, except for spreads of 4.8·10⁻⁵ on qiu (32 runs) and 3·10⁻⁵ on mas284.
    - The number of root cuts for prod1 varies with the strong-branching setting: 133 without strong branching, 143 for full strong branching, and 167 / 163 / 156 for λ = 4 / 8 / ∞ (e.g. pp. 21, 23, 25, 32, 41). So the cut-and-branch roots are not identical across rules. The text does not comment on this.
  - **Failures** are reported per setting ("fails", p. 17) and per instance (pp. 21–60). The instances on which the winning rule is slow are not discussed: "We did not not base our conclusions on performances of single instances" (p. 10).

- **D6 Positioning**:
  - The rule is a "new generalization" of today's strong and pseudocost branching (abstract, p. 2). Earlier rules become its special cases (p. 8): positioning by re-expression, not by criticism.
  - Credits: pseudocosts to [3] (Benichou et al. 1971; p. 5), strong-branching initialization to [10] (Linderoth and Savelsbergh; p. 7), and the hybrid rule as "available for example in Lindo" (p. 6).

**Transferable techniques**:
- (D4) **One parameter for all rivals**: before running anything, express the rival rules as settings of one new parameter, and draw the map of which value gives which old rule (Figure 1, p. 8).
- (D5) **Grid and effort plots**: run the whole grid, and plot each setting as one labelled point (geometric-mean nodes, geometric-mean time) (Figure 2, p. 11). Then plot nodes and time against the number of calls to the expensive operation, on a log axis (Figures 3–4, p. 14).
- (D5) **Choosing the test set**: select instances by a reference solver's behaviour, never by the method under test. Here: CPLEX 9.0 needing ≥ 5,000 nodes and ≤ 1 h (p. 9).
- (D5) **Comparing only the tree search**: to compare it against a commercial code, feed the commercial code your own preprocessing and root cuts, and match the gap tolerances ("CPLEX/SIP cuts", pp. 9–10).
- (D5) **The incumbent decision**: write down why you did or did not supply the optimal solution. List the ways an early incumbent changes node counts and time per node (p. 9 fn. 1).
- (D4) **Capping strong-branching LPs**: cap them at twice the running average of simplex iterations per LP. This guards against long runs; it is not meant to truncate (p. 6).
- (D5) **Diagnosing a fixed threshold**: explain why a fixed threshold fails by measuring the quantity it thresholds across the test set (average node depth 7.3 to 134.6, against d ≤ 20), and by drawing one balanced and one path-like tree (Table 4, p. 20; pp. 11–12; Figure 5).
- (D5) **Reporting**: give a "fails" column beside the totals and geometric means. State how infeasible or cut-off strong-branching children are counted (Table 1, p. 17; p. 10 fn. 3).
