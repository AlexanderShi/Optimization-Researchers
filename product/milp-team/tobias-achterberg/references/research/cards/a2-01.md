### D007 · Constraint Integer Programming: A New Approach to Integrate CP and MIP (CPAIOR 2008, LNCS 5015: 6–20, DOI 10.1007/978-3-540-68155-7_4)
**Read**: abstract (Springer chapter page, new in this batch) · **Role**: core (no full text of this version) · **Coauthors**: Timo Berthold, Thorsten Koch, Kati Wolter · **Version**: the Springer abstract is word for word the ZIB-Report 08-01 abstract (R009 p. 2); R009 was read in full (card c02).
- **D1 Problem & entry**: combine the CP and MIP methodologies. Constraint integer programming (CIP) generalizes MIP by admitting general constraints as in CP (abstract).
- **D2 Key idea**: the CIP framework SCIP, which also integrates SAT techniques, applies the MIP machinery to the linear part and CP techniques to the non-linear constraints (abstract).
- **D5 Evaluation**: two tasks (abstract):
  - pure MIPs, where SCIP is called almost competitive with commercial MIP solvers;
  - chip design verification, with highly non-linear constraint types.
  - R009's card (c02) reads the first claim against the tables: it rests on solved counts, while CPLEX is at least 10 % faster on 27 of 36 instances (a Method 2 contradiction there). The abstract alone cannot show this.
- **D8 Contribution**: a concept (CIP), software (SCIP in source code, free for non-commercial use) and an application (chip verification); no limits stated (abstract).

**Method links**:
- Method 6 ✅ evidence (abstract level): CP's general constraints and SAT techniques are brought into a MIP framework (abstract). The data-structure level and the per-habit tests are not visible in the abstract; see R009.
- new-pattern candidate: **linearize only what stays small, propagate the rest** (existing candidate, R009). The abstract states the split: MIP machinery for the linear part, CP techniques for the non-linear constraints. Same paper as R009, so not a new occurrence.

**Transferable**: for a model with a large linear core and a few constraint types that linearize badly, keep the LP relaxation for the linear part and handle the rest by propagation in the same search (abstract).

**Quotes**:
- "CIP is a generalization of MIP that supports the notion of general constraints as in CP." (abstract)
- "The CIP approach is very effective here: it can apply the full sophisticated MIP machinery to the linear part of the problem, while dealing with the non-linear constraints by employing constraint programming techniques." (abstract)

### D014 · ParaSCIP: A Parallel Extension of SCIP (Competence in High Performance Computing 2010, Springer 2012: 135–148, DOI 10.1007/978-3-642-24025-6_12)
**Read**: abstract (Springer chapter page, new in this batch) · **Role**: core · **Coauthors**: Yuji Shinano (first author), Timo Berthold, Stefan Heinz, Thorsten Koch · **Version**: the Springer abstract is the ZIB-Report 10-27 abstract (R014 p. 2), read in full (card c04). - **D1 Problem & entry**: parallelize the MIP solver SCIP on a distributed-memory machine (abstract).

**Quotes**:

### D016 · Stronger Inference through Implied Literals from Conflicts and Knapsack Covers (CPAIOR 2013, LNCS 7874: 1–11, DOI 10.1007/978-3-642-38171-3_1)
**Read**: abstract · **Role**: core · **Coauthors**: Ashish Sabharwal, Horst Samulowitz · **Position in trajectory**: CPLEX years. There is no report version on disk, so this abstract is first-hand evidence from a period SKILL.md's Honest Boundary calls almost empty.
- **D1 Problem & entry**: implied-literal detection helps SAT solvers on some problem classes, in particular when applied dynamically to learned clauses (abstract).
- **D2 Key idea**: carry implied literals over to MIP conflict constraints. This strengthens inference from the clique and implication tables MIP solvers already keep. Then extend the technique to knapsack covers, with an efficient implementation (abstract).
- **D5 Evaluation**: inside the MIP engine of IBM ILOG CPLEX 12.5; better performance, especially on harder instances. Test set, measure and what makes an instance harder are not stated (abstract).
- **D8 Contribution**: an inference technique implemented in a commercial solver; no limits stated (abstract).

**Method links**:
- Method 6 ✅ evidence (clear at abstract level): a SAT technique moved to MIP through data structures MIP solvers already hold (clique and implication tables), then tested in the production solver (abstract).

**Transferable**: before porting a technique from another solver field, find the data structures your solver already maintains that can carry it (here clique and implication tables), then measure it in the full solver (abstract).

**Quotes**:
- "This results in stronger inference from clique tables and implication tables already commonly maintained by MIP solvers." (abstract)
- "Our experiments show that implied literals, in particular through stronger inference from knapsack covers, improve the performance of the MIP engine of IBM ILOG CPLEX Optimization Studio 12.5, especially on harder instances." (abstract)
