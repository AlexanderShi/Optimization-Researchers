- **D1 Problem and entry point**: three entries meet.
  1. A personal one: he wanted a topic that joined his two subjects, which in 2002 led to the idea of integrating integer and constraint programming. That integration "was way beyond the scope of SIP", so he started a new code at the end of 2002 (p. 9).
  2. A platform one: the best MIP codes are proprietary, which makes it hard for academics "to evaluate new ideas by computations within a state-of-the-art environment". SCIP is offered as free software that is "(almost) comparable" to them (p. 73).
  3. An application one: in chip property checking, SAT on the gate level fails on arithmetic data paths, while word-level IP and CP solvers do not learn conflict clauses and fail on control logic (p. 201). Verification takes 60–80 % of SoC design expenses (p. 199).

  The problem is stated as a model class. A CIP is a finite set of arbitrary constraints that become linear in the continuous variables once the integer variables are fixed (Def. 1.6, p. 27). This class generalises CP(FD) and MIP (Prop. 1.7, p. 28). Most Part II chapters enter through either a common rule that nobody had measured or a SAT technique that MIP lacked:
  - most infeasible branching is "not much better than selecting the variable randomly" (p. 76);
  - restarts are a key SAT ingredient that MIP solvers had not used (p. 174);
  - MIP solvers "simply discard infeasible and bound-exceeding subproblems" (p. 179).
  - Transferable: enter a field through a model class defined by the structural condition that keeps the core algorithm valid (here, linearity after the integers are fixed, Def. 1.6, p. 27), then prove that the old classes are special cases (Prop. 1.7, p. 28).
- **D2 Core idea and algorithm design**:
  - Integration "on a very low level": all CP, SAT and MIP algorithms work on one search tree and share statistics and LP duals (p. 16). They are organised around constraint handlers, which check, presolve, propagate, relax and branch for their own class (pp. 37–38).
  - In MIP, the recurring design move is to write the incumbents as settings of one new rule. Reliability branching contains pseudocost branching (η_rel = 0), pseudocost branching with strong-branching initialisation (η_rel = 1) and strong branching (η_rel → ∞) (pp. 79–80; Fig. 5.2, p. 82; p. 83).
  - Hybrid reliability/inference branching reduces to reliability branching when the inference, conflict (VSIDS) and cutoff weights are zero. Each score is first divided by its current average and mapped with g(x) = x/(x+1) (p. 81).
  - The product score max{q−, ε}·max{q+, ε}, with ε = 10⁻⁶, replaces the weighted sum (p. 76).
  - Conflict analysis changes the SAT method where MIP differs. The LP as a whole causes the infeasibility, so local bounds are relaxed greedily, using the dual ray (or the dual solution for bound-exceeding LPs), while the infeasibility proof stays valid. The bounds that remain are the conflict vertex's predecessors (Alg. 11.1, p. 189; Alg. 11.2, p. 191).
  - Non-binary bound changes give bound-disjunction constraints (11.14), which are used only for propagation. Alternatively, those bound changes are moved to the conflict side so that the conflict stays a set-covering constraint (pp. 191–192).
  - What stays unchanged: LP-based branch-and-bound and most of SIP's algorithms (pp. 20, 37).
  - Chip verification: each register-transfer operator gets its own constraint handler, with an LP relaxation, bit- and word-level propagation, and reverse propagation for conflict analysis (pp. 202, 209). Operators whose LP relaxation would be huge are handled by CP propagation only; a 64-bit shift-left would need 2,145 auxiliary variables and 6,306 constraints (p. 19).
  - Transferable: to combine heterogeneous scores, divide each by its current average over all candidates, map it with x/(x+1), and only then weight it (p. 81).
  - Transferable: to bring a SAT conflict graph to an LP-based solver, seed it with the bounds that the LP infeasibility proof uses. Relax every local bound while yᵀb + rᵀû stays negative (Alg. 11.1, p. 189).
- **D3 Problem class and data model**:
  - Model form: MILP min cᵀx subject to Ax ≤ b, with bounds kept outside the matrix and with binary, general integer and continuous index sets (pp. 25, 74). Constraint handlers specialise linear constraints to knapsack, set partitioning/packing/covering and variable-bound constraints (contents, p. 12). The infrastructure keeps an implication graph and a clique table (pp. 81, 124).
  - MIP data: ten public sets with 244 instances (Table A.1, p. 334):
    - three mixed collections: miplib (30 instances; MIPLIB 2003, ref. [6]), coral (38) and milp (37);
    - seven single-class sets: enlight (a combinatorial game), alu (infeasible chip verification), fctp, acc (sports scheduling), fc, arcset and mik.
  - Results are read through class structure. Enlight, alu and acc have objectives that are unimportant, artificial or missing. This is used to explain why inference branching, propagation and inference child selection win on them and why cuts lose (pp. 84, 96, 113, 126).
  - Stated correctness conditions:
    - conflict constraints on continuous variables are relaxed to non-strict bounds, because strict inequalities cannot be handled with floating point and tolerances (p. 191);
    - dropping a non-binary branching bound from a conflict set leaves a conflict that is only locally valid (p. 192);
    - local cuts must be removed from the LP, or the conflict marked as locally valid (p. 187, footnote).
  - Chip data:
    - register variables have domains {0, …, 2^β − 1}, and a property is valid if and only if the CSP is infeasible (p. 203);
    - unlike bounded model checking from the reset state, the initial state is left free, so unreachable errors may be reported (p. 201);
    - the test circuits ALU, PipeAdder, PipeMult, Biquad and Multiplier come from OneSpin, with 5–40-bit registers (2–14 bits for Multiplier) (p. 337).
  - Transferable: when a result splits by test set, name the structural property of the class that explains it (here, an artificial or missing objective) before generalising (pp. 84, 113, 126).
- **D4 Algorithm and implementation design**:
  - Each component carries a budget, stated with its numbers:

    | Component | Budget or setting | Pages |
    |---|---|---|
    | Strong branching | look-ahead λ = 8; at most κ = 100 candidates; γ = 2γ̄ iterations, within [10, 500] | p. 78 |
    | Reliability branching | η_rel = 8, adjusted so that strong-branching iterations stay below ½ γ̂_LP + 100,000; it falls linearly to 1, then to 0 once the budget is exceeded | pp. 79–80 |
    | Node selection | interleaved best estimate/best first, bestfreq = 10; hybrid weight ω = 0.1 | p. 92 |
    | Cut selection | efficacy, objective parallelism and orthogonality with weights 1, 0.1 and 1; minortho = 0.5; at most 2,000 cuts per round at the root and 100 elsewhere | pp. 62–63 |
    | Linear propagation | by default only at every fifth depth level | p. 113 |
    | Probing | aborted after 2,000 useless or 100 totally useless probings; interrupted after 50 fixings | p. 171 |
    | RENS | root only; at most 5,000 nodes, or 500 without improvement; skipped if more than half of the integers are fractional; run only if presolving the sub-MIP removes at least 25 % of the variables | pp. 132–133 |
    | RINS | at most 10 % of the total branching nodes in sub-MIPs | p. 141 |
    | Root restart | only if at least 5 % of the integer variables were fixed | p. 174 |
    | Conflict analysis | at most 10 conflicts per infeasible subproblem; used for propagation only; deleted by aging | p. 193 |

  - Numerical safeguards:
    - propagated bounds are relaxed to five decimals within the feasibility tolerance δ̂ = 10⁻⁶ ((7.2), p. 100);
    - a bound change is accepted only if it cuts at least 5 % of the domain width or bound magnitude ((7.3), pp. 100–101). This stops chains such as 0.2 ≤ x − y ≤ 0.8, which would otherwise take 1,000 rounds;
    - an unstable LP is retried with other solver settings, and otherwise skipped at that node (p. 48);
    - chip registers are split into 16-bit words, to avoid coefficients like 2^β (p. 209);
    - the conservative Gomory separator keeps only cuts that look numerically stable (p. 127).
  - Engineering devices:
    - two watched literals for set covering. The replacement rule was chosen by test, avoiding variables whose down branch is often visited (pp. 107–108);
    - 64-bit constraint signatures rule out pairs in pairwise presolving (p. 154);
    - block memory and a stack of reusable buffers (pp. 65–68).
  - Proof devices:
    - an exchange argument for the optimality of best-first search (Prop. 6.1, p. 89);
    - characterisations of bound and interval consistency (Prop. 7.2 and Cor. 7.3, pp. 98–99);
    - NP-completeness by reduction from subset sum (Prop. 7.4, p. 100);
    - NP-hardness of the minimum bound-IIS by reduction from the minimum IIS (Prop. 11.5, p. 188);
    - the Farkas/dual-ray proof (11.13), kept valid while bounds are relaxed (p. 188; Algs. 11.1–11.2, pp. 189, 191);
    - termination of term normalisation by a well-founded ordering and Dershowitz's recursive path ordering (Thm. 14.21 and Prop. 14.22, p. 236; Prop. 15.7, p. 298).
  - The hardness results justify cheap heuristics. A Farkas-based IIS heuristic was implemented, but "the overhead in running time was very large", so simple LP-based rules are used (p. 188).
  - Transferable: give every expensive component a budget in a solver-internal unit (simplex iterations relative to node-LP iterations, useless probings, fixings, conflicts per infeasible node), and print the numbers (pp. 78–80, 171, 193).
  - Transferable: before accepting a propagated bound, require a minimum relative change (5 % of width or magnitude), to stop slow ping-pong chains ((7.3), pp. 100–101).
  - Transferable: when the exact subproblem of a component is NP-hard, prove it, then justify the cheap heuristic with the measured overhead of a better one (p. 188).
- **D5 Computational evaluation**:
  - **Test set**: 575 public instances were reduced to 244 by a stated five-step rule, using Cplex 10.0.1 and SCIP 0.82d with and without conflict analysis (p. 334):
    1. remove instances that neither solver solves within 1 h;
    2. remove coral's duplicates of milp;
    3. remove coral instances that both solvers solve within 10 s, then drop every second remaining coral instance in Cplex-time order;
    4. remove the trivial alu instances, and those above 8 bits for numerical reasons;
    5. remove mik instances that both solvers solve within 10 s.
  - **Runs**: 244 instances × 115 settings = 28,060 runs, more than one CPU year (p. 16).
    - SCIP 0.90f was used for MIP and 0.90i for chip verification, with Cplex 10.0.1 as the LP solver (p. 333).
    - Hardware: eight identical Dell Precision 370 machines (Pentium 4, 3.8 GHz, 2 GB) (p. 333).
    - Limits: 1 h for MIP, 2 h for chip verification, 1.5 GB of memory (p. 333).
  - **Metrics**:
    - per test set, the percentage change of the shifted geometric mean against the default, for time (s = 10) and nodes (s = 100) (pp. 335–336);
    - geometric means and totals in Appendix B (p. 336);
    - a total that weights each single-class set as three pseudo-instances: 105 instances plus 21 pseudo-instances (p. 336);
    - Example A.1, in which the three means disagree in sign on one data set (pp. 335–336);
    - in the appendix tables, time-outs (T), counts of instances at least 10 % faster or slower, and "different path" and "equal path" blocks. Equal path means the same number of nodes and simplex iterations (pp. 339–340).
  - **Protocols**:
    - knock-out from the default for most components;
    - for cuts, all off / one off / one on alone, after Bixby et al. (p. 125);
    - for heuristics, also the time to a 5 % and a 20 % gap (pp. 143–146);
    - conflict analysis by effort level, against a reference without conflict analysis that Appendix B labels "default" (p. 193; Table B.191, p. 386).
  - **Variability**: single runs on unloaded machines; suspicious runs rerun; differences of up to 2 % attributed to timing noise; no seeds or permutations (p. 333).
  - **Failures reported**:
    - time-outs are scored at the limit, and the bias is stated (p. 333);
    - memory-outs count as time-outs with the node count scaled; 180 of 28,060 runs hit the limit (p. 333);
    - solver crashes are noted under the tables (pp. 324–325);
    - a leaf-queue bottleneck that penalises estimate-based node selection (p. 94).
  - **External baselines**:
    - Cplex 10.0.1, run with SCIP's gap tolerances (mipgap 0, absmipgap 10⁻⁹). Only the MIP part is compared, because SCIP uses Cplex for its LPs. SCIP 0.90f is 115 % slower, 0.90i 63 % slower (pp. 334, 391).
    - For chip verification, MiniSat 2.0, chosen as the best of MiniSat 1.14, Siege v4 and zChaff. Siege's 146.8 s is quoted where MiniSat behaves irregularly (pp. 313, 317).
    - Chip results are reported per instance, with sizes, nodes and seconds rather than means (pp. 313–332).
  - Transferable: compute the summary total as a shifted geometric mean in which the mixed sets count per instance and each single-class set counts as k pseudo-instances (p. 336).
  - Transferable: split every comparison into "different path" and "equal path" blocks, using identical node and simplex-iteration counts as a cheap test for an unchanged run (p. 339).
  - Transferable: for heuristics, add an experiment that stops at a gap target (5 %, 20 %) next to time to optimality (pp. 143–146).

  - He builds on:

    - Linderoth–Savelsbergh for branching (pp. 75, 85);

  - He delegates details to Wolter's and Berthold's diploma theses (pp. 115, 132).
  - Disagreements come with data and a stated scope:

**Transferable techniques**:
- State once in a footnote what the percentages mean, and use one summary-table layout in every chapter: time on top, nodes below, positive values worse (pp. 16, 83).
- In the shifted-geometric-mean total (shift 10 s for time, 100 for nodes), count each single-class test set as three pseudo-instances, so that no class dominates (pp. 335–336).
- Select the test set by a written rule, run with a frozen older version and a reference solver, and list where each set comes from (pp. 333–334).
- Score time-outs at the limit, and memory-outs as time-outs with the node count scaled by the nodes-per-second ratio; say that this favours the failing runs (p. 333).
- Add counts of instances at least 10 % faster or slower, and equal/different-path blocks, to every detailed table (p. 339).
- For interacting families, run all off, one off and one on alone, and compare the sum of the single knock-outs with all off as a measure of overlap (pp. 125–127, 142).
- Report heuristics at gap targets as well as in time to optimality (pp. 143–146).
- Draw the parameter interrelation diagram that shows the old rules as corners of the new one (Fig. 5.2, p. 82).
- Tie the reliability parameter to a strong-branching iteration budget: at most ½ γ̂_LP + 100,000 iterations, with η_rel decreasing linearly from 8 to 1, then to 0 (pp. 79–80).
- Use the product score max{q−, ε}·max{q+, ε} with ε = 10⁻⁶, tested against the weighted sum at several values of µ (pp. 76, 85).
- In propagation, round new bounds within the feasibility tolerance and accept only bound changes of a minimum relative size (7.2 and 7.3, pp. 100–101).
- Seed the conflict graph by relaxing bounds along the dual ray (Alg. 11.1, p. 189). Move non-binary bound changes to the conflict side to keep set-covering conflicts (p. 192).
- Prefilter pairwise constraint comparisons with 64-bit signatures (p. 154).
- When a published recommendation fails in your code, limit your claim to your code and test sets, and offer a mechanism (pp. 175–176).
- Print refuted impressions and losing defaults next to the table that refutes them (pp. 96, 114, 127).
- When a variant fails, read the logs, explain the failure, and say what would be needed instead (delayed restarts, p. 177).
