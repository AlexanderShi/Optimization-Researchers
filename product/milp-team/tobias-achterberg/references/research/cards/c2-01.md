**Role**: core, co-signed group work · **Coauthors**: Andreas Eisenblätter and Roland Wessäly (Atesio GmbH); Armin Fügenschuh, Alexander Martin and Oliver Wegel (TU Darmstadt); Thorsten Koch and Arie Koster (ZIB) (p. 2) · **Position in trajectory**:

- The chapter's author order (Crossref, in the work list) is Eisenblätter, Wessäly, Martin, Fügenschuh, Wegel, Koch, Achterberg, Koster. This groups the authors exactly by the report's affiliations (Atesio, Darmstadt, ZIB; p. 2), so his seventh place says nothing about his share (my comparison).

- **D1 Problem and entry**:
  - **The application.** The entry is an application project: MOMENTUM wants planning tools for the UMTS radio interface (p. 3).
    - The paper's goal is a model for planning the static installation of base stations: which candidate sites, which sectorisation, antenna types, heights and tilts, which maximum and pilot powers, and how much hard capacity (p. 3).
    - Scrambling codes, hand-over details and radio resource management are left out (p. 3).
  - **No single quality measure.** No measure says which of two networks is better (pp. 3–4):
    - a performance-centred view and a budget-centred view give conflicting ratings;
    - so the planner decides, and the optimiser should produce alternative designs for each planning goal.
  - **Three uses.** The model rates performance on traffic snapshots, costs a configuration, and scores configurations during optimisation (p. 4).
  - **Why a deterministic MIP.** The true problem is to serve several estimated future demands best on average (p. 5):
    - this is a stochastic integer program, nonlinear and discrete, with a lower semi-continuous objective;
    - the report calls it intractable at the sizes faced, and the only support given is a personal communication (Schultz, ref. [33]) (pp. 5, 25);
    - planning on traffic snapshots instead gives a very large MIP (p. 5).
  - **A surrogate.** The model stands in for the core of a static system-level simulator. It is less accurate, much faster, and evaluates many snapshots and configurations at once (pp. 5–6).
  - **Validation loop.** Optimise on the snapshots and analyse the result in a simulator. Then add the snapshots on which it fails and optimise again, until the result is satisfactory or the planner must relax the constraints (p. 6).
  - **How it was built.** The model was shaped in weeks of discussion with UMTS and radio engineers. It aims at an appropriate model rather than an easily accessible one (pp. 6, 22).

- **D2 Core idea and design**:
  - **Key idea.** Write feasible network configuration as the feasible set of a MIP (section 4). Put the rating into a separate linear objective built from cost and performance terms (section 5) (pp. 13, 20–22).
  - **Linearity sets the budget**, and each time the report says what it costs:
    - the SIR requirement takes the largest of the occurring ratios rather than a sum of targets, because sums are hard to handle in linear optimisation (p. 17);
    - the objective must be linear so that the LP-based toolbox applies, and the model is called too complex for a nonlinear one (p. 20);
    - uplink soft hand-over combining cannot be written with linear constraints, so it is approximated (p. 17).
  - **What is new against the surveyed IP models.** One model holds up- and downlink SIR, pilot SIR, code capacity and power limits per link and per installation (pp. 13–16). Several surveyed works lack the SIR target, interference or power control (pp. 7–8).
    - The longest account is of Amaldi et al. They use SIR with two power-control mechanisms and argue that the uplink is the more stringent direction for balanced connections such as voice calls (pp. 7–8).
    - The report never states its difference to them in one sentence (my reading: they are the closest prior model).
  - **Soft hand-over.** Modelling it exactly is called prohibitive, for three reasons: the resources used at all serving cells, the combining modes, and fading (p. 17).
    - Three options are ranked by fidelity: a general SIR gain, post-processing, and an approximation inside the model.
    - The third is chosen (pp. 17–18) and built from candidate sets and a *phantom power* (pp. 18–19).

- **D3 Problem class and data model**:
  - **Variables** (pp. 14–16, 19, 27):
    - binaries s_k (site used), z_i (installation used), w_m (mobile served) and x_mi (m served by i);
    - continuous uplink power p↑_m, downlink power p↓_im, pilot power p̂↓_i and phantom power v↑_m.
  - **Structure**:
    - Snapshots d ∈ D have mobile sets M_d, and M is their disjoint union (pp. 11, 26).
    - Rows (5), (7) and (10)–(12), with the interference sums (13)–(14), are written per snapshot (pp. 15–16).
    - Site, installation and pilot-power variables carry no snapshot index (pp. 14–16, 27). So they link per-snapshot blocks that are otherwise separate (my reading). No decomposition is mentioned.
  - **Continuous design choices made discrete.** An installation is a candidate antenna setting (coordinates, direction, tilt, type) at a site, and it acts only through precomputed attenuations (pp. 10, 12).
    - The authors flag one assumption as a possible problem: all installations at a site are compatible, and all combinations are allowed (p. 10).
    - Channel elements are assumed not to be limiting (p. 10).
  - **Semi-continuous variables.** Binaries switch the powers on: Π^min_m w_m ≤ p↑_m ≤ Π^max_m w_m (6). Per-link power is switched by x_mi (8), and pilot power by z_i (9) (pp. 15–16).
  - **Knapsack row.** Code consumption is Σ_{m∈M_d} λ_m x_mi ≤ Λ_i z_i for every installation and snapshot (5) (p. 15). The row comes from Kraft's inequality (see D4).
  - **Ratio constraints with a binary right-hand side.** Uplink SIR (7), downlink SIR (11) and pilot SIR (12) read signal / (interference + noise) ≥ μ x_mi (pp. 15–16).
    - The abstract hedges these constraints as *essentially* linear, and section 4 calls the model a MIP (pp. 2, 13).
    - Multiplied out, each constraint has a binary times a sum of continuous powers. Making it linear needs a big-M or a similar device, and the report does not give one (my reading of pp. 15–16).
  - **Stated assumptions**:
    - perfect power control (pp. 13, 15);
    - each mobile is linked to at most one cell (pp. 14, 17);
    - no secondary code trees and no code fragmentation: mobiles take an average number of codes from the budget (pp. 11–12);
    - the loss of orthogonality on secondary code trees and the effect of fading are not modelled (pp. 13, 17);
    - power-control headroom and fading can enter only through the SIR targets (p. 13).
  - **Data.** The appendix gives every parameter with its domain and every variable with its type (pp. 26–27). No instance, model size or coefficient range is reported, so the numerical ranges are unknown from this text.
  - **Complexity.** NP-hardness is concluded from Galota et al.'s result for a simplified problem, without a reduction (p. 9).

- **D4 Algorithm and implementation design**: there is no algorithm and no proof (n/a). The formulation devices are these.
  - **Code capacity from Kraft's inequality** (pp. 11, 15):
    - Orthogonal spreading codes are generated recursively, and each is described by its generating bit pattern. Two codes are orthogonal iff the shorter pattern is not a prefix of the longer one.
    - The report calls Kraft's inequality a necessary condition for a prefix-free set. It rescales the inequality by 2^{n_max} to avoid fractions.
    - Each mobile then consumes λ_m ≥ 2^{n_max − n} codes of the budget Λ_i, which gives row (5).
  - **A redundant linking row, kept and labelled** (p. 15). Row x_mi ≤ z_i (3) carries a footnote that it is redundant given (5).
    - It is redundant for integer points (with λ_m > 0). But (5) does not imply it in the LP relaxation: z_i = 1/2 and x_mi = 1 for one mobile with λ_m ≤ Λ_i/2 satisfy (5) and violate (3) (my check).
    - The report does not say why the row is kept.
    - Achterberg's later co-signed presolve paper draws the same line: removing MIP-redundant rows can hurt because it weakens the LP relaxation (R021 p. 27).
  - **Candidate sets by a ratio threshold.** K_mi(δ) = { j ≠ i : 1/δ ≤ γ↑_mi / γ↑_mj ≤ δ }, with δ typically between 2 and 4, that is 3 to 6 dB (p. 18). Only these installations can co-serve m (pp. 18–19).
  - **Phantom power** (p. 19):
    - The variable v↑_m adds to the mobile's power in the SIR numerator but not to interference (row 7′).
    - Its rows are 0 ≤ v↑_m ≤ ρ↑_m (16) and v↑_m ≤ ρ↑_m − ρ↑_m x_mi + Σ_{j∈K_mi(δ)} g_mij z_j (17).
    - Here g_mij is the gain when m is served by i and supported by j; its symbol does not extract (pp. 19, 26).
    - The big-M in (17) is ρ↑_m, the variable's own bound from (16), so the row is slack when x_mi = 0 (my reading).
    - With ρ↑_m = 0, row (7′) falls back to (7) (my reading).
    - Gains from several secondary servers are assumed to add up, and the rows must hold whichever installation finally serves m (p. 19).
  - **Soft hand-over in code consumption.** Raise λ_m globally, or lower Λ_i depending on the candidate sets that contain i (p. 19).
  - **Minimum powers come from the objective.**
    - Perfect power control means minimum powers (p. 15), but the SIR rows are inequalities.
    - At the headroom terms, the report adds that the least possible power level must always be selected (p. 21).
    - So the minimum comes from the objective, not from the constraints (my reading).

- **D5 Computational evaluation**: n/a. There are no instances, runs, solvers or tables.
  - Experiments are promised for the soft hand-over extension (p. 20).
  - Both next lines of work are to be tested extensively on real-world instances from MOMENTUM (p. 22).
  - The only validation design is the simulator loop of D1 (p. 6).

- **D6 Positioning**:
  - **Two books.** Holma and Toskala [18] give the WCDMA background, and Laiho et al. [24] cover planning. The authors say the second does not make their paper unnecessary: it holds the information that models need, but no models or methods (p. 6).
  - **The methods literature** is called still limited (p. 6). Each work is described by what it leaves out:
    - Fallot-Josselin: no WCDMA-specific constraints (p. 7);
    - Ibbetson and Lopes, and Molina et al.: no SIR target (p. 7);
    - Tutschku et al.: no interference (p. 7);
    - Mathar [26]: quality-of-service constraints studied only afterwards, with stochastic methods (p. 8).
  - **Amaldi et al.** get the longest account: SIR, two power-control mechanisms, and general MIP solvers that fail on practical instances in reasonable time, hence greedy heuristics (pp. 7–8).
  - **Against GSM.** There, coverage and capacity can be planned separately, but not in UMTS, so the models are hard to compare (p. 9). cdma-One is closer to UMTS (p. 10).
  - **Tone and support.** The critique works by reformulation, without polemic. Two central claims rest on citation alone:
    - intractability rests on a personal communication (pp. 5, 25);
    - NP-hardness rests on a simpler problem's result (p. 9).

- **D7 Writing and rhetoric**:
  - **Problem first.**
    - The decisions are listed as questions (p. 3).
    - Planning parameters come before the model (pp. 10–13).
    - Each constraint is stated in words before its formula (pp. 14–16).
    - Figure 1 sketches the model (p. 14).
  - **Simplifications where they bite.** *Notice* paragraphs put a simplification at the constraint it affects (pp. 15, 17), and footnote † labels the redundant row (p. 15).
  - **Dense hedging**: on the linearity of the constraints (p. 2), on whether a crude gain beats doing nothing (p. 18), and on whether the soft hand-over approach is viable (p. 20).
  - **The contribution sentence** opens with its limit: apart from a detailed objective function, the model is complete. It is called the basic model, and its complexity is presented as the price of capturing the relevant side constraints (p. 22).
  - **Finish.** Some typos are left in (pp. 3, 22), and the appendix tables serve as the notation reference (pp. 26–27).

- **D8 Contribution and limits**:
  - **Contribution level**: a model only. There is no algorithm, software or computation, and the objective is a set of proposals (pp. 20–22).
  - **Limits** are concrete and stated at the point of use (the assumptions in D3). The soft hand-over treatment is admitted to be incomplete (p. 20).
  - **Future work** has two lines (p. 22):
    - heuristic simplification, in the hope that established techniques then apply. Because the full model exists, the compromises of a simplified model can be measured precisely;
    - methods tailored to the full model.

    Both are to be tested on MOMENTUM's real-world instances. Heuristic dimensioning rules from MOMENTUM are to simplify, modify or extend the model (p. 22).

**Method links**:
- **Method 5** (variant ⚠; pp. 20, 22): the order is reversed. The model is published as a project deliverable before any instance, run or harness exists, and computation is promised for later. This is co-signed group work in another genre, from before SCIP, so it is no counter-example to his solver practice. It only shows a case where the habit is absent (inferred).
- **Method 6** (variant ⚠; pp. 6, 11, 15): an import from information theory, mapped object by object. The spreading codes' generation patterns are prefix codes, and Kraft's inequality becomes knapsack row (5). Practitioners explained the domain over weeks (p. 6). But no test decides, and the importer is not named.
- **Method 3** (variant ⚠, weak; p. 19): the soft hand-over extension contains the basic uplink row as the setting ρ↑_m = 0 (my reading). This resembles Method 3's first step, the incumbent as one setting of a parameter, but the report neither says so nor sweeps anything.
- **Heuristic 6** (context; p. 15): the redundant row (3) is kept and labelled, without a test. His later work measures what such information does:
  - omitting seemingly useful redundant information can sometimes speed up solving (R011 p. 2);
  - removing MIP-redundant rows can weaken the LP relaxation (R021 p. 27).
- New-pattern candidate: *full model first as the yardstick for simplifications* (pp. 6, 22).
- New-pattern candidate: *sampled scenarios with a simulator in the loop* (pp. 5–6).
- New-pattern candidate: *MIP-redundant is not LP-redundant: label the row, keep the disaggregated link* (p. 15; R021 p. 27; R011 p. 2).
- **Not linked**: Methods 1, 2 and 4. They need computations, defaults or solver components, and this report has none.

**Transferable techniques**:
- (D1) Replace an intractable stochastic planning problem by a MIP over sampled scenarios. Check each solution in an external simulator, and add the scenarios it fails on (pp. 5–6).
- (D3) Discretise continuous design choices (tilt, height, direction) into candidate configurations with precomputed coefficients. State the compatibility assumption this makes (pp. 10, 12).
- (D4) Model a prefix-free code resource with Kraft's inequality, scaled by 2^{n_max} to integer coefficients, as a knapsack row against a budget (pp. 11, 15).
- (D4) Use a conditional variable's own upper bound as the big-M of its conditional row, so that the off case follows from a bound the model already has (p. 19, rows (16)–(17)).
- (D4) Keep a disaggregated linking row x ≤ z next to an aggregated capacity row, and label it as MIP-redundant. Test it on the LP relaxation, not only on integer points (p. 15; my check).
- (D4) Sparsify conditional terms with candidate sets built from a physical ratio threshold (p. 18, row (15)).
- (D7) In a model paper, state each constraint in words before its formula, and put each simplification in a *Notice* at the constraint it affects. Add an appendix with the domain of every parameter and the type of every variable (pp. 14–17, 26–27).
- (D8) Write the complete model first, even when no solver can take it yet, so that each later simplification can be measured against it (p. 22).
