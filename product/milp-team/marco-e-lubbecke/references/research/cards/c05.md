- **D1 Problem and entry point**: The report enters through software practice, not through a research question. Solver success is credited to careful implementation of theoretical ideas, and the field is said to have outgrown solvers written for one purpose (a PhD thesis, one industrial problem), so that future development must build on flexible frameworks (p. 4); the stated aim is to present the recent changes with the emphasis on implementation and its computational consequences (abstract, p. 3). The collective introduction presents SCIP's pricer plugin as the way to employ branch-and-price without developing a tree search (p. 5), and GCG's value as support for non-experts in using Dantzig-Wolfe decomposition plus a platform for research on decomposition (p. 5). The RWTH section enters through structure: many programs expose a model structure that Dantzig-Wolfe reformulation or Benders decomposition can exploit, at the price of solving another relaxation, "hopefully stronger" than the LP relaxation, and of the extra algorithmic burden of column generation (p. 59).
  - Transferable: open the description of a decomposition with both sides of the bet in one sentence, the bound you hope to gain and the algorithmic cost you take on (p. 59).
- **D2 Core idea and algorithm design**: GCG 2.1.2 handles Dantzig-Wolfe reformulations and Lagrangian decompositions of LPs and MILPs (p. 59). The structure is a doubly-bordered block-diagonal matrix with k blocks D_i, linking columns F^i, linking rows A_i and a corner block G. If the F^i and G are zero, classical Dantzig-Wolfe applies; otherwise each linking variable is duplicated for each of the at most k subsystems it appears in, a Lagrangian decomposition is applied, and the identity of the copies is enforced by constraints in the master (p. 60). The structure comes either from a .dec, .blk or .ref file (formats also used by DIP) or from detection by several heuristics and partitioning algorithms on graph and hypergraph representations of the matrix (ref. [18], the 2015 paper); compiled with bliss, GCG detects identical blocks and aggregates them to remove symmetry (p. 60). After reformulation a "fully generic" branch-price-and-cut algorithm runs on the master, and the k pricing problems are solved as MIPs by SCIP or CPLEX, or by a dedicated pricing solver, sequentially or in parallel (p. 60). Kept from the SEA 2010 design as the skill records it (two synchronized SCIP instances, structure supplied by file; Signature Work Anatomy): the two trees, here described as the main solving loop working on the original problem, the master represented by a relaxator plugin, both trees kept node for node in one-to-one correspondence, and a mapping between solutions of the two models (p. 60). Beyond the file input recorded for SEA 2010, this section names detection, symmetry aggregation and linking-variable duplication, and lists as the most important ingredients branching on original variables, Ryan-Foster branching for set partitioning and Vanderbeck's generic branching, primal heuristics (ref. [94]), separators on original variables (ref. [95]), dual variable smoothing and a column pool (p. 60); when each was added is not stated. Nothing in §6 is new in this release (p. 59).
  - Transferable: handle linking variables by copy and link: duplicate each one per block it touches and put the copy-identity constraints into the master, so that a doubly-bordered matrix becomes ready for Dantzig-Wolfe (p. 60).
- **D3 Problem class and data model**: GCG takes linear and mixed-integer linear programs as input (p. 59); what it exploits is a permutation of the matrix to doubly-bordered block-diagonal form with k blocks (p. 60). Classical Dantzig-Wolfe needs zero linking columns and corner block; linking variables are admitted through duplication; identical blocks are aggregated only with the optional bliss library; other matrix forms such as staircase structure are covered only by experimental detectors that are off by default (p. 60). Pricing problems are general MIPs with matrices D_i unless the user supplies a dedicated solver (p. 60). §6 states no correctness assumption and names no instance library (n/a). In the co-signed rest, SCIP's class is the MINLP (1) with a linear objective assumed throughout (p. 5); correctness arguments state their assumptions (a nonempty bounded feasible set for the KKT reformulation, p. 29; Slater's condition for the Lagrangian variable bounds, p. 35). The MIP test sets are the MIPLIB 2010 benchmark (87 instances, p. 71), the MMM union of MIPLIB 3, MIPLIB 2003 and the MIPLIB 2010 benchmark (p. 14), a 254-instance union for dual-ray analysis (p. 28), 13 line-planning instances with very long knapsack rows beside non-intersecting set-packing rows (p. 10), and supply-chain models whose regions or products do not interact (pp. 11-12, 20); MINLPLib2 serves the MINLP features (pp. 33, 36, 72).
- **D4 Algorithm and implementation design**:
  - §6 (group): the original problem drives SCIP's main loop and the master is a relaxator plugin; the two branch-and-bound trees are kept synchronous with a one-to-one node correspondence and a solution mapping (p. 60). This is the invariant that lets branching decisions and cuts be stated on original variables; how they are translated to the master is not described in §6 (p. 60).
  - §6: pricing problems are independent MIPs, so parallel solving is stated as a capability, not as a default (p. 60). Heuristic pricing, monitoring of the Lagrangian bound and early branching (H1) are not mentioned in §6 (p. 60).
  - §6: the experimental detectors are disabled by default (p. 60).
  - Host features that touch decomposition, by other authors where attributed (§4.4 on the basis representation is unattributed, p. 74): relaxators whose relaxation includes all LP rows (flag RELAX_INCLUDESLP) can now have their solution enforced, that is used for cuts and branching, when their bound is strictly better than the LP bound or no LP was solved (pp. 14-15; TG, GG and BM, p. 74); reoptimization is extended to general MIPs, with column generation's sequence of pricing MIPs named as one of the major motivations (pp. 26-27; JW, p. 74); the column representation of the basis suits added variables in branch-and-price and the row representation suits added cuts, chosen anew for every LP solve (p. 56); independent components can be solved as separate sub-SCIPs during the tree search, off by default (pp. 11-12; GG, p. 74). The report does not say that GCG uses any of them.
  - Correctness devices in the co-signed sections: aggregating the v-bounds around a cycle of the variable bound graph into a self-bound that yields a valid bound or proves infeasibility (pp. 8-9); a Farkas proof constraint kept for propagation through maximal-activity residuals (pp. 27-28); equivalence of a mixed binary QP with a complementarity-constrained KKT program through z_j = x_j λ_j (pp. 29-30); a Lagrangian variable bound derived from the KKT conditions of a convex NLP (pp. 35-36); Lemma 4.1, column and row bases are regular together, by a determinant identity (pp. 55-56); a deterministic clock fitted by Lasso regression on solver statistics with leave-one-instance-out cross-validation, and delayed reads at communication points that keep concurrent runs deterministic (pp. 41-42).
  - Transferable: if a decomposition code sits on a MIP framework, let the framework's tree run on the original model and hang the master in as a relaxation, with nodes kept one to one; every branching rule and cut can then be written in original variables (p. 60).
- **D5 Computational evaluation**: none for GCG: §6 reports no run, no test set and no comparison (pp. 59-60). The co-signed rest carries a full protocol. Overall MIP comparison: SCIP 4.0 against SCIP 3.2.1 on the 87 MIPLIB 2010 benchmark instances, each also in four permuted copies; an instance counts as solved only if solved in all permutations; times and nodes are averaged arithmetically over permutations before shifted geometric means with shifts of 10 s and 100 nodes; exclusive jobs on Xeon E5-2670 v2 at 2.50 GHz, 7200 s, 35 GB, SoPlex 2.2.1 against SoPlex 3.0 (pp. 70-71). Results: 7% faster over all permutations, 1% slower on the default order with two more instances solved, the loss attributed to the deliberate randomization against overtuning (pp. 71-72, Table 12). MINLP: 115 MINLPLib2 instances, 1 h, 40 GB, gap limit 10^-3, CPLEX 12.6.0.0 as LP solver, with a "failed" column counting runs whose bounds contradict the library's reported values (pp. 72-73, Table 13). Component tests: five seeds per instance, solved only if all five seeds solve within 2 h, and the spread between fastest and slowest seed reported (7.6% down to 5.5%) (p. 14); leave-one-out heuristic configurations (pp. 25-26); affected and highly affected subsets (105 and 22 of 254 instances) (p. 28); the shift is stated for most shifted geometric means (pp. 31, 57, 62, 69, 70) but not for the node means of p. 14 or the NLOBBT table (p. 36). Failures and slowdowns are printed: cycle detection finds no reductions on standard benchmarks (p. 9), LP face finds no solution on MIPLIB 2010 (p. 25), polishing at the root solves two fewer instances (p. 49), the gauge separator slows the convex instances by 25% (p. 39), and on the 215 instances of the decomposition-based dual simplex study default SoPlex needs the fewest iterations on about 60%, each decomposition setting on 25% to 35% (p. 53).

**Transferable techniques**:
- Doubly-bordered block-diagonal matrix: with no linking columns apply classical Dantzig-Wolfe; otherwise duplicate each linking variable once per block it appears in and enforce the equality of the copies in the master, a Lagrangian decomposition (p. 60).
- Run the framework's tree on the original model and represent the master as a relaxation plugin, keeping the two trees in one-to-one node correspondence with a solution mapping, so that branching (on original variables, Ryan-Foster, Vanderbeck) and cut separation are stated in original variables (p. 60).
- Remove the symmetry between identical pricing blocks by detecting them with a graph-automorphism tool (bliss) and aggregating them into one subproblem (p. 60).
- Accept a decomposition from a file in a format other frameworks read (.dec, .blk, .ref, shared with DIP) besides automatic detection, so that a known structure can be tested directly (p. 60).
- Default rule for a new component: switch it on only when a general benchmark shows a gain or no harm; if it helps only on a structured set (supply chain), ship it off behind a parameter and print the reason next to the result (pp. 9, 12, 49).
- Variability protocol for a solver change: run each instance with k seeds or k permuted copies, count it solved only if solved in all, average times per instance arithmetically before the shifted geometric mean (shifts 10 s and 100 nodes), report the default order separately, and report the spread between the fastest and the slowest seed (pp. 14, 70-71).
- Report a feature on three nested sets: all instances, the affected subset (the feature acted at least 100 times) and the highly affected subset (at least 50,000 times), with time-outs counted in each (p. 28).
- In a many-author software report, map every section to its authors' initials in a code-contributions paragraph (p. 74).
