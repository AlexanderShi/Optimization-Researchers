- **D1 Problem & entry**:
  - Entry from history and structure: the most common vehicle routing variants "have served for decades as guinea pigs" for ideas such as branch-and-bound and cutting planes, and a school bus routing problem was the first problem solved by an exact column-generation-based algorithm, i.e. branch-and-price (Desrosiers et al. 1984), soon followed by bus driver and aircrew scheduling (p. 3).
  - The shared feature that defines the chapter: set partitioning or covering masters whose columns are routes, itineraries or schedules over an underlying network, so that pricing is often a shortest path problem with resource constraints (SPPRC) (p. 3).
  - Stated goal: illustrate column generation on vehicle and crew scheduling examples, formulate them, and describe dynamic programming for the SPPRC and the elementary ESPPRC; integer solutions are postponed to ch. 7 (p. 3).
  - Problem statement: the VRPTW with identical vehicles of capacity Q at one depot, hard time windows (early arrival waits), each customer visited exactly once, minimum travel cost (p. 4).
  - Secondary entries: with wide windows and loose capacity the elementary pricing problem becomes "highly time-consuming", hence relaxations (p. 18); each example is introduced by the one modelling feature it adds (pp. 30, 32, 38); §5.4 asks for a compact linear formulation of the VRPTW (p. 45).
  - Transferable: open a decomposition application by naming the structure that makes pricing tractable (an underlying network, so an SPPRC) and the master type (set partitioning) before writing any model (p. 3).
- **D2 Core idea & algorithm design**:
  - *Kept* from ch. 4: Dantzig-Wolfe reformulation by convexifying each vehicle's domain, aggregation of the identical blocks (Section 4.4), the bound advantage of Prop 4.1, binary λ by Prop 4.4, and the aggregated convexity constraint kept for branching (Note 4.16) (pp. 7–10).
  - *Changed* for routing: an extreme point is a route plus an extreme schedule, so one route gives several extreme points (Note 5.1, p. 8). Cost and visit coefficients do not depend on time, so one representative schedule per route suffices and λ is binary (Note 5.2); this breaks down when columns encode time, as with vehicle synchronization or time-dependent delivery costs (Note 5.3) (p. 9).
  - Pricing: the ISP is an elementary shortest path problem with time windows and capacity (ESPPTWC) (p. 10), and it is "typically not solved" from its MIP model (5.13) but by a labeling algorithm on the network: labels, resource extension functions (REFs), resource windows, and a dominance rule that keeps only Pareto-optimal labels (p. 12).
  - Generalization: the ESPPRC with an arbitrary resource set (pp. 25–28), then three examples that each add one feature: a resource whose extension depends on another resource (SPDP, p. 30), pairing and precedence (PDPTW, p. 32), several resources to compute a non-linear reduced cost (crew pairing, p. 38).
  - *Why* relaxations: allowing all cycles (SPPTWC) or certain cycles (ng-routes) makes pricing cheaper and the bound weaker (pp. 18–24); the ng family spans the two extremes (Note 5.8, p. 22).
  - §5.4 changes the network rather than the algorithm: a time-expanded network internalizes time, so the compact model is linear and, the text says, "thus" permits a Dantzig-Wolfe reformulation (p. 47). §5.1 had already convexified the non-linear domain (5.3) (p. 7); the chapter does not comment on the difference.
  - Transferable: keep schedule components (time, load) out of the column whenever no master row or cost reads them, so that one route is one binary column (Notes 5.2–5.3, p. 9).
- **D3 Problem class & data model** (team.json):
  - Model forms: a compact arc-flow mixed-ILP (5.1) with vehicle index, binary arc variables and continuous time variables; its non-linear linking constraints (5.1g) are linearized by big-M with M = b_j − a_i, and those with b_i + t_ij ≤ a_j are dropped (pp. 6–7). Masters: set partitioning (5.8), (5.36), (5.41), and set partitioning with soft side constraints and static variables (5.54) (pp. 9, 31, 34–35, 42–43). Blocks: one aggregated ISP for identical vehicles (VRPTW, SPDP, PDPTW) and one ISP per day and base for crew pairing (pp. 7, 31, 35, 43).
  - Assumptions, stated "To reflect practice": integer Q, q_i, a_i, b_i and t_ij; positive duration of every cycle; travel times satisfying the triangle inequality (Def 5.1) (p. 4; repeated for the PDPTW, p. 33). The triangle inequality is necessary for two of the unreachability tests (p. 15). The ESPPRC needs, along any cycle, a resource with positive consumption and bounded windows (p. 26), and labeling needs every REF non-decreasing in each component (p. 27). The fleet is unconstraining, so the convexity row (5.7c) and Σλ_p ≤ |K| may be dropped (pp. 9, 49).
  - Crew pairing: "one relatively simple variant" (p. 38): a weekly schedule repeated over weeks, one aircraft type, no deadheading, no overnight flights (pp. 38–40). The pairing cost max{l_p, α s_p} has α (e.g. 1/4) "dictated by the collective agreement"; soft base flying-time limits L_b carry a two-piece penalty ω¹_b < ω²_b, with no owner named for the rates (p. 40).
  - Data: one four-customer network (Fig. 5.1, p. 5) carried through Illustrations 5.1–5.5 and §5.4 (pp. 5, 15–23, 46); a three-request PDPTW network (Fig. 5.5, pp. 34–35); six of Solomon's (1987) 100-customer instances with randomly located customers, R104, R108, R110 (narrow windows) and R202, R203, R205 (wide windows) (pp. 23–24). Mentioned, not tested: all 56 Solomon instances and the Gehring–Homberger instances with 200 to 1000 customers (p. 50); an industrial monthly crew-pairing instance with 46,588 flights (p. 51).
- **D4 Algorithm & implementation design, proofs and devices** (team.json):
  - Labeling (Algorithm 5.1, pp. 16–17): unprocessed and processed label sets per node; select the unprocessed label of minimum time; extend it along every outgoing arc by the REFs (5.18); discard labels outside the windows (5.15); check dominance against U_h ∪ P_h and filter U_h (both optional); return the least reduced-cost label at d, recovered through predecessor pointers (p. 20). With t_ij > 0 on arcs out of customers it is label-setting, and this order "guarantees a minimum number of label extensions" (p. 16); if the selection resource can decrease, it becomes label-correcting (p. 27). Exercises 5.6–5.7 ask for the proofs behind the two dominance steps: a new label found dominated dominates no other label, and a new label never dominates a processed one (p. 52).
  - Dominance: Def 5.3 (every feasible extension of p′ is feasible for p at no higher reduced cost) cannot be checked, so componentwise conditions (5.19) and (5.35) are used, sufficient because all REFs are non-decreasing (pp. 14, 28; proof as Exercise 5.5, p. 51). For hard instances the dominance check becomes "a highly critical bottleneck operation"; data structures (Sadykov et al. 2021) are out of scope; postponing dominance means managing more labels (p. 17). Dominance at the sink is "not helpful", since sink labels are not extended (p. 20).
  - Strengthened dominance (Feillet et al. 2004): customer resources become unreachability resources, set to 1 when a customer has been visited or can no longer be reached in time or capacity (Def 5.4, REFs (5.23)–(5.24)); Illustrations 5.2–5.3 show two labels that become comparable (pp. 14–16). Arcs to unreachable customers are skipped (Note 5.5, p. 17).
  - Relaxations: the SPPTWC allows all cycles and has pseudo-polynomial labeling (p. 19). The ng-SPPTWC (Baldacci et al. 2012) allows a cycle only through a node whose neighbourhood excludes the cycle's start; it is implemented with memories M_p′ = (M_p ∪ {h}) ∩ NG_h and dominance M_p ⊆ M_p′ (pp. 20–23), and the dominance test needs ρ + 3 comparisons instead of |C| + 3 (p. 22). With cycles, a_ip counts visits and π_i is subtracted at every visit (Note 5.7, p. 19).
  - Validity device for relaxed pricing: a route that visits a customer twice has a_ip ≥ 2, so (5.8b) forces λ_p = 0 in every integer solution, while in the MP it may take up to 1/a_ip and weaken z⋆_MP (p. 19).
  - REF toolkit: f1 (add, e.g. load), f2 (subtract, e.g. residual battery of an electric vehicle), f3 = max{b, t + a} (window lower bound), f4 (reset, e.g. daily crew counters) (pp. 28–29). Compositions of non-decreasing functions stay non-decreasing (Note 5.11, p. 29; Exercise 5.16, p. 53). Note 5.10: replace f by max{a_j, f} so that a resource never falls short of its window lower bound (p. 27).
  - SPDP: the maximum-load resource maxL extends with the collected load loadP and is still non-decreasing (p. 32); arcs are eliminated by capacity, including delivery after pickup (p. 31).
  - PDPTW: ten arc-elimination conditions from precedence, capacity and time windows (pp. 33–34); the request dual is split 0.5π_u over the arcs leaving u⁺ and u⁻, with the alternatives named (p. 35); resources req_u, on_u and notOn_u with node-type windows (Table 5.3, p. 36), whose dominance conditions reduce to equal onboard sets, which "can be proven" (p. 37). Røpke and Cordeau's (2009) relaxed dominance (Def 5.5) follows a cost shift δ_u that restores the triangle inequality at delivery nodes, recomputed at every column generation iteration, and weakens the condition to O_p ⊆ O_p′ (pp. 37–38). It requires that every arc that can be part of a feasible path stays in A at all times during the search for an integer solution (p. 38).
  - Crew pairing: acyclic time-space networks per day and base, with departure, arrival (arrival time plus minimum connection) and to-flight nodes and seven arc types (pp. 40–42). The reduced cost (5.55) is the max of two linear expressions; unconstrained resources rCostF and rCostS carry one each, and rCost is their max (5.57a) (pp. 43–45). A count-down resource dtyMin and a count-up resource dtyMax, with reset REFs, enforce the duty-duration interval (Table 5.4, pp. 44–45; Exercise 5.25 asks why one resource is not enough, p. 54). On an acyclic network the SPPRC equals the ESPPRC (pp. 27, 45).
  - §5.4: the time-expanded network G^Δ has one copy of each node per integer time unit of its window, and keeps an arc only for the exact travel time or a necessary, minimal wait (5.58) (p. 46). Pruning unreachable copies gets harder as the network and the windows grow, and G^Δ is acyclic but its paths can revisit a customer (p. 46). The elementarity rows (5.60), redundant in the compact model, are needed in the pricing domain (p. 48). The text states, without proof, a bijection between the extreme points of conv(D) and feasible routes, so convexification and discretization give the same master (p. 48). Capacity can be internalized by three-dimensional nodes, useful for understanding labeling (p. 47).
  - Accelerations listed, not described: bounded bidirectional labeling, decremental state-space relaxation, completion bounds (citing Lübbecke 2005), heuristic pricing (Note 5.6, p. 18).
  - Transferable: for every new pricing model, list each resource with its window and REF and check that every REF is non-decreasing before using componentwise dominance, as the chapter does at the end of each example (pp. 32, 37, 45).

**Transferable techniques**:
- Labeling for resource-constrained pricing: per node, keep unprocessed and processed labels; extend the minimum-time label along every arc with the REFs; drop labels outside the windows; check dominance in both directions; keep predecessor pointers to recover the path (Algorithm 5.1, pp. 16–17, 20).
- Before relying on componentwise dominance, list every resource with its window and REF and check that each REF is non-decreasing; build complex REFs by composing add, subtract, max{b, t + a} and reset (pp. 27–29, 32, 37, 45).
- Unreachability resources (Feillet et al. 2004): mark a customer when it is visited or can no longer be reached in time or capacity; more labels become comparable, and extensions to marked customers are skipped. Valid only if travel times satisfy the triangle inequality (pp. 15–17).
- ng-route relaxation with memories: M_p′ = (M_p ∪ {h}) ∩ NG_h and dominance by M_p ⊆ M_p′; NG_i = {i} gives the SPPTWC and NG_i = C the ESPPTWC; choose ρ per instance class (pp. 20–24).
- When pricing admits cycles, count visits in a_ip and subtract the dual at every visit (Note 5.7, p. 19).
- Pricing-relaxation table: same code and machine; per instance, time, bound and gap closed GP(A) = (z⋆_MP(A) − z⋆_MP(weakest)) / (z⋆_IMP − z⋆_MP(weakest)), plus the ratio to the strongest bound; one class where the relaxation should matter and one where it should not (Table 5.2, Fig. 5.2, pp. 23–25).
- Max-of-linear column cost: carry each linear component in its own unconstrained resource and set the reduced-cost resource to their max (crew pairing, (5.55)–(5.57a), pp. 43–45).
- Interval constraint on a duration: one count-down resource for the minimum (extended by max{t − E, 0}, window [0, 0] where the interval must be complete) and one count-up resource for the maximum, both reset when a duty starts (Table 5.4 and (5.57d)–(5.57e), pp. 44–45; Exercise 5.25, p. 54).
- Røpke–Cordeau cost shift for pickup-and-delivery pricing: move δ_u from the arcs leaving u⁺ to the arcs leaving u⁻ to restore the triangle inequality at delivery nodes, recompute it at every iteration, then dominate with O_p ⊆ O_p′ instead of equality; keep every possibly feasible arc in A during the integer search (pp. 37–38).
- Preprocess the pricing network with provably valid arc-elimination rules from capacity, precedence and time windows: the VRPTW keeps only arcs with q_i + q_j ≤ Q and a_i + t_ij ≤ b_j (p. 4); the SPDP and PDPTW add capacity and precedence rules, the latter ten conditions in all (pp. 31, 33–34).
- Encode in the column only what the master reads: if no master row or cost uses the schedule, keep one representative schedule per route and binary λ; re-encode when synchronization or time-dependent costs appear (Notes 5.2–5.3, p. 9).
- Time-expanded network for a linear compact model: one node copy per integer time unit, an arc only for the exact travel time or a necessary minimal wait (5.58), and the elementarity rows (5.60) added to the pricing domain (pp. 45–48).
