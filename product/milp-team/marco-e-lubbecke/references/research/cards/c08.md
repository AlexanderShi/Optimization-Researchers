- **D1 Problem and entry point**: The report states two aims: explain the changes in SCIP's solving process with their effect on MILP and MINLP performance and robustness, and present what practitioners can now do with the suite (p. 3). For GCG the entry is usability, not an algorithmic gap: since 3.0 in 2018 "most development efforts" went into usability for experts and beginners, with more interfaces, better documentation and tools that support computational experiments and their evaluation (p. 70). The one algorithmic entry is a cost problem. Exact strong-branching gains in branch-and-price require solving every candidate's child LPs by column generation to optimality. Because pricing problems are often hard, this is a much larger burden than in branch-and-cut, yet strong branching has shown potential on hard branch-and-price instances and builds small trees ([82, 91]; p. 71). The co-signed MINLP part is entered from a counted failure: SCIP 7 returned solutions feasible for the presolved but not for the original problem on 7% of MINLPLib instances (§4.2.1, p. 20; BM, FeS, KB, SV per p. 82).
  - Transferable: open a component study with the cost structure that blocks a known-good rule in your setting (here: strong branching needs column generation in every child, p. 71), then design relaxations of the rule along that cost axis.
- **D2 Core idea and algorithm design**: GCG's stated philosophy is that decomposition-based algorithms such as branch-price-and-cut can be applied to MILPs routinely and without the user's interaction, as branch-and-cut is. GCG detects a structure, reformulates, and solves the node relaxations by column generation (or by Benders cut generation) (p. 70). What GCG 3.5 changes:
  - the detection loop is refactored, with classifiers turned into plugins, the decomposition classes renamed and the legacy (pre-3.0) detection removed (pp. 70–71);
  - strong-branching-based candidate selection is added for branch-and-price (pp. 71–74);
  - a Python interface, a visualization suite and new website documentation are added (pp. 76–78).

  What does not change: the branching rules themselves (original variables, Vanderbeck's generic branching, Ryan–Foster; p. 71) and the defaults (strong branching stays off; p. 73). The strong-branching idea uses a degree of freedom that branch-and-cut lacks: candidates can be evaluated with or without column generation (SBw/CG, SBw/oCG; pp. 71–72). Hierarchical strong branching filters in three phases: a cheap score (pseudocost, most fractional or random), then SBw/oCG, then SBw/CG for the last few candidates, with more effort at nodes whose estimated subtree is larger (pp. 72–73). Hybrid branching (depth limits) and reliability branching (pseudocost counts) combine with it into hybrid hierarchical and hierarchical reliability branching, and all variants are one implementation with different parameter settings (p. 73). In the co-signed rest of the report, the MINLP rewrite keeps the original constraints and handles the extended formulations implicitly by annotating expressions, with structure detection moved into nonlinear-handler plugins (pp. 20–21, 25).
  - Transferable: when evaluating a candidate is expensive because of an inner loop (here pricing), list the evaluation modes along that loop (none, partial, full) and spend the full mode only on candidates that survive the cheaper ones (pp. 72–73).
- **D3 Problem class and data model**: SCIP treats MILP (1) and MINLP (2) as constraint integer programs. Nonlinear functions must be given in algebraic form from base expressions known to SCIP (pp. 2–3). GCG targets MILPs with a structure that admits a decomposition, such as a block-angular constraint matrix. The resulting master and subproblems are usually MILPs, and the subproblems are solved as sub-SCIPs or by specialized solvers (p. 70). Part of detection's data model is the modeller's: classifiers group constraints and variables by any decomposition-relevant information, "like type or name". Detectors then assign master or block roles over several rounds and usually find many candidate decompositions (p. 70). Ryan–Foster branching applies only to set-partitioning masters (p. 71). The strIPlib test instances are all known to contain a structure to which a Dantzig–Wolfe reformulation applies (p. 73). The capacitated p-median example supplies the textbook decomposition of Ceselli and Righini [20]: assignment and p-median constraints in the master, one capacity constraint per block. Automatic detection stays available (p. 76). SCIP's two decomposition heuristics need a user decomposition: PADM one with linking variables only, DPS one with linking constraints only (pp. 13–14; KH and DW per p. 82). No correctness argument is given for any GCG component (n/a). Elsewhere the assumptions are those of the cited results, e.g. Salvagnin's for SST cuts (p. 8), and the normalization (A) of variable lower bounds, reached by four preprocessing steps, for mixing cuts (p. 12).
  - Transferable: in structure detection, classify constraints and variables by type and by name before searching for blocks. The report calls this classifier concept empirically very successful but gives no count (p. 70), so measure it on your own models.
- **D4 Algorithm and implementation design**:
  - Detection (EM): PARTIALDECOMP objects (formerly Seeed) hold partial or finished decompositions, and DETPROBDATA (formerly Seeedpool) manages them. Constraint and variable classifiers are plugins that produce ConsPartition and VarPartition objects (pp. 70–71). The default flow is presolve, detect, solve. Detection on the unpresolved model has to be started by hand, and a second detection round on the presolved model still follows (pp. 70–71).
  - Strong branching (OG): it is implemented in SCIP's probing mode, and the columns generated during SBw/CG evaluation stay in GCG's column pool; that side effect has not been evaluated (p. 73). It is enabled per rule with branching/orig/usestrong or branching/ryanfoster/usestrong, and it then runs hybrid hierarchical branching by default (p. 73). Table 7 lists the controls (p. 74):
    - minimum and maximum candidate counts per phase, and node-gap weights that set how many candidates pass;
    - the fraction of phase-0 candidates chosen by historical strong-branching performance;
    - caps on simplex iterations and pricing rounds, set to twice the average when the parameter is 0;
    - immediate selection of a candidate with an infeasible child;
    - a look-ahead limit;
    - a switch-off: strong branching stops entirely after the phase-0 choice has been close to the phase-2 choice a set number of times in a row (closepercentage, maxconsecheurclose);
    - depth limits per phase, κ1⁺ = λ1depth + ρdepth · log_λbase(ncands).

    Preset settings files for every selection heuristic and a template ship in GCG's settings folder (p. 73). Strong branching is available for original-variable and Ryan–Foster branching but not for Vanderbeck's (Table 6, p. 72; p. 73).
  - Library use (SS): core functions moved out of the dialog handlers into a public interface (gcgtransformProb(), gcgpresolve(), gcgdetect(), gcgsolve() and getters for bounds and gap), so that PyGCGOpt and C/C++ programs can call them. Detectors and pricing solvers can be written in Python (p. 76).
  - Instrumentation (TD): Python scripts read the .out, .res and .vbc files written by make test STATISTICS=true. make visu builds a testset report (one run) and a comparison report (two or more runs), and a Jupyter notebook filters and plots (pp. 76–77). Figure 7 is a bubble plot of where variables were found, per pricing round and pricing problem (p. 77).
  - Proofs or invariants: none in §10 (n/a).
  - Rest of the report (other authors):
    - SST cuts handle symmetries of general variables through leaders, orbits and stabilizers (Salvagnin), with rules for choosing leaders; suborbitopes are detected by greedily collecting permutations made of 2-cycles (pp. 8–9; JvD, CH, MP).
    - Minimal cover inequalities for symresacks are separated in linear time, because the auxiliary graph's components are paths or cycles (pp. 10–11).
    - Mixing inequalities are separated by the Günlük–Pochet procedure in O(|N| log |N|) (p. 13; WC, MP).
    - Cut cleanup bounds the coefficient range by 10^7, scales the largest coefficient into [10^-4, 10^4] and relaxes coefficients within 10^-9 of an integer (p. 34).
    - When enforcement admits weak cuts, a cut's violation must still be at least 2^-50 max(|b|, max_j |a_j x̂_j|), a floor tied to the 52-bit mantissa (p. 36).
    - Ipopt's local-infeasibility claims are checked against the Berthold–Witzig criterion (p. 58).
    - PaPILO applies reductions in a deterministic, transaction-based order and now postsolves dual solutions and bases (pp. 62–63).
  - Transferable: implement a family of selection rules as one parameterized code and ship each rule as a preset settings file. Comparing ten variants side by side is then a loop over settings files (pp. 73, 113–114).
  - Transferable: give an expensive evaluation an exit test: stop strong branching after k consecutive nodes where the cheap rule's pick is within a set fraction of the expensive rule's best score (p. 74).
- **D5 Computational evaluation**:
  - GCG strong branching (§10.2.3, Appendix B). The comparison is called preliminary and covers original-variable branching only (p. 73).
    - Test set: 73 instances (Appendix B "total (73)", p. 113) from the unreleased strIPlib, all with a structure to which a Dantzig–Wolfe reformulation applies. Instances were kept if they needed at least 1,000 nodes with a previous GCG version, and diversity was controlled much as in the MIPLIB 2017 benchmark selection; details are deferred to Gaul's thesis [36] (p. 73).
    - Setup: Intel Xeon L5630, 2.13 GHz, 16 GB, time limit 3,600 s. Threads, seeds and repetitions are not stated (p. 73).
    - Baseline and variants: pseudocost branching (entries that beat it are set in italics, p. 113), against random, most fractional, SBw/oCG, SBw/CG (full strong branching), hierarchical, hybrid, reliability, reliability hierarchical and hybrid hierarchical (pp. 113–114).
    - Metrics: geometric mean (no shift stated) and arithmetic mean of time and nodes, the number of instances on which each variant is best, timeouts, totals, and per-instance tables of time and nodes (pp. 113–114; Figure 6, p. 75).
    - Results: hybrid hierarchical has the lowest geometric mean time, 108.4 s against 149.9 s for pseudocost (ratio 0.72 [computed]), 1 timeout against 5, and the best time on 22 of 73 instances against 14 (p. 113). Full strong branching with column generation has the smallest geometric mean node count (418.7 against 2,689.8, p. 114; its timed-out runs enter with the count reached at the limit, marked ">"), but it is the slowest (343.0 s) and has 17 timeouts (p. 113). Losses are visible per instance: on d25 03 alternative, hybrid hierarchical takes 837.5 s against 336.7 s for pseudocost (p. 113). There is no general-purpose set showing no harm, and no second library.
  - SCIP 8.0 against 7.0 (§2; authorship not assigned on pp. 82–83):
    - Protocol: out of the box, without tuning (p. 4). 347 MILP instances from MIPLIB 2003, 2010 and 2017 and COR@L, and 113 MINLPLib instances, each solved by at least one version with at least one of five seeds. Five seeds each give 1,735 and 565 runs, with a limit of 7,200 s and one single-threaded run per machine on identical machines (p. 4).
    - Metrics: shifted geometric means with shifts of 100 nodes and 1 s. Runs with numerically inconsistent results are excluded (p. 4). Table 1's "all" row lists 1,708 of the 1,735 MILP runs and Table 2's 558 of the 565 MINLP runs; the text does not count the exclusions (pp. 4–5) [computed].
    - Subsets: difficulty brackets, "affected", "diff-timeouts" and "both-solved". The MILP gain on both-solved instances is only 1.12, which the text reads as most of the speed-up coming from newly solved instances (Table 1, p. 5).
    - Losses: convex MINLPs got slower. The syn group's shifted geometric mean went from 87.01 s to 1,685.14 s, and 10 rather than 26 of its 30 instances are solved (Table 3, p. 6).
  - New against classic MINLP handling (§4.14). 1,678 MINLPLib instances, each also run in two permuted copies, give 5,034 jobs with a 1 h limit (p. 59). A run counts as failed if its bounds conflict with the best known bounds, if it aborts, or if it does not stop at the limit. Runs whose final solution is infeasible are counted separately, 481 classic against 49 new. A version counts as "fastest" when it is at most 25% slower. Performance profiles cover time and gap (pp. 59–61). The new code solves about 400 more and about 200 fewer (p. 59).
  - Other components: the mixing separator is neutral on the internal MIP benchmark and gives a 20% speed-up with 15 more solved on 90 chance-constrained lot-sizing instances (p. 13). DPS finds a feasible solution in 17 of 80 MIPLIB 2017 cases, with no general improvement (p. 15). PaPILO 2.0 is about 5% faster on the MIPLIB 2017 benchmark with 16 threads (Table 5, p. 64).
  - Transferable: select a component's test set by its difficulty under the previous version (at least 1,000 nodes), control family diversity as the MIPLIB 2017 selection did, and publish per-instance time and node tables with counts of wins and timeouts (pp. 73, 113–114).
  - Transferable: in a version comparison, report difficulty brackets plus "both-solved" and "diff-timeouts" next to "all", so that a speed-up from newly solved instances is not read as a speed-up on instances both versions solve (Table 1, pp. 4–5).

**Transferable techniques**:
- Tiered strong branching for branch-and-price: filter candidates by a cheap score, re-rank the survivors by strong branching without column generation, and run column generation only for the last few. Scale the number of survivors with the node gap and the estimated subtree size, and cap simplex iterations and pricing rounds at twice their running average (pp. 72–74).
- Give the expensive evaluator an exit: stop strong branching after a set number of consecutive nodes where the cheap rule's choice is within a set fraction of the strong-branching winner's score (closepercentage, maxconsecheurclose; p. 74).
- Build a family of rules as one parameterized implementation, ship each rule as a preset settings file plus a template, and compare all of them on the same instances with per-instance time and node tables, win counts and timeouts (pp. 73, 113–114).
- Choose a component's test set by difficulty under the previous version (at least 1,000 nodes) and control diversity across instance families as the MIPLIB 2017 benchmark selection did (p. 73).
- In version comparisons, split the results into difficulty brackets, "both-solved" and "diff-timeouts", and state the exclusion rule. Then a speed-up from newly solved instances is visible as such (Table 1, pp. 4–5).
- Count failures against best known bounds, count a final solution that is infeasible for the original problem as a separate failure, and add permuted copies of every instance to expose variability (pp. 59–60).
- Expose the decomposition solver as a library (transform, presolve, detect, solve) so that a modelling layer can try branch-and-price on an existing model, with or without a user decomposition (p. 76).
