- **D1 Problem and entry point**: The entry is the release itself: describe the "new features and enhanced algorithms" of version 5.0 and the speed gained over SCIP 4 when SCIP is used out of the box for MIP and MINLP (pp. 3, 6). The measurement problem comes first. Indicative results "require a careful benchmarking methodology", because changes that are neutral from a mathematical point of view cause performance variability (Danna; Lodi and Tramontani). This "poses a challenge to the accurate evaluation of deterministic, that is, systematic changes" (p. 6). The test-set problem is posed with a count: the 87 MIPLIB 2010 benchmark instances "often are too few in order to obtain robust results" (p. 6). Each component section then starts from a specific shortfall of SCIP 4:
  - aggregation and cut generation were one routine, so one base inequality could not be reused for several cut types (p. 18);
  - flowcover cuts were separated only from single rows (p. 19);
  - general MIP cuts and the cut pool were used only at the root (p. 18);
  - there was no symmetry handling at all ("for the first time", p. 5; p. 13);
  - the analysis of bound-exceeding LPs was off by default (p. 21);
  - LNS heuristics that fix no variables themselves, such as Local Branching, had been switched off "because of their expensive runtime behavior" (p. 24);
  - McCormick relaxations miss the convex hull when further linear constraints act on the two variables (p. 20).
  - Transferable: open a release or component paper with the measurement problem (variability, test-set size) before the features, so that every later number is read against it (p. 6).
- **D2 Core idea**: There is no single idea. The claim is that many component changes, each measured, add up to factors of 1.41 (MIP) and 1.17 (MINLP) over SCIP 4 (pp. 3, 8-9). The report's own list of the main changes (p. 5):
  - cut management (pp. 17-18): the score becomes a convex combination of efficacy, objective parallelism and integral support (after Wesselmann and Suhl); parallelism moves from the score into a filter with maximum 0.1, relaxed to 0.5 for cuts scoring at least 0.9 of the round's best; global cuts go only to the cut pool, which is separated at every depth that is a multiple of 10; separators also run at local nodes;
  - an aggregation API decoupled from cut generation, double-double arithmetic and a post-processing step (p. 18); CMIR and lifted flow cover from one base inequality (p. 19);
  - dual solution analysis of bound-exceeding LPs (p. 21);
  - ALNS, which coordinates eight LNS heuristics under one budget by a bandit rule (pp. 23-24);
  - symmetry detection with orbital fixing (default) or symretope separation (pp. 13-16);
  - stronger McCormick relaxations (p. 20);
  - SoPlex polishing activated in probing and diving (p. 28).

  Described as background, not as changed: the centrally coordinated branch-cut-and-price core with its callbacks (pp. 4-5). Zimpl is not updated and GCG gets only bugfixes (p. 5). The idea in his own component (with Müller and Serrano, p. 37): for each bilinear term in a nonconvex quadratic constraint, solve auxiliary LPs (9) that move from a corner s of the variable box towards a corner t over the linear relaxation R. If t is not reached, the optimal duals aggregate R into a valid inequality α_i x_i + α_j x_j ≤ α_0 (10). Up to four such inequalities per term form a polytope, which Locatelli's convex-hull formulas then use (p. 20).
  - Transferable: when a convex-hull result needs side constraints that the model does not state, generate them from the relaxation with small auxiliary LPs and read each one off the LP duals (p. 20).
- **D3 Problem class and data model**: MIP (1) with bounds in the extended reals and integer index set I (p. 4). MINLP (2) with possibly nonconvex f and g_k, "given explicitly in algebraic form, using only operators that are known to SCIP" (p. 4). CIP: once all integer variables are fixed, an LP or NLP must remain (p. 5). Assumptions of single components:
  - Symmetry: handled for binary variables only; symmetries of other variables are ignored (p. 13). The group used is the formulation group Γ(A, b, c), found by graph automorphism, because computing all symmetries is NP-hard (p. 13). Lemma 2.1 needs F0 and F1 from symmetry-independent methods (p. 15). Every other component that might break symmetry must be switched off, "Otherwise, SCIP may declare a feasible but non-optimal solution as optimal" (p. 16).
  - Nonzero cancellation: by default only when the equality's support lies inside the other row (W = ∅). It skips rows whose integrality, ±1 coefficients, set-packing, covering, partitioning or logicor type, or lock structure it would destroy, and keeps |λ| ≤ 1000 "as in [5]" (Achterberg et al.) (p. 11).
  - Disaggregation needs block-separable quadratic constraints. Non-separable splits are rejected because a convex constraint can split into nonconvex pieces (x² + 2xy ≤ z1) and propagation on the original is stronger (p. 12).
  - Bilinear strengthening acts only on terms that appear in at least one nonconvex quadratic constraint (p. 20).
  - The CMIR and flowcover gains depend on fixed-charge network structure: network design, lot-sizing, unit commitment (p. 19).
  - Libraries used: COR@L and the five MIPLIB versions up to 2010 (all 361 MIPLIB 2010 instances), MINLPLib2 (p. 6); Margot's 16 symmetric instances (p. 16); UFCN (83) and ULSB (65) (p. 19); CBLIB (194 MISDP instances) plus 126 compressed-sensing instances (p. 34).
- **D4 Algorithm and implementation design** (devices and invariants):
  - Clique table: implication graph over literals and Tarjan's SCC algorithm. The literals of one SCC are equal and are aggregated; a path u → ū fixes u = 0. A second Tarjan run, started from the last node of the topological order, finds more fixings. Cliques are handled implicitly so that each is entered at most twice (after Achterberg), which avoids the quadratic arc count (p. 10).
  - Nonzero cancellation: subtract λ times equality i from row r. The nonzero count drops by |U| − |W|, and the step is applied only when this is positive. Candidate pairs are found by hashing (coefficient, index) quadruples of variable pairs instead of a quadratic search over row pairs (pp. 10-11).
  - Disaggregation: (5)-(6) is equivalent to (4). Without it, a relaxation may need ∏ m_p inequalities. Partition size is capped at 127. The new constraints are scaled so that a solution feasible for them is also feasible for the original (p. 12).
  - Symmetry (pp. 13-16): FD inequalities with coefficients 2^(n-1), …, 1 are rejected because they "may cause numerical instabilities" (p. 13). Symresacks get ternary IP formulations from minimal covers (Balas-Jeroslow), separable in O(n α(n)) (p. 14). Orbisack facets are separable in linear time (p. 14). Full orbitopes are separated through n−1 orbisacks in O(mn) and propagated row by row, recursively, in O(mn) (p. 15). Orbital fixing uses the subgroup Σ generated by the generators that keep B1 invariant, valid because Σ(i) ⊆ Stab_Γ(B1)(i) (pp. 15-16).
  - Cuts: efficacy is the Euclidean distance of the LP point to the cut, parallelism the cosine (p. 17). The cut-pool threshold η is adapted after Andreello et al. (p. 18). Post-processing enforces a maximal dynamism by cancelling small coefficients with bounds, scales, and strengthens coefficients (p. 18). CMIR scores rows by how much the LP point's fractionality drives their activity and prefers equalities with a single active continuous variable. Efficacies for k scaling factors cost O(k·n + m) instead of O(k·(n + m)) once the continuous part is aggregated (p. 19).
  - Bilinear LPs run inside the existing `prop_obbt` after the OBBT LPs, with the same per-call iteration limit and a total budget set by a parameter. The inequalities reach `cons_quadratic` through `SCIPaddBilinearIneqQuadratic` and are used only in term-wise separation (p. 20).
  - Dual solution analysis: a dual solution of (12) with value above the cutoff z* gives inequality (13), "globally valid, but violated for all x ∈ [ℓ′, u′]". Dual-ray analysis is the special case c = 0, z* = 0 and shares one implementation for filtering, storage, propagation and removal (p. 21).
  - Heuristics: fix-and-propagate now backtracks after infeasible fixings (p. 22). MPEC: Algorithm 1 with θ = 1/8 and σ = 1/2 (pp. 22-23). ALNS: a UCB bandit whose reward weighs success against cost, an adaptive target fixing rate (after Rothberg), generic fixing priorities by proximity in the variable-constraint graph with ties broken by reduced costs and pseudo costs, and Local Branching started with about 45% of the variables fixed (pp. 23-24). The bandit algorithms UCB, ε-greedy and Exp.3 become a public API (p. 25).
  - Numerics: double-double arithmetic after Rump represents a number as an unevaluated sum of two doubles, needs no branches, and computes the exact sum of two doubles in 6 additions. It is used in MIP cut separation (p. 25). For every checked solution the maximum absolute and relative violations of rows, constraints, bounds and integrality are computed. They are a lower bound, tight only when every involved handler implements the update (p. 26). SoPlex now drops zero entries, matching new LP-interface checks, "to make behavior of different LP solvers as consistent as possible" (p. 29). The aggressive scaling (geometric, up to eight passes, then equilibrium) is meant for numerically difficult instances and is available only through a flag (pp. 28-29).
  - SCIP-SDP warmstarts: the rounding problems (P-R) and (D-R) are LP restrictions with optval(P-R) ≤ optval(SDP-P) ≤ optval(SDP-D) ≤ optval(D-R). Equality certifies the SDP optimum by LPs alone. If (P-R) is dual infeasible or its value exceeds the cutoff, the node is pruned without an SDP solve (pp. 32-33). Projection P_λ clips the eigenvalues at λ (14) (p. 32).
- **D5 Computational evaluation**:
  - Test sets (p. 6). MIP: COR@L plus five MIPLIB versions, minus MIPLIB 2010's "numerically unstable" instances and duplicates, gives 666. Keeping the instances solved by at least one of SCIP 4.0.0, 4.0.1 or intermediate SCIP 5 versions on at least one of five seeds gives 417, 19 of them infeasible. MINLP: MINLPLib2, cut to 143 by manual inspection and heuristic filtering (overrepresented types, instances "numerically troublesome by construction"), then by the same solvability rule (SCIP 4.0.0 and a SCIP 5 release candidate) to 105. The direction of the filter's bias is stated as conservative (Quote 1).
  - Protocol (pp. 6-7): SCIP 5.0.0 + SoPlex 3.1.0 against SCIP 4.0.0 + SoPlex 3.0.0. Third-party versions are listed: GCC 5.4, Ipopt 3.12.5 with MUMPS 4.10, CppAD 20160000.1, bliss 0.73 with a patch; SCIP 4 has the same Ipopt and CppAD and no bliss. Five seeds including the default zero: the random seed for MIP, the permutation seed for MINLP "because this yielded a higher variability". Each (instance, seed) pair is one observation. Means are shifted geometric means with shifts 1 s and 100 nodes; times below 0.5 s are raised to 0.5 s; unsolved runs count separately and enter the means at the time limit. One job per machine (MIP on Xeon E5-2670 v2 at 2.5 GHz, MINLP on E5-2660 v3 at 2.6 GHz, 128 GB). Non-exclusive runs, with a slightly raised time limit, were used only to collect the test sets.
  - Subsets (pp. 7-8): "all" drops runs with errors, "including cases where the primal and dual bounds returned were inconsistent with a known optimal objective value". Brackets [s, T] are defined by the slower version and require at least one version to solve, with a reason for each exclusion: unsolved-by-both runs only act "as a constant scalar", and the lower cut selects hard instances "if they are hard for any of the solvers". Further rows: diff-timeouts; MIPLIBs vs COR@L; integer vs continuous. Limits: MIP 7200 s with zero gap; MINLP 3600 s, because few instances finish between one and two hours, with relative gap 10^-4, motivated by an observation the authors say they have not quantified (p. 8).
  - Results. MIP, Table 1 (p. 8): 2069 observations, timeouts 403 → 217, time factor 1.41, node factor 2.65; [100,7200] 2.07; [1000,7200] 3.53; diff-timeouts 6.94; MIPLIBs 1.27, COR@L 1.52. MINLP, Table 2 (p. 9): 515 observations, timeouts 125 → 105, time 1.17, nodes 2.47; [1000,3600] 1.74; continuous 1.23, integer 1.15. My arithmetic: 417 × 5 = 2085 and 105 × 5 = 525, so 16 MIP and 10 MINLP observations were dropped as errors or bound inconsistencies. The report gives neither the count nor the instances (pp. 6-9; inferred).
  - Component results are explicitly not to the release standard: other setups, intermediate code, other test sets, mostly one seed (p. 9; Quote 2). The numbers:
    - clique table +1.8% on the MIP set and +5.7% on [100,7200] "At the time of addition" (p. 10);
    - nonzero cancellation neutral, +2 solved, 3-6% on [1000,7200] and MIPLIB (p. 11);
    - symmetry on the MIPLIB 2010 benchmark (i3 3.2 GHz, 1 h, seed zero): orbital fixing 13.0% faster and 77 vs 75 solved, polyhedral 9.5% faster; on Margot's instances orbital fixing 72.9% faster and 11 vs 6 solved, polyhedral 91.6% faster and +8 solved; on the full MIP set, switching symmetry handling off costs 12%, and 57% on [1000,7200] (pp. 16-17);
    - {0,1/2}-cuts 3-5%; macrophage solved in under 200 s "consistently over several random seeds" (p. 18);
    - UFCN 3.21 and ULSB 227.36, against SCIP 4.0.1 + SoPlex 3.0.1 (Table 3, p. 19);
    - bilinear relaxations: 398 MINLPLib2 instances affected, root gap −40% under aggressive separation, +2 solved over five permutations (p. 20);
    - dual solution analysis 1.02 (MIP set) and 1.06 ([1000,7200]); on MIPLIB 2010 1.07 in time and 1.12 in nodes (p. 21);
    - structure heuristics: time unchanged, +4 solved, primal integral −3%, time to first solution −11%; on COR@L −4% time and −10% primal integral (p. 22);
    - MPEC: 42 calls, 6 improving solutions, 2 of them optimal (p. 23);

    - polishing 6%, over 10% on [100,7200], seed zero (p. 28);
    - SCIP-SDP (Table 5, 320 instances, SDPA 7.4.0, preliminary versions): solved count, shifted geometric means of time and of SDP iterations (shift 1000), shares of penalty-formulation solves and of unsolved relaxations (p. 34);
    - UG-MISDP on one instance: up to 27× with 64 threads, with the node-count variability flagged (p. 36).
  - Failures and slowdowns reported: SCIP 4 is faster on a few easy UFCN instances (p. 19). Of the SDP warmstarts, the unadjusted one is "not a good idea", earlier iterates and the analytic center do poorly, the 1% convex combination (fastest on two instance sets) is 41% slower than a cold start on truss topology, and the rounding problems cost too much, with the dual rounding problem "failing regularly" (pp. 34-35).   - component numbers come from intermediate versions and other setups, mostly with one seed (p. 9);

**Method links**:
- Method 6 ✅ evidence. The development test set is an instrument built by written rules, with counts at each step: 666 → 417 (19 infeasible) for MIP, 143 → 105 for MINLP. Instances that MIPLIB 2010 flags as "numerically unstable" are removed. The direction of the filter's bias is argued (p. 6). The limits of the instrument are printed: the MIPLIB 2010 benchmark is too small for robust results, the MINLP sets are less diverse (pp. 6, 9). Cross-check for the instrument chain (S002 text, file pp. 13 and 17; only these passages read): MIPLIB 2017 computed its features after a trivial presolve with SCIP 5.0, and its "Constraint classification" feature group uses the same 17 linear-constraint types that SCIP 5.0 ships as `display linclass` (pp. 26-27 here), the tool Hendel built "together with AG" (p. 37).
- Method 2 ⚠ variant. The release form compares default SCIP 5.0.0 + SoPlex 3.1.0 with default SCIP 4.0.0 + SoPlex 3.0.0, lists every third-party version and names the mismatch: a different SoPlex, no bliss in SCIP 4 (p. 7). The co-released LP solver counts as part of the treatment, and no reduced baseline is built. Like-for-like comparisons are done by switching one component in one build, for example default orbital fixing against no symmetry handling (p. 16). Table 3 changes the baseline to SCIP 4.0.1 + SoPlex 3.0.1 without comment (p. 19). Later releases add the latest bugfix release as a second baseline (Method 2 step 10).
- Method 3 ✅ evidence. Gaps are printed where they arise, with a size or a cause: symmetry for binaries only (p. 13); the bilinear evaluation still to be done (p. 20, in AG's own component); further uses of several NLP solvers not implemented (p. 27); SDP rounding problems that cut off over 25% of the infeasible relaxations on one instance set and over 50% of all relaxations on another but cost too much, with two named remedies, which is a lost experiment read as the next step (p. 35); UG-MISDP analysis pending (p. 36); bandit selection for other components, with the API already public (pp. 24-25). Most of this is group work.
- Method 5 ⚠ variant. In floating-point SCIP 5 precision is raised only where round-off threatens validity. Cut aggregation and generation use double-double; GMP-style arbitrary precision is ruled out as "orders of magnitudes slower" (p. 25). The accuracy gained is spent on deleting cut-rejection rules that existed for numerical reasons, such as rank limits and small integral scaling factors (p. 18). Numerically dangerous constructions are avoided by design: FD inequalities with exponential coefficients (p. 13), |λ| > 1000 in nonzero cancellation, where AG is a co-implementer (pp. 11, 37), and unscaled disaggregated quadratics (p. 12). This is a cheap mid-precision step in a cut generator, ahead of the later safe cuts, not the produce/decide split with exact arithmetic.
- Method 4 ⚠ variant. Correctness is screened, not certified. Runs whose bounds contradict a known optimal value are dropped from "all" (p. 7). Accepted solutions report their maximum violations, as a lower bound (p. 26). The symmetry section names the component interaction that would make SCIP call a non-optimal solution optimal (p. 16). The release has no independent checker and no exact verification.
- Method 1 ⚠ variant. The solver carries instruments for variability: the centralized random seed of SCIP 4 and the permutation seed are means "to trigger performance variability systematically" (p. 6). One belief stays unmeasured and is labelled as such: the MINLP gap limit 10^-4 rests on a "repeated observation" that spatial branch and bound suffers more variability near small gaps, which the authors say they have not quantified systematically (p. 8).
- Heuristic 3 ✅ evidence. Each default rests on a measurement dated to its merge: clique table analysis (p. 10), the new {0,1/2}-cut separator (p. 18), the analysis of bound-exceeding LPs, off by default in SCIP 4.0 and on in 5.0 after 1.02/1.06 (p. 21), ALNS (p. 24), and polishing in probing and diving, which AG co-implemented (pp. 28, 37). Components stay off or are restricted where they do not pay: SCIP-SDP warmstarts are off (p. 35), MPEC runs with conservative limits (pp. 22-23), aggressive scaling needs a flag (p. 29), and polishing stays out of strong branching and OBBT, "which are not focused at finding primal solutions" (p. 28).
- Heuristic 7 ✅ evidence. Each component gets its metric: primal integral and time to first solution for the fix-and-propagate heuristics (p. 22); calls, improving finds and optimal finds for MPEC (42/6/2, p. 23); root gap for the bilinear relaxations (p. 20); SDP iterations and the shares of penalty and unsolved relaxations for warmstarts (p. 34). Null results are said plainly (pp. 11, 22, 34-35).
- Heuristic 8 ✅ evidence. Five seeds per instance, each (instance, seed) pair one observation (p. 7), four years before the three-seed sentence the skill quotes from 2021. Brackets come with the reason for each exclusion, plus a diff-timeouts row and per-library subsets (pp. 7-8); shifts, a 0.5 s floor, and unsolved runs charged the time limit (p. 7); the collection filter's bias is argued (p. 6); a time-limit bias is footnoted: a shorter limit "slightly favors the weaker solver" (p. 16). ⚠ variant: the exclusions for errors and bound inconsistencies are neither counted nor named (16 MIP and 10 MINLP observations by my arithmetic, pp. 6-9).
- Heuristic 9 ✅ evidence. Use what the solver has already computed: AG's bilinear strengthening reads valid inequalities off the duals of auxiliary LPs solved inside the existing OBBT propagator and its iteration budget (pp. 20, 37). Witzig's dual solution analysis turns the dual of a bound-exceeding LP into a globally valid propagation constraint (pp. 21, 37).

**Transferable techniques**:
- Build a development test set as a funnel and state the count at each step: a broad public pool; minus instances flagged unstable and duplicates; old and new versions run with five seeds, non-exclusively, at a slightly raised time limit; keep the instances solved by at least one version on at least one seed. Then say in which direction the filter biases the comparison (p. 6).
- Report brackets [s, T] defined by the slower version and requiring at least one solve, plus a diff-timeouts row, with each (instance, seed) pair as one observation. Floor times at 0.5 s, use shifts of 1 s and 100 nodes, and charge unsolved runs the time limit while counting them separately (pp. 7-8).
- Choose the perturbation by problem class: whichever of the random seed or the permutation seed produces more variability (MIP: random seed; MINLP: permutation seed, p. 7).
- When a component study uses a shorter time limit or another machine, footnote the direction of the bias: a shorter limit "slightly favors the weaker solver" (p. 16).
- For a reduction that relies on an invariant (here symmetry), list the components that must be switched off and the wrong answer that follows otherwise (p. 16).
- Run aggregation-heavy cut generation in double-double, which is branch-free and needs 6 additions for an exact sum, then delete the rejection rules that existed only because of round-off (pp. 18, 25).
- After a reformulation, scale the new constraints so that feasibility within tolerance for them implies feasibility for the original constraint (p. 12).
- Report the maximum absolute and relative violation of every accepted solution, and call it a lower bound when not every constraint handler computes it (p. 26).
- Rate a primal heuristic by calls, improving finds and optimal finds (42/6/2), and by primal integral and time to the first solution, not only by solving time (pp. 22-23).
- In a multi-author software paper, add a section that names the implementers of each feature (pp. 37-38).
