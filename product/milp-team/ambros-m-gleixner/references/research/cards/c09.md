**Role**: core · **Coauthors**: 28 authors, Gerald Gamrath first and the other 27 in alphabetical order, Gleixner eighth (p. 3) · **Position in trajectory**: the SCIP release after 6.0. In this report's reference list the SCIP 5.0 and 6.0 reports carry Gleixner as first author (refs. [35], [36], pp. 43-44); here he is an alphabetical co-author. - **D1 Problem and entry point**: A release report: it documents what version 7.0 adds (abstract, p. 3) and frames performance as the development target, since use "as an out-of-the-box solver" makes MIP and MINLP performance "of particular interest during the development process" (p. 6). The component sections enter in four ways:
  - an architecture limit: SCIP's constraint-based view "deprives SCIP of a global view on the constraint matrix", which motivates PaPILO as a separate matrix-based presolve library (p. 9);
  - a count: in a study by Witzig et al. only 5% of infeasible LP relaxations in MINLP solving yielded a globally valid infeasibility proof, which motivates locally valid dual proofs (p. 24);
  - a user experience: the gap closes to 99% within seconds while most of the runtime goes to the last 1%, which motivates tree-size estimation as a "progress bar" (p. 26);
  - reproducible failure modes: wrong results when an unconstrained auxiliary variable is fixed in a sub-SCIP and the fixing is copied back (relaxation-only variables, p. 36); enforcement stuck when the LP returns x = 2.000001 for a variable fixed to 2 under x^5 = 32 (p. 36).
  - Transferable: open each component section with its entry point (a measured count, a design limitation, or a reproducible failure) in one paragraph before the mechanism (pp. 9, 24, 26, 36).
- **D2 Core idea and algorithm design**: No single idea; the main additions are:
  1. PaPILO 1.0, with "no novel presolve reductions" (p. 9) but a new parallel scheme borrowed from database systems: presolvers read a shared read-only problem and return reductions as transactions with locks; the core applies them sequentially in a fixed order and discards any whose locks were violated, so the result is deterministic regardless of thread count (pp. 9-10). Data parallelism inside probing, parallel rows and columns, dominated columns and sparsification is load-balanced with Intel TBB (p. 10). Speedup on ex10 is almost linear up to 8 threads (Fig. 1, pp. 10-11). The SCIP plugin rebuilds constraints only if constraints or nonzeros drop by at least 20%, and skips parallel-column removal because SCIP lacks the postsolve (p. 11).
  2. Presolve (§4.1, Gleixner among the implementers): two-row LP-based bound tightening that solves single-row LPs in linear time (Dantzig; Balas and Zemel) and finds row pairs through four hash lists keyed on the sign pattern of variable pairs, under working limits (p. 12); two-column nonzero cancellation (pp. 12-13); complementary slackness on two continuous columns (p. 13).
  3. A decomposition structure (user .dec files, label inference, area score, modularity, block-graph statistics) (pp. 14-16), used by the new padm heuristic, by GINS on blocks (pp. 16-18) and by Benders' decomposition; adaptive diving (p. 16).
  4. Branching: degeneracy-aware hybrid branching divides the dual-bound weight by ψ(α)ω(β) and multiplies the conflict, inference and cutoff weights by it. Here ψ = 10^(10(α-0.7)) for degeneracy share α ≥ 0.8 (eq. 11, as extracted), and ω(β) > 1 for variable-constraint ratio β ≥ 2.0 (eq. 12; the extraction does not show whether it reads 10β or 10^β). Strong branching is switched off when ψω ≥ 10, and standard hybrid branching is kept at the root so that root restarts still fire (pp. 19-20). Further: treemodel Ratio and SVTS scores (pp. 20-22); a "vanilla" full strong branching for experiments and ML oracles (pp. 22-23); lookahead updates (p. 23); branching points pulled toward the domain middle with midpull 0.75 (pp. 23-24).
  5. Locally valid dual proofs, lifted to the highest ancestor at which all local information used was present (pp. 24-25).
  6. Tree-size estimation (sum of subtree gaps, tree weight, leaf frequency, forecasting, monotone linear regression, random forests) and clairvoyant restarts: restart once if estimated completion is below 2% after at least 1k leaves (pp. 26-27).
  7. Symmetry handling by components of the formulation symmetry group, with orbitopes or orbital fixing per component (pp. 27-31).
  8. Benders' decomposition: parallel subproblems, convex MINLP subproblems, in-out cut strengthening, a feasibility phase, three-phase parameters (pp. 31-35); parallel BD through UG (pp. 38-39).
  9. SoPlex 5.0: runtime-selectable arbitrary precision via Boost multiprecision (MPFR if available) and full templatization (pp. 37-38).
  - Transferable: to parallelize a pipeline of reductions without losing determinism, let workers propose reductions as transactions with locks on a read-only copy, apply them in a fixed order, and discard those whose locks were broken (pp. 9-10).
- **D3 Problem class and data model**: MIP (1) with Ax ≥ b, bounds in the extended reals and an integer index set (p. 4); MINLP (2) in explicit algebraic form, possibly nonconvex (p. 4); constraint integer programs in general (p. 5); MISDP (23) for SCIP-SDP (p. 39). Assumptions inside correctness arguments:
  - PaPILO never relaxes variable bounds (p. 10);
  - symmetry is handled for binary variables only, through the formulation symmetry group computed with bliss (pp. 27-28);
  - orbital fixing requires strict setting algorithms (pp. 30-31);
  - BD recognizes convexity only for linear, abspower, nonlinear and quadratic constraints (p. 32).

  Data: on the MMMC set (MIPLIB 3, 2003, 2010, COR@L), 55 instances show no dual degeneracy in the final root LP and 149 have at least 80% degenerate nonbasic variables (p. 19). Test sets: a 514-instance MIP base set drawn from MIPLIB 3, 2003, 2010, 2017 and COR@L with "the selection methodology used to select the MIPLIB 2017 collection" (p. 6); a 200-instance MINLP base set "manually selected from MINLPLib", filtering overrepresented classes and numerically troublesome instances (p. 6); "solvable" subsets of both for routine testing (p. 6).
- **D4 Algorithm and implementation design (invariants and devices; no theorems)**:
  - transaction correctness: locks on the bounds of x and on rows 1-2, together with bounds never being relaxed, keep an implied-free substitution valid "regardless of other transactions" (p. 10); determinism comes from the fixed application order and from sorting non-deterministically ordered results (p. 10);
  - local dual proof validity: proof (19) holds in the subtree of the ancestor q defined by an index-set condition; it is used for dual proof analysis only, not conflict graph analysis, to avoid delta-tree overhead (p. 25);
  - orbital fixing kept correct by storing globally fixed binaries instead of disabling interfering plugins (pp. 30-31); multi-aggregation of affected binaries forbidden (p. 28);
  - parallel BD kept deterministic: all subproblems are solved before cut generation and cuts are added in a set subproblem order (p. 31); a priority queue balances load, with ties broken by subproblem index (pp. 31-32); the feasibility-phase subproblem (22) is always feasible and yields valid underestimators, with M ← 10M while slacks stay nonzero (p. 34); up and down locks on master variables block invalid presolve reductions (p. 34);
  - numerical safeguards: a "numerics" emphasis setting limits dynamism in multi-aggregations and disables numerically critical presolve operations, and "may slightly deteriorate performance" (p. 36); the LP primal feasibility tolerance is tightened temporarily when a constraint handler cannot enforce, then reset (p. 36); gap limit 0 for MIP and relative gap 10^-4 for MINLP (p. 7); SoPlex's higher precision does not adapt tolerances automatically (p. 37).
  - Transferable: when a handler cannot enforce because the LP solution sits inside the LP solver's bound tolerance around a fixed variable, tighten the LP feasibility tolerance for that node, resolve, and reset afterwards (p. 36).

### S029 · Linear programming using limited-precision oracles (Mathematical Programming 183 (1) 2020, DOI 10.1007/s10107-019-01444-6; arXiv 1912.12820)
**Read level**: full (pp. 3-26 read in full, including every proof of §5, pp. 17-22; references pp. 26-27 skimmed; the electronic supplement with per-instance statistics is not in the file: not read). The text is ZIB-Report 19-57 / arXiv 1912.12820v1, which states that its content is also available as the Mathematical Programming article (p. 1).
**Role**: core · **Coauthors**: Daniel E. Steffy, Oakland University (p. 3) · **Position in trajectory**: the theory sequel to iterative refinement for LP (Gleixner, Steffy, Wolter, IJOC 2016, ref. [16], p. 27), which supplies the algorithm, the SoPlex implementation and the 1,202-LP test bed (pp. 8, 22-23). The IPCO 2019 conference version is D001 (work-list note); the file does not mention it. Funded by the Research Campus MODAL (p. 3). Own voice: a two-author paper with Gleixner first and no student lead.

- **D1 Problem and entry point**: Complexity analyses of LP assume exact arithmetic or count bits, "Yet in practice, implementations typically use limited-precision arithmetic" (abstract, p. 3). The classical exact methods (ellipsoid or interior point, then simultaneous Diophantine approximation) need precision far beyond double. Example 1 makes this concrete: for a 3 × 6 LP, the tolerance of Theorem 6.3.2 of Grötschel, Lovász and Schrijver is ε ≈ 10^-169,059 (p. 6), while every vertex has encoding length at most 27 and denominator at most 8 (p. 7). The practically fastest exact methods (QSopt_ex's precision boosting, iterative refinement [16]) had no such theory (p. 7). The paper asks how limited-precision LP oracles can be used to design algorithms "with polynomial running time guarantees" that compute exact solutions (§1.4, p. 8).
  - Transferable: evaluate the textbook worst-case bound on a tiny, "unremarkable" instance and set it beside the actual size of the solution; one number shows why an output-sensitive analysis is needed (Example 1, pp. 6-7).
- **D2 Core idea and algorithm design**: The floating-point simplex becomes an oracle with constants p, η and σ: on the LP rounded to F(p) = {n/2^p : |n| ≤ 2^(2p)}, it either reports failure or returns an approximate primal-dual solution with residuals at most η and complementarity at most σ (Definition 1, pp. 8-9); IEEE doubles lie in F(1074) (p. 8). A "basis oracle" also returns a basis satisfying (6a)-(6b) (p. 9). Algorithm 1 keeps the refinement loop of [16] but uses equal primal and dual scaling, a single violation measure δk, and rounds the scaling factor to a power of two (line 11) (pp. 9-10). Two exact layers sit on top:
  1. basis verification: once the basis has stalled, solve its linear systems exactly and check primal and dual feasibility in rational arithmetic (§3.2, pp. 12-13);
  2. rational reconstruction: round the iterates componentwise by continued fractions with a speculative denominator bound Mk = sqrt(∆k+1/(2β^k)), check each candidate exactly, and retry at a geometric frequency f (Algorithm 2, pp. 14-15).

  Kept from [16]: the loop and the correction step. Changed: scaling rounding, the basis requirement, and the exact layers.
  - Transferable: round scaling or step factors to powers of two so that the encoding length of the iterates grows only linearly with the iteration count (Lemma 4, pp. 10, 18-19).
- **D3 Problem class and data model**: LP in standard form min{c^T x | Ax = b, x ≥ ℓ} with A of full row rank, m ≤ n, and rational data (pp. 3-4); irrational data is set aside (p. 4). Algorithms and Theorems 5 and 7 assume a primal and dual feasible LP (pp. 10, 13, 15, 17); infeasibility and unboundedness are left to the tests of [16] (footnote 3, p. 23). About the oracle, the authors concede that real solvers "are certainly not guaranteed" to stay within fixed residual bounds, but residuals can be computed and checked, so "failure" is detectable (p. 9). Requiring inputs in F(p) forbids the trick of scaling the LP to get arbitrary accuracy in one call (footnote 1, p. 9). Lemma 7's convergence of the iterates rests on bounded corrector solutions: Example 2, a degenerate two-variable LP, has residuals tending to 0 while the iterates diverge (pp. 13-14). Exploited structure: small solution denominators (61 LPs need no exact solve because the floating-point solution is already exactly optimal, 59 of them with integral solutions, pp. 24-25) and nonbasic entries fixed at bounds, which reconstruction skips (p. 22). Test bed: 1,202 primal and dual feasible LPs from Netlib, Mittelmann, Mészáros and the LP relaxations of COR@L and MIPLIB (p. 23).
- **D4 Algorithm and implementation design (proof devices)**:
  - Lemma 1: a denominator bound H from Cramer's rule and Hadamard's inequality (p. 5);
  - Lemma 3 (from [16]): residuals shrink linearly at rate ε = max{η, 1/α}, which bounds the oracle calls by (8) (p. 9);
  - Lemma 4: all numbers have encoding length O(⟨A,b,ℓ,c⟩ + (n+m)⟨τ⟩), shown by writing the iterates as Σ ∆j^-1 nj/2^p over a common power-of-two denominator (pp. 10, 18-19);
  - Lemma 5, a separation bound: a basic solution is either exactly feasible or violates primal feasibility by at least 1/2^(4⟨A,b⟩+5⟨ℓ⟩+2n²+4n), with an analogous dual bound (pp. 11, 19-20);
  - Theorem 4: the bases are optimal after K ∈ O((m²⟨A⟩ + ⟨b,ℓ,c⟩ + n²)/log(1/ε)) refinements. Claims 1-4 bound the infeasibility of the exact basic solution of the current basis by 2^(4m²⟨A⟩+2)ε^k, which then falls below Lemma 5's threshold (pp. 11, 20-22);
  - Lemma 6: an induction showing that (6a)-(6b) make the iterates "more and more basic" (9a)-(9b) (pp. 11-12);
  - Theorem 6: output-sensitive reconstruction after K ∈ O(max{⟨q̃⟩, ⟨C⟩}) rounds, via a geometric-series bound on the tail (pp. 15-16);
  - Lemma 8: a reconstruction frequency f > 1 makes the cumulative cost O((n+m)K²), dominated by the last attempt (pp. 16-17);
  - Theorems 3, 5 and 7: oracle-polynomial running time (pp. 10, 13, 17).

  The authors concede that the bound "may seem surprisingly large" next to the O(√(n+m)⟨A,b,ℓ,c⟩) iterations of interior-point methods, and explain the gap by linear against superlinear convergence (p. 12). Exact arithmetic is used only for residuals, the basis systems (a rational LU adapted from SoPlex's floating-point LU) and the checks (pp. 10, 12, 15, 22). Code parameters: factorization after 2 stalled refinements, β = 1.1, f = 1.2, and DLCM acceleration of reconstruction (p. 22). Cross-reference slip: the proof of Theorem 4 twice cites "Theorem 5" for the thresholds that Lemma 5 supplies (pp. 21-22; the proof sketch on p. 11 correctly names Lemma 5).
  - Transferable: prove finite, polynomial optimality of a basis sequence by a separation bound: nonoptimal basic solutions violate by at least a computable constant, so once the residuals of the exact basic solution fall below it, the basis is optimal (Lemma 5, Theorem 4, pp. 11, 19-22).
  - Transferable: schedule an expensive speculative step (here reconstruction) geometrically, retrying after f·k rounds, and prove its total cost is dominated by the final attempt (Lemma 8, pp. 16-17).

- **D6 Positioning**: Built on
  - Grötschel, Lovász and Schrijver's weak/strong distinction and simultaneous Diophantine approximation (pp. 5-6);
  - Karmarkar's and Renegar's rounding to a basis or an optimal face (p. 6);
  - Edmonds' polynomial linear algebra and Q-method (pp. 6-7);
  - Espinoza's measurement that a naive rational simplex is much slower (p. 7);
  - Gärtner's mixed simplex, basis repair and verification [9, 20, 21], QSopt_ex's incremental precision boosting [3], and Cheung and Cucker's variable precision (p. 7).

  The paper positions itself as the low-precision, practical counterpart to high-precision ellipsoid and interior-point schemes, with a focus "more practical" on standard floating-point solvers (§1.4, p. 8); QSopt_ex is the state of the art it measures against (p. 22). Critique works by reformulation, not attack: the ε of Example 1 is "suitable for establishing polynomial running time" but beyond real computation (p. 7).
- **D7 Writing and rhetoric**: The abstract ends on the practical stake (p. 3). Theorems come with one-paragraph proof sketches, and the technical proofs are collected in §5 (pp. 10-11, 17-22). The paper is candid about the weak worst-case bound and why practice beats it: an optimal basis "is typically reached after very few refinements", so the basis is checked early rather than trusting a priori bounds (p. 12). The experiments open with three bulleted questions (p. 22). Hedging is low. The conclusion turns the measured trade-offs into two concrete next designs (pp. 25-26). Reviewers are thanked for comments "of exceptionally high quality" (p. 26). Slips: the Theorem 5/Lemma 5 cross-reference (pp. 21-22) and the 44-against-39 count (p. 23).
- **D8 Contribution and limits**: Layers:
  - theory: an oracle model with oracle-polynomial and output-sensitive bounds (pp. 8-17);
  - algorithms: two exact extensions of iterative refinement (pp. 12-17);
  - software: implemented in SoPlex, with the code "freely and publicly available for research" (p. 8);
  - computation: 1,202 LPs (pp. 22-26).

  Limits written in: primal and dual feasible LPs only (pp. 13, 17); real solvers do not meet Definition 1's guarantee (p. 9); a large worst-case refinement bound (p. 12); a reconstruction bottleneck for large denominators (p. 24); factorization can dominate the run time (p. 25); 7 oracle failures (p. 23). Future work: a factorization-reconstruction hybrid, most promising as a rational factorization run "in the background" while refinement continues (p. 25); and incremental precision boosting inside iterative refinement whenever the floating-point solver fails (p. 26).

**Transferable techniques**:
- Model a production floating-point solver as a limited-precision oracle with constants (p, η, σ), a failure outcome and inputs restricted to a fixed number set, then prove oracle-polynomial bounds for the exact algorithm built on it (Definition 1, pp. 8-9).
- Use power-of-two rounding of scaling factors to keep encoding lengths linear in the iteration count (Algorithm 1 line 11, Lemma 4, pp. 10, 18-19).
- Use a separation bound on the violations of nonoptimal basic solutions to turn linearly converging residuals into a finite, polynomial optimality guarantee for the basis (Lemma 5, Theorem 4, pp. 11, 19-22).
- Run speculative rational reconstruction with a denominator guess whose safety factor β^k grows geometrically, check each candidate exactly, and retry at geometric frequency f (Algorithm 2, Theorem 6, Lemma 8, pp. 14-17; β = 1.1 and f = 1.2 in the code, p. 22).
- Delay the exact basis solve until the floating-point basis has stalled for 2 refinements (pp. 12, 22).
- Stratify the comparison by the baseline's escalation level and attribute each failure to a stage (Table 1, p. 24; p. 23).
