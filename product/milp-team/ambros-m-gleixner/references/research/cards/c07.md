### S014 · The SCIP Optimization Suite 4.0 (ZIB-Report 17-12 2017, no DOI or arXiv id)
Read level: **full** (pp. 1-74 read in full, including the "Code Contributions of the Authors" paragraph on p. 74; reference list pp. 74-83 skimmed and checked for the Gleixner items [70]-[72] and [85]). - **D1 Problem and entry point**: A release report, not a research question. Its goal is to present the recent changes to the collection, with a focus "on implementation aspects and their computational consequences" (abstract, p. 3). The framing argument: repeated single-purpose solver development (a PhD thesis, one industrial problem) used to suffice, but the field's growth makes flexible software frameworks necessary; the report gives "a snapshot of the development process" in the hope of informing other solver developers (p. 4). Individual features enter from an observed misbehaviour or a motivating application: cycle detection in the variable bound graph from a toy instance on which propagation tightened two bounds until they reached infinity (p. 9); the propagation-loop fix from pre-root heuristics that changed the tree search even when they found nothing, because probing reset constraint-handler flags (pp. 12-13); connectivity-aware clique partitioning from 13 line-planning instances (p. 10); tree-search component handling from supply-network planning (pp. 11-12); the randomization parameters from the risk of over-tuning on fixed seeds (p. 16).
  - Transferable: enter a solver feature from a reproducible misbehaviour (a toy instance, an unintended side effect) and report its effect on the motivating case separately from its effect on the standard set: cycle detection settles the toy instance immediately but yields no reductions on standard MIP benchmarks, so it ships off (p. 9).
- **D2 Core idea and algorithm design**: No single idea: changes across SCIP 4.0, SoPlex 3.0, UG 0.8.3, GCG 2.1.2 (a bugfix release), SCIP-Jack 1.1, PolySCIP 2.0 and SCIP-SDP 3.0 (pp. 4-6, 45, 56, 59, 61, 63, 67); §2.1 alone lists eight technical improvements (p. 6). The cross-cutting design rule is visible in almost every section: each feature ends with a default decision tied to a measurement. Off by default when the standard sets show no gain or a net loss: cycle detection (p. 9), tree-search component handling (p. 12), the KKT reformulation except for pure QPs (p. 30), implication-graph analysis (p. 31), the multi-start heuristic except for continuous problems (p. 34), NLOBBT (p. 36), the gauge and projection separators (pp. 38-39), least-squares scaling (p. 47), LP solution polishing (p. 49). On by default when neutral or better: dual-ray analysis (p. 28), the locks, GINS and LP face heuristics (p. 26), persistent scaling (p. 47), the switch to a row basis when there are at least 20% more rows than columns (p. 56). Infrastructure for measuring the solver itself: a randomization parameter class (randomseedshift, lpseed, permutationseed; Table 1, p. 17) and a deterministic concurrent solver (pp. 39-42).
  - Transferable: end each feature description with its default status, the parameter that switches it, and the measurement that decided it (e.g. propagating/vbounds/detectcycles, p. 9; heuristics/lpface/minpathlen, p. 25; rowrepswitch, p. 56).
- **D3 Problem class and data model**: CIP framework covering MINLP, convex MINLP, MIQCP, MBQP and MIP; a linear objective is assumed throughout (pp. 4-5). Correctness assumptions are stated where an argument is given: nonempty bounded feasible set for the MBQP-to-MBPCC equivalence (pp. 29-30); Slater's condition for the Lagrangian variable bounds of NLOBBT (p. 35); a relaxator's solution is enforced only if the relaxator includes all LP rows (RELAX_INCLUDESLP, p. 15); an interior point of the convex relaxation for the gauge separator, else it is disabled (p. 37). Structures exploited: the variable bound graph (pp. 7-9), connected components of the conflict graph (pp. 9-10), independent sub-problems (pp. 11-12), variable locks (pp. 18-19, 25), connectivity-graph neighbourhoods (pp. 21-23), complementary slackness on continuous columns (pp. 19-20), the row-versus-column dimension of the basis (pp. 54-56). Model libraries: MMM = MIPLIB 3 + MIPLIB 2003 + MIPLIB 2010 benchmark (p. 14); MIPLIB 2010 benchmark, 87 instances (pp. 25-26, 71); a 254-instance conflict set from MIPLIB, MIPLIB 2003, MIPLIB 2010, COR@L, ALU and markshare (p. 28); MINLPLib2 subsets (1367 MINLP and 469 NLP, p. 34; 318, p. 36; the 115 instances used by Mittelmann, p. 72); QP sets BoxQP, RandQP, LibsQP, LibsMBQP (pp. 31-32); 1235 public LPs reduced to 215 (p. 53); four Steiner tree sets (p. 62); 194 MISDP instances (p. 68). Not used anywhere: exact or rational arithmetic. A search of the whole file for the strings exact and rational finds no mention of SoPlex's rational solving mode or of iterative refinement; besides the word exactly, the hits are SCIP-Jack's exact framework and exact reduction methods (pp. 61-62) and rational data in a QP complexity remark (p. 29).
- **D4 Algorithm and implementation design**: Proof devices: aggregation of v-bounds along a cycle, with validity shown by substituting arc by arc, giving either infeasibility or a bound β/(1-α) (pp. 8-9); a one-line change to greedy clique partitioning (partition by connected components first, work limit t_comp = 10^6) (p. 10); KKT-based equivalence of an MBQP and a mixed-binary program with complementarity constraints, with z_j = x_j λ_j removed via complementarity (pp. 29-30); a Lagrangian variable bound derived from the KKT conditions and convexity, "a cheap approximation of NLOBBT in the branch-and-bound tree search" (pp. 35-36), generalising Gleixner and Weltge's CPAIOR 2013 bounds [72] (p. 34); Lemma 4.1, a column basis is regular if and only if the row basis is, via det(M) = det(A_RC̄) = det(N) (p. 55); the Farkas proof constraint of an infeasible LP reused for propagation (pp. 27-28); gauge boundary points by binary search, and projection onto one convex quadratic by eigendecomposition plus Newton's method on a strictly decreasing convex φ(ρ) (pp. 37-39). Numerical safeguards, all inside floating point: SoPlex scaling factors are integral powers of 2, so scaling only changes exponents and adds no roundoff apart from under- or overflow (p. 46); persistent scaling through an interface layer that scales incoming data and unscales outgoing data, including basis-inverse rows used for Gomory cuts (p. 47); NLP feasibility tolerance 10^-8 instead of SCIP's 10^-6 so that an NLOBBT optimum is a valid bound with respect to SCIP's tolerances (p. 36); MOSEK's relative feasibility tolerance converted to SCIP-SDP's absolute one by dividing by (1 + max C_ij), with 10^-7 instead of 10^-6 (p. 68); a penalty formulation when the Slater condition fails (p. 67). Determinism: a deterministic clock fitted by Lasso on solver statistics scaled by the number of nonzeros, with the regularisation chosen by cross-validation leaving out one instance at a time (p. 41); delayed reading of communication points to cut idle time (18.69% vs 6.73% average idle on biella1 with 8 threads, Fig. 5, p. 42); buffering of propagation marks during probing and of bound-change events on node switches (p. 13).
  - Transferable: when a transformation must add no error, restrict it to exactly representable operations: power-of-2 scaling changes only exponents (p. 46).
  - Transferable: when an inner solver's result is reused as a bound under an outer tolerance, run the inner solver at a tighter tolerance than the outer one (10^-8 vs 10^-6, p. 36).
  - Transferable: for deterministic parallel search, fit a deterministic clock to per-run statistics with leave-one-instance-out cross-validation, then plot it against wall clock under several settings to see where it fails (aow40b, Fig. 4, p. 41).

### S019 · Verifying Integer Programming Results (IPCO 2017, DOI 10.1007/978-3-319-59250-3_13; arXiv 1611.08832)
Read level: **full** (pp. 1-13; reference list pp. 11-13 skimmed). The file is ZIB Report 16-58, "Revised version March 2017", posted as arXiv v2 on 1 Jan 2019 (p. 1); the paper is dated March 9, 2017 (p. 3). Title and Gleixner in the byline checked (pp. 1, 3). It is the text listed in the index, not the Springer typeset version; the proceedings pages (pp. 148-160) appear only in the citation note (p. 1). Whether an earlier version excluded an instance cannot be checked from this file; this version reports all 107 instances (Table 1, p. 10).
**Role**: core · **Coauthors**: Kevin K. H. Cheung (Carleton University), Daniel E. Steffy (Oakland University) (p. 3) · **Whose work**: alphabetical byline (Cheung, Gleixner, Steffy; p. 3), no contribution statement. The producing solver is a modified version of the exact rational SCIP of Cook, Koch, Steffy and Wolter [13] (p. 9); the format specification and checker are at github.com/ambros-gleixner/VIPR (footnotes, pp. 5, 8). · **Position in trajectory**: the first paper on certificates for general MIP in this corpus; it verifies results reported for the 2013 exact SCIP (p. 4), and its future-work list (pp. 10-11) holds the seeds the SKILL traces to later decision analysis and delta debugging (Method 3).

- **D1 Problem and entry point**: MIP software can return wrong results, from floating-point arithmetic but also from programming or algorithmic errors in exact solvers, so independently verifiable certificates are wanted; their ideal form for MIP "is not entirely clear" (abstract, p. 3). The motivation is stated as not being distrust: a skeptical attitude bordering on paranoia is called neither healthy nor practical; the aim is to identify and reduce errors and raise confidence (p. 3). Entry from three gaps: formal code verification is "an ambitious goal" for solvers with several 100,000 lines of code (p. 3); for LP, duality gives easy certificates, but for MIP polynomial-size certificates may not exist and many forms are possible (tree, cut list, superadditive dual) (p. 4); solvers do not expose their trees or cuts and use propagation, conflict analysis and reduced-cost fixing, so a verifier reading all of that would itself be complex, and today's practice is to compare several solvers or check only the returned solution, as the MIPLIB solution checker does (p. 4). Two applications where verification matters: circuit-design verification models on which solvers returned wrong results, and Pulaj's MIP work on Frankl's conjecture; the software was used on models from both (p. 4).
  - Transferable: before designing a verification artefact, list what a checker would have to understand if it read the solver's own reasoning (tree, cuts, propagation, conflict analysis) and design the artefact so that it needs none of it (p. 4).
- **D2 Core idea and algorithm design**: A certificate is a list of statements, each verified in sequence by one of a few inference rules (abstract, p. 3): linear inequality inference, i.e. a linear combination with sign-constrained multipliers, which are a feasible dual solution (Remark 1, p. 5); rounding of a derived inequality whose coefficients on integer variables are integral and zero elsewhere, giving Chvátal-Gomory cuts (p. 6); assumptions plus "unsplitting", which discharges a split disjunction once both sides have led to 0 ≥ 1 (pp. 7-8, Fig. 1). The proposal is to "flatten" the branch-and-bound tree into this list, processed bottom-up while assumptions are discharged towards the root (p. 7). Against Applegate et al. (TSP) and Carr et al. (general MIP, unpublished), the format drops explicit tree handling; the price named is that one can no longer just examine the leaves (p. 7). Because any linear inequality may be assumed, general disjunctions and split cuts are representable (pp. 7-8, Remark 3). The checker deduces each statement's assumption list on the fly, so the file need not carry it (p. 7). The model is natural deduction and SAT unsatisfiability-proof checking (p. 4).
  - Transferable: choose the certificate format that minimises what the checker must know, and name the price paid for it (here: no direct reading of the tree's leaves, p. 7).
- **D3 Problem class and data model**: MILP with rational data, constraints Ax ≥ b, A'x ≤ b', A''x = b'' (S) (p. 5); "Throughout this paper, we assume that problems are specified and solved with exact rational arithmetic" (p. 5); rational multipliers suffice for rational data (Remark 2, p. 6). Branching on split disjunctions a^T x ≤ δ or a^T x ≥ δ+1, with δ integral and a^T x integral for all feasible x; cuts must be derivable as split cuts (p. 6). Test sets: the easy (57) and numerically difficult ("hard", 50) sets of Cook, Koch, Steffy and Wolter [13], drawn from libraries including MIPLIB 3.0, MIPLIB 2003, MIPLIB 2010, COR@L and Mittelmann's collection (p. 9; Table 1, p. 10).
- **D4 Algorithm and implementation design**: Proof devices: linear inequality inference justified by LP duality, so an optimal value v can always be derived (p. 5); the rounding rule for integral left-hand sides (p. 6); assumption and unsplitting rules (pp. 7-8); split cuts derived by assume, derive on both sides, unsplit (Remark 3, p. 8). Software (p. 8): viprchk checks certificates entirely in exact rational arithmetic (GMP); viprttn "tightens" certificates by building the dependency graph of derived constraints and writing only the component that reaches the final constraint, reordered by a depth-first topological sort (pp. 8-9); vipr2html renders a certificate for reading (p. 8). After each derived constraint the format stores the largest index of any later constraint that references it, so a checker can free memory early (p. 8). Producer: a modified exact rational SCIP using a hybrid of floating-point and exact rational arithmetic in a pure branch-and-bound, with CPLEX 12.6.0.0 as floating-point LP solver and a modified QSopt_ex 2.5.10 as exact LP solver; certificates come only from the Project-and-shift method (dual solutions) and the Exact LP method (dual solutions and Farkas proofs) (p. 9). The certificate is printed during the solve, so derivations of nodes later made redundant by branching or by a new incumbent stay in the file (p. 9).
  - Transferable: store with every derived statement the last index that uses it, so the checker's memory stays bounded by the live statements (p. 8).
  - Transferable: let the producer print naively during the solve and run a separate trimming pass on the dependency graph that keeps only what the final claim needs (pp. 8-9).
- **D5 Computational evaluation**: 107 instances (57 easy, 50 hard) from [13]; Intel Xeon E5-2660 v3 at 2.60 GHz, jobs run exclusively (p. 9). Arms: SCIP (exact SCIP with its default dual-bounding strategy), SCIP+C (the certificate-printing version, restricted to Project-and-shift and Exact LP), VIPR (tightening and checking) (p. 9). Limits: 1 h and 10 GB of certificate file. Categories: all; solved (by both SCIP and SCIP+C); memout (SCIP+C stopped at the file limit); timeout. Shifted geometric means with shifts of 10 s and 1 MB (p. 9). For memout and timeout runs the check time is the time to verify the primal and dual bounds in the intermediate certificate (p. 9). Results (Table 1, p. 10): easy-solved (39): exact SCIP 23.2 s, SCIP+C 48.0 s, check 11.5 s, tightening 3.6 s; hard-solved (13): 22.9 s, 40.7 s, 5.3 s; solved counts 54 vs 39 (easy) and 23 vs 14 (hard); 5 + 12 = 17 memouts. Computed from Table 1: the certificate run takes about 2.1 times (easy-solved) and 1.8 times (hard-solved) the plain exact solve, and checking takes about half (easy) and a quarter (hard) of the plain solve. File I/O is about 7% of solution time on the 39 easy-solved instances (p. 10). Tightening removes strictly more than 50% on average in every category; markshare1_1 shrinks from 10 GB to 8 kB because its root dual bound is already zero (p. 10). Per-instance timings and memory are in a document hosted with the software (p. 9). No significance test; no second checker to compare against.
  - Transferable: measure overhead only on instances solved by both arms, and sort the rest by failure type (memory cap vs time limit) instead of averaging them in (p. 9).
  - Transferable: for runs that stop early, still check what their partial certificate proves (the bounds reached) (p. 9).
- **D6 Literature positioning**: Against formal code verification (p. 3) and against current practice, cross-solver comparison and solution checking as in the MIPLIB checker [32] (p. 4). Claims a "significantly simpler structure" than Applegate et al.'s TSP certificate and Carr et al.'s unpublished MIP work (p. 4), and the first software for general MIP certificate verification made available to the community, "To the best of our knowledge" (pp. 4-5). Borrows from SAT: unsatisfiability-proof checking, DRAT-trim and extended resolution [27, 43] (p. 4); Hooker's inference view of duality [28] (p. 5). Safe bounds (Neumaier and Shcherbina [37]) and numerically safe Gomory cuts (Cook et al. [12]) appear as related exact or safe methods (p. 3) and as the route to floating-point certificates (p. 10).
- **D7 Writing and rhetoric**: Conceptual paper with the technical file specification moved to the repository (p. 5). Builds up from LP to pure IP to branch and cut with one small worked example each (Examples 1-3, Fig. 1; pp. 5-8). Hedges are explicit ("arguably", p. 3; "not entirely clear", p. 3; "To the best of our knowledge", p. 4). Observations are enumerated after the table ("First, ...", pp. 9-10). "significantly" is used without a test (p. 10). The conclusion calls the work "the first step of many" (p. 10).
- **D8 Contribution and limits**: Contribution: a certificate format, reference software (checker, tightener, viewer), certificate output in exact SCIP, and a computational demonstration. Limits written specifically: certificate output only for two of exact SCIP's dual-bounding methods (p. 9); the producing exact SCIP is "available from the authors by request" (p. 9), so only the checker side is public; 17 runs stop at the 10 GB cap (p. 10); redundant output from printing during the solve, with two named fixes, buffering derivations of internal nodes and skipping nodes that do not improve the parent's bound (p. 10). Forecast: file I/O is only about 7%, so future code changes should bring certificate runs much closer to plain exact SCIP (p. 10). Future directions: valid certificates computed with floating-point data by directed rounding and interval arithmetic; approximate certificates for debugging solvers or "measuring the maximum or average numerical violation over all derivations"; conversion for a proof assistant such as HOL Light (pp. 10-11). Not written: what is outside the certificate (the producer is a pure branch-and-bound, p. 9, so presolve, propagation and conflict analysis are not exercised) and any test of the checker itself.

**Transferable techniques**:
- Write a certificate as a flat list of derived constraints, each justified by one rule (sign-constrained linear combination, rounding, assumption, unsplitting), so the checker needs no knowledge of the producing algorithm (pp. 5-8).
- Flatten a branch-and-bound tree into a bottom-up derivation: branching constraints enter as assumptions, pairs of contradictions are unsplit, and the checker tracks assumption lists on the fly (pp. 7-8).
- Represent split cuts the same way: assume each side, derive the cut on both, unsplit (p. 8).
- Store the last referencing index after each statement so checkers can free memory (p. 8).
- Trim a naively printed certificate with a dependency-graph pass that keeps only the component reaching the final claim (p. 9).
- Report overhead on both-solved instances and file runs that hit the memory or time cap in their own rows (p. 9).
- Measure the I/O share of an overhead before forecasting how far it can shrink (p. 10).
