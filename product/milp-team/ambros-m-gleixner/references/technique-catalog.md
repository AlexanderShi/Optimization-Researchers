## 1. Proof devices (PD)

| # | Technique | How to use | Cards |
|---|---|---|---|
| PD1 | Analysis against a limited-precision oracle contract (*his line*; *own* in the thesis) | State what the floating-point solver delivers on inputs from F(p) = {n/2^p : n ∈ Z, −2^(2p) ≤ n ≤ 2^(2p)} (doubles lie in F(1074)): residuals at most η < 1, complementarity at most σ, or failure; with growth limit α > 2 the violations then shrink as ε^k, ε = max{η, 1/α} [S029 pp. 8–9]; prove convergence and oracle-polynomial running time of the exact layer against that contract alone (Method 7) | [S020 TR p. 7; S013 TR pp. 9–10, 26–27; S032 pp. 41–45, 83–84; S029 pp. 8–22; S058 pp. 7–11; S050 pp. 8–9] |
| PD2 | Shift-and-scale correspondence (*his line*) | Shift the problem to the current iterate, replace data by scaled residuals, and prove that a solution of the shifted problem corrects the original one; this is what lets an absolute-tolerance solver refine | [S020 TR pp. 6–7; S013 TR p. 6; S032 pp. 35–37; S058 p. 5] |
| PD3 | Encoding-length control | Round scale factors to powers of the oracle's base so rational iterates share a denominator, and bound denominators by best rational approximation, so that rational cost grows only linearly with the rounds | [S032 pp. 44–45; S013 TR p. 11; S029 pp. 10, 18–19; S036 pp. 11–15] |
| PD4 | Separation bound and output-sensitive reconstruction (*his line*; *own* in the thesis) | Prove that non-optimal basic solutions violate by at least a computable constant, so linearly shrinking residuals certify the basis after finitely many rounds; schedule speculative reconstruction geometrically so its total cost is dominated by the last attempt | [S029 pp. 5, 11, 15–17, 19–22; S032 pp. 90–91] |
| PD5 | Self-certifying exact basic solutions; certificates in the user's units | Compute the basic solution of a floating-point basis exactly: it certifies its own optimality whatever produced the basis; turn an approximate Farkas ray into a box radius inside which no feasible point exists | [S020 TR pp. 5, 7; S013 TR pp. 11–14, 32; S032 pp. 52–54] |
| PD6 | One safe-rounding lemma for every derived row | Prove once that a row aggregated with directed rounding of activities and rays stays valid, then reuse it for cuts, propagation and dual proofs; scale duals to integers where pricing needs exactness | [S036 pp. 6–8, 10; S074 pp. 6–7; S021 p. 8; S085 pp. 13–14] |
| PD7 | Running error analysis with an undecided band | Decide most feasibility tests in floating point with a running error bound and recompute exactly only the rows whose slack falls inside the band | [D002 p. 8; S022 pp. 7–8] |
| PD8 | LP-duality aggregation into learned one-row bounds | Read a dual solution of a bound-tightening LP as a globally valid one-row inequality and propagate it through the tree instead of re-solving | [S039 p. 5; S011 pp. 7–9; S032 p. 139; S006 p. 10; S003 pp. 20–21] |
| PD9 | Certificates from few inference rules | Write the proof as a flat list of derived statements, each justified by one of a few rules (sign-constrained combination, rounding, assumption, unsplitting), so the checker needs no solver knowledge; for presolve, classify each reduction as primal, weak dual or strong dual, certify primal ones by implication (cutting planes, reverse unit propagation) and dual ones by redundance-based strengthening with a witness substitution, aggregation scales split into integers [S038 pp. 4, 6–10] | [S019 pp. 5–8; S036 p. 17; S074 pp. 7–8; S021 pp. 10–11; S060 pp. 5–7, 17–24; S038 pp. 3–11] |
| PD10 | Hardness by reduction (*common practice*) | Before designing an algorithm, prove the subproblem NP-hard by a reduction from a classical problem, and say what the proof licenses (heuristics, a separation oracle) | [S025 pp. 37–38, 48–50; S018 pp. 7–8; S054 p. 6; S053 pp. 12–14; S073 p. 3; S085 p. 4; S012 pp. 6, 16–17] |
| PD11 | Minimal counterexample before generalising (*common practice*) | Before reusing an algorithm or a result in a neighbouring setting, build the smallest instance where it fails | [S012 p. 7; S018 pp. 8–9; S062 p. 5; S080 pp. 8, 14–15; S063 pp. 15–16; S029 pp. 13–14] |
| PD12 | Re-derivation as an instance of a host-field family (*common practice*) | Show that a new technique is a special case of a known family (Kelley's cutting planes, a proof system), then generalise from the family | [S047 pp. 14–16; S044 pp. 9–10; S062 pp. 7–8; S080 pp. 9, 12–14; S011 p. 7] |
| PD13 | Dominance and bidirectional completeness in labelling (*outside this lens*: decomposition, marco-e-lubbecke) | Prove which labels may be discarded and that forward and backward extensions together find every resource-feasible cycle | [S092 pp. 4–6; S085 pp. 5–8] |
| PD14 | A worst-case quality bound that licenses a cheap approximation | Prove how much a relaxation of a projection can lose, then compute only the relaxation | [S043 pp. 12–14] |
| PD15 | Invariants for parallel code | State the invariant each worker preserves (no conflicting reductions, stale counters as one-sided bounds, a structure that no reduction may break) and check it at the commit point | [S026 pp. 6–7, 20; S068 p. 5; S078 arXiv p. 7; S005 p. 10] |
| PD16 | Reference-solution invariant for delta debugging | Accept a reduction step only while the failure persists against a fixed reference solution, so the reduced instance still exposes the same bug | [S065 pp. 4–6] |
| PD17 | Equivalence-preserving reductions in a computer-assisted proof | Shrink the problem with reductions each proved equivalence-preserving before the solver runs, and keep the proof apart from the computation | [S042 pp. 5–9] |
| PD18 | Decisions classified as heuristic or critical | Split solver decisions into those that only steer the search and those that decide correctness, and define error classes by what hindsight shows | [S072 pp. 4–6] |

## 2. Design moves (DM)

| # | Technique | How to use | Cards |
|---|---|---|---|
| DM1 | Exact repair of floating-point heuristic solutions | Fix the integers of a floating-point solution and solve an exact LP over the continuous rest, behind an improvement filter, a hash of tried assignments and a failure limit | [D002 pp. 7, 12; S022 pp. 5–6, 14; S021 p. 10] |
| DM2 | Scheduled exact LPs and switch-off rules for safe bounding | Call exact LPs at fixed depths, pad the objective limit by the observed safe-bounding increase, and switch a cheap safe method off when its success rate drops below a threshold (20% for bound shift [S022 p. 12; D002 p. 10]) | [D002 pp. 7–10; S022 pp. 7, 10–12; S021 p. 9] |
| DM3 | A verification ladder, cheapest check first | Check each decision with the cheapest sufficient test (floating-point safe bound, then exact LP) and record which rung decided | [S072 pp. 6–7, 14] |
| DM4 | Failure triggers and escalation | List the conditions that mean the floating-point oracle has failed (non-optimal status; residuals close to or above one; stalling, the maximum violation falling by less than 2^4 over two consecutive rounds; infeasibility or unboundedness claimed where none can hold [S050 pp. 5–6]) and escalate on them: retry with other settings, back off the scaling, raise the precision | [S013 TR pp. 15–16; S058 p. 12; S050 pp. 5–8] |
| DM5 | A safety flag per plugin in exact mode | Mark which plugins are safe for exact solving and turn floating-point bounds into safe outward roundings before use | [S021 pp. 7–8] |
| DM6 | Certificates written online, trimmed or completed offline | Let the solver print what it knows cheaply during the solve; a separate tool trims the dependency graph or completes weak derivations, so the checker's logic stays unchanged | [S019 pp. 8–9; S036 pp. 18–20; S074 p. 8] |
| DM7 | The input checked too | Check that the certificate encodes the intended model (a proof assistant, or redundant annotation of user structure) before trusting the verdict | [S042 pp. 2–3; S046 p. 5] |
| DM8 | Harvest by-products of auxiliary solves | Reuse duals, infeasibility proofs and relaxation points that auxiliary solves already computed (bound-tightening LPs, sub-MIPs, conflict analysis) before computing anything new | [S039 pp. 4–7; S011 pp. 7–12; S018 pp. 10–11; S034 pp. 7–10; S003 pp. 20–21; S043 pp. 15, 18] |
| DM9 | Fail fast, success gating, back-off | Give a heuristic a small budget, stop it at the first sign of failure, run it again only after success, and refund the budget when it pays | [S018 pp. 4, 15–16; S034 p. 12; S079 pp. 5–7; S040 p. 4; S031 p. 24] |
| DM10 | New signals as tie-breakers or wrappers of the default | Enter a new score with a small weight beside the default, or wrap the existing rule, so the zero setting is the old default and the comparison isolates one term | [S066 pp. 4, 12; S054 p. 8; S032 pp. 178, 180–181; S007 p. 16] |
| DM11 | Deterministic commit order in parallel code | Fix the order in which parallel results are committed so the output does not depend on the thread count, and measure what the determinism costs | [S026 pp. 6–9; S005 p. 10; S004 pp. 62–63; S078 arXiv pp. 13, 15] |
| DM12 | Structure-preserving presolve with postsolve | Admit only reductions that keep the structure the downstream solver needs and whose postsolve restores what the user needs (duals, bases) | [S033 p. 74; S068 pp. 3–5; S078 arXiv pp. 7–8; S031 p. 24; S004 pp. 62–63] |
| DM13 | Floating-point safety without exact arithmetic | Where no exact arithmetic runs, tighten only the tolerance that decides validity, use double-double or interval arithmetic where round-off threatens a bound, and count numerical fallbacks | [S011 p. 14; S006 pp. 7, 19; S003 pp. 12, 18, 25; S004 pp. 31, 33–38; S062 pp. 9–10] |
| DM14 | An application idea implemented through a generic proxy | Turn a structure seen in one application into a generic solver rule that any instance can trigger, then test it on general MIPs too | [S045 p. 14; S098 p. 21] |
| DM15 | Valid dual bounds under heuristic or incomplete pricing (*outside this lens*: decomposition, marco-e-lubbecke) | Derive a dual bound that stays valid when pricing is heuristic or stops early, so every intermediate bound is reportable | [S041 pp. 16, 18–21; S087 pp. 24–25; S085 pp. 13–14] |

## 3. Experiment and evaluation protocols (EP)

| # | Technique | How to use | Cards |
|---|---|---|---|
| EP1 | Reduced and default baselines, both factors | Strip the incumbent of exactly the features the new code lacks, keep the default too, and print both factors on the same named subset | [S022 pp. 17–18; S036 pp. 20–21; S074 pp. 8–9; S021 pp. 11–12] |
| EP2 | Staircase: one component per table | Add one factor per table, each on top of the previous configuration, so each step's effect is read off directly | [S022 pp. 8–18; D002 pp. 8–14; S024 pp. 16, 26; S076 pp. 9–10] |
| EP3 | Instance-seed pairs, nested brackets, both-solved rows | Treat each instance-seed pair as one observation; report nested brackets (all, ≥1 s, ≥10 s, ≥100 s) with both-solved and differing-timeout rows; three seeds in the exact-MIP studies [S036 p. 21; S050 p. 9], five in 2017 [S003 pp. 6–8] | [S003 pp. 6–8; D004 pp. 13–15; S005 pp. 6–8; S004 pp. 4–5; S015 pp. 4–5; S034 pp. 11–12; S036 p. 21; S050 p. 9] |
| EP4 | Affected subsets fixed before the runs | Define by a mechanical criterion, before measuring, the instances where a component can act, keep a control group, and count applicability before the effect | [H001 p. 5; S039 pp. 7–8; S054 pp. 10–11; S043 pp. 19–25; S006 pp. 19–20; S014 p. 28; S021 p. 5] |
| EP5 | Negative control and attribution runs | Run the control that removes or forces the suspected mechanism (a channel off, a tighter tolerance, the component off) and print the null; where a component cannot help, a gain is variability, so rerun with more seeds | [S022 pp. 10–11, 15; S034 pp. 17–19; S074 pp. 11–12; S070 p. 20; S072 p. 12; S064 p. 29; S083 p. 18; S062 p. 11] |
| EP6 | Variability instruments | Measure variability explicitly (constraint permutations, coefficient of variation, best and worst seed, seed spread) before reading a small gain | [S001 TR pp. 12–14; S014 p. 14; S084 p. 20; S010 pp. 19–20; S003 p. 7] |
| EP7 | Significance tests | Use a one-sided Wilcoxon signed-rank test on log ratios of shifted values per bracket, and remember it ignores the size of the change; for an instrument's design claim, a one-sided KS test per solver | [S032 pp. 23–24; S011 pp. 16, 21; S006 p. 20; S002 pp. 40–41] |
| EP8 | Two sets: one where the belief should hold, one compiled to break it | Run a set the floating-point solver finds easy and one compiled to be numerically difficult (FPEasy 57, NumDiff 50), each also permuted, and report each set apart | [S019 p. 9; S072 p. 8] |
| EP9 | Rival's best case; conservative comparators | Where no stripped rival exists, build the rival's best case by hand and say what it costs; prefer comparators that make your gain smaller; validate a baseline against an independent implementation | [S078 arXiv pp. 13, 18–20; S034 pp. 13, 15; S085 pp. 18–19; S067 arXiv pp. 16–18] |
| EP10 | Replication in a second solver | Re-implement the component in another solver and compare tendencies, not pooled numbers | [S070 pp. 21–22] |
| EP11 | Certification cost accounting | Report certificate overhead on both-solved instances only, capped runs in their own rows, time split into solve, print and check: e.g. +56.3%, +22%, +46% solving time on fpeasy, numdiff, miplib and 92.5%, 32.8%, 65.8% with checking [S022 p. 16]; presolve proof logging under 6%, checking 14.7 to 22.4 times the presolve time, PAR2 for timeouts [S038 pp. 12–13] | [S019 p. 9; S036 pp. 24–26; S038 pp. 12–15; S007 p. 17; S022 p. 16] |
| EP12 | Benchmark and competition construction | Write purpose, admission rules, selection model, hidden series and scoring before collecting results, and print the manual choices | [S002 pp. 27–41; S009 pp. 15–16, 21; S055 pp. 2–3, 6–7; S016 pp. 2–5; S001 TR pp. 5–8; S058 p. 14] |
| EP13 | Per-instance tables | Publish per-instance results from which every aggregate can be recounted | [S011 pp. 26–72; S041 pp. 32–48; S078 arXiv p. 13] |
| EP14 | Scaling explained | Explain parallel scaling by the sequential (Amdahl) fraction, correlations and a decomposition of communication time, not by speed-up curves alone | [S026 pp. 11–14; S078 arXiv pp. 14, 17, 26–27; S033 pp. 104–105] |
| EP15 | Deterministic work limits for paired runs | Inside one solver, compare arms under deterministic work limits; keep wall-clock time for cross-solver tables | [S012 pp. 4, 6, 18; S024 p. 11; S080 p. 20; S001 TR p. 14] |
| EP16 | Limit-independent effort profiles (*own* in the thesis; co-authored in S011) | Compare strategies that will run under unknown working limits by per-instance success-versus-effort profiles, normalised by the best strategy | [S032 p. 155; S011 pp. 17–18] |
| EP17 | Timeouts as lower-bound speed-ups (*own*, single card) | Give instances solved by one arm only a column with T/t as a lower bound on the speed-up, and rerun the test with them | [S032 p. 181] |
| EP18 | Check what an unfinished run has proved (single card) | For runs stopped by a cap, still verify the bounds their partial certificate proves | [S019 p. 9] |
| EP19 | Failures of one project as the next test set (single card) | Take the instances on which the previous method failed as the target set of the next one | [S050 pp. 9, 12–13] |
