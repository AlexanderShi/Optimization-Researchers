### S014 · A finite branch-and-bound algorithm for two-stage stochastic integer programs (Mathematical Programming 2004, doi:10.1007/s10107-003-0475-6)
Read level: **full** (pp. 1-23; reference list p. 23 skimmed).
**Role**: core · **Coauthors**: Shabbir Ahmed (Georgia Tech ISyE at publication; his 2000 UIUC PhD thesis is ref. [1], cited pp. 2, 18), Mohit Tawarmalani (Purdue) · **Position in trajectory**: UIUC optimization-under-uncertainty line; received June 2000, accepted September 2003 (p. 1); funded by IBM Research, ExxonMobil Upstream Research and NSF (p. 1). The companion paper S069 counts it among the "finite branching schemes" with which branch-and-reduce was enhanced (S069 p. 2), and its hardest test set runs inside BARON (p. 22).

- **D1 Problem and entry point**: Stochastic-LP machinery relies on the convexity of the recourse value function; with integer recourse Q(·, ω) is only lower semicontinuous, so convex-programming approaches "break down" (p. 2), as the discontinuous, multi-extremal example (EX) of Schultz et al. shows (Fig. 1, pp. 2-3). Each rival is located by the assumption it needs: a binary first stage (Laporte-Louveaux), a master with nonlinear discontinuous cuts for which "no practical method for its solution is currently known" (Carøe-Tind), finiteness only for a discrete first stage or ε > 0 (Carøe's dual decomposition), explicit enumeration of a candidate set (Schultz et al.) (pp. 2-4). The entry is geometric: existing B&B methods branch on one first-stage variable at a time, the discontinuities are not orthogonal to the axes, so some cell always keeps one inside and a continuous first stage gives "a convergent only scheme" (p. 6). Problem: a finite global algorithm for discrete distributions, mixed-integer first stage and pure-integer second stage (p. 4).
  - Transferable: explain why the incumbent methods fail through the geometry of the partition (oblique discontinuities, axis-parallel cells); the explanation points to the fix, a change of variables (p. 6).
- **D2 Core idea and algorithm design**: Search in the tender variables χ = Tx instead of x (problem (TP), pp. 6-7). Because D^s is integral, each ψ^s_j is constant on unit half-open intervals (k − h^s_j − 1, k − h^s_j] (Lemma 2, p. 8), so the expected recourse is constant on axis-parallel boxes C(k) (Thm. 3, p. 8), and only finitely many boxes meet the compact feasible set (Thm. 4, pp. 9-10). The Horst-Tuy prototype B&B with least-lower-bound selection (pp. 10-12) is then specialized in three places: partition elements are half-open boxes whose lower corners are possible discontinuities (§5.1, pp. 11-12); the lower bound solves the scenario IPs at the lower corner plus an ε computed in advance from the h^s, using monotonicity (problem (LB), pp. 12-13; Prop. 1, p. 13), and is exact on a box without discontinuities, so such a box is fathomed (Props. 2-3, p. 14); branching cuts at p_j = min_s{(D^s y^s)_j − h^s_j}, where the current second-stage solutions would become infeasible, on the axis with the most central cut (p. 14). Unchanged: the scenario IPs remain black-box oracles (p. 6), and the bound decomposes completely by stage and scenario (p. 13). Tighter bounds plug in: one Benders (L-shaped) cut moves the (EX) root bound from −72.25 to −60.9 (pp. 15-16); a Lagrangian dual restricted to the box dominates (LB) (Prop. 4, pp. 16-17).
  - Transferable: for a monotone, piecewise-constant value function, bound a half-open box by its value at the lower corner + ε; the bound becomes exact once the box holds no breakpoint, which gives fathoming and finiteness together (pp. 12-14).
  - Transferable: branch where the current subproblem solution stops being feasible, not at the midpoint (p. 14).
- **D3 Assumptions and model**: (A1) a finite discrete distribution, justified by Schultz's approximation result (p. 5); (A2) pure-integer recourse; (A3) a deterministic technology matrix T; (A4) X nonempty and compact; (A5) complete recourse, assumed "for simplicity of exposition" although relatively complete recourse suffices and can be forced with penalized artificial variables (pp. 5-6); (A6) dual feasibility; (A7) integral D^s, obtainable "by appropriate scaling whenever the matrix elements are rational" (p. 6). The first stage is taken continuous without loss of generality, mixed-integer first stages being handled the same way (p. 5), and the scenario IPs are implicitly assumed "small" and easier than the deterministic equivalent (p. 6). Dropping (A2) loses axis-orthogonality: finiteness returns only by moving the continuous second-stage variables into the first stage (viable with few of them) or by branching on second-stage integers; dropping (A3) needs S × m2 tender variables (p. 18).
  - Transferable: give each assumption one line saying why it is harmless (approximation theorem, scaling, artificial variables) or what dropping it costs (pp. 5-6, 18).
- **D4 Analysis and proof devices**: Existence of an optimum via lower semicontinuity (Blair-Jeroslow), Fatou and Weierstrass (Thm. 1, p. 7); equivalence of (TP) and the original problem by contradiction (Thm. 2, p. 7); a rounding argument, (D^s y)_j ≥ ⌈h^s_j + χ_j⌉, for piecewise constancy (Lemma 2, p. 8); a partition of R^{m2} into full-dimensional half-open boxes (Thm. 3, pp. 8-9); finitely many boxes, by bounding the integer vector k (Thm. 4, pp. 9-10); finiteness of the algorithm through Horst-Tuy "finitely consistent" bounding: every unfathomed box contains a discontinuity, and there are finitely many (Def. 1, Lemmas 3-4, Thm. 5, p. 15); the dominance chain f_L(P) ≤ z_LD(P) ≤ inf over P (Prop. 4, pp. 16-17).
  - Transferable: prove finiteness through finite consistency (an unfathomed cell must contain one of finitely many breakpoints) instead of analysing bound convergence (p. 15).
- **D5 Numerical experiments**: Three literature test sets; rivals' numbers are taken from their papers, not rerun (pp. 18-22). Set 1 (Carøe; pure-integer first stage; 4-441 scenarios, Table 1, p. 19): fewer second-stage IPs (6,615 vs 9,702 at 441 scenarios) and 0.06 vs 25.1 CPU s, on different machines whose LINPACK ratings are printed (59.9 vs 235.3 Mflop/s) (Table 2, p. 20). Set 2 (Schultz et al.; continuous first stage; they reported no CPU times): evaluations of E[Q] counted, 28 vs 121 (−76%) and 10 vs 19 (−47%), next to the CPLEX 5.0 gaps of 24% and 27% after 50,000 nodes reported in the literature (pp. 20-21; Tables 3-4, p. 21). Set 3 (SIZES3/5/10, mixed-integer second stage, outside the finiteness theory): explicit branching on second-stage integers, the B&B tree kept by BARON, CPLEX 6.0 for LPs; gap closed for SIZES3 (70.7 s) and SIZES5 (7,829.1 s), SIZES10 left open; better upper bounds than previously known for all three (Tables 7-8, p. 22). Small inconsistencies: the text states a 100,000 s limit on a 332 MHz machine, while Table 7 lists SIZES10 at 10,000.0 s with the footnote "IBM RS/6000 133 MHZ" (p. 22).
  - Transferable: when the only baselines are published results on other machines, compare a machine-independent count of the expensive operation (scenario IPs solved, E[Q] evaluations) and print a standard rating for each machine (pp. 20-21).
- **D6 Literature positioning**: An explicit map of the field, each rival placed by its assumption and its cost (pp. 2-4). Criticism is technical and direct: enumeration "is, in general, computationally prohibitive" (p. 4). Schultz et al.'s insight (the value function is constant on certain sets) is kept and re-proved in tender-variable space (p. 8), while their enumeration is replaced by branch-and-bound and the scope widened to uncertain costs and recourse matrices (p. 4). Theory comes from deterministic global optimization (Horst-Tuy, pp. 12, 15) and the group's own BARON and book (refs. [19], [22], p. 23).
  - Transferable: take a rival's structural lemma and re-prove it in a transformed space where it can drive branching (p. 8).
- **D7 Writing and rhetoric**: The key concept fits one paragraph at the end of the introduction, with (a) branching and (b) bounding enumerated, followed by the defence of theory as practice: finiteness "is not only of theoretical significance" (p. 4). Assumptions come as a numbered list with one-line justifications (pp. 5-6). Figures 2-3 show the same value function in x-space and χ-space, so the rotation of the discontinuities is seen as well as proved (pp. 9-10). Hedging is moderate ("indicate superior performance", abstract p. 1; viable "only when there are a few continuous variables per second-stage subproblem", p. 18).
- **D8 Contribution and limits**: Theory and algorithm: a finite B&B for continuous first stages without enumeration (Thm. 5, p. 15), with computational support (pp. 18-22). Limits are concrete: finiteness is lost with a mixed-integer second stage (p. 18); a random T multiplies the branching dimension by S (p. 18); SIZES10 is unsolved (p. 22). There is no future-work section; §7 lists the bounds that can be plugged in (pp. 15-18).

**Method links**:
- Method 2 (evidence ✅): the hardest test set is solved "using BARON [19, 22] to maintain the branch-and-bound tree", with CPLEX 6.0 for LPs (p. 22): a student's thesis algorithm lands in the group's production code as its tree manager.
- Method 1 (variant ⚠): no range reduction. Domain knowledge enters as a precomputed grid of breakpoints (the initial box from LPs over X, lower corners where l_j + h^s_j is integral, pp. 11-12) and as branching points restricted to those breakpoints (p. 14): structure decides where to cut, not how far to shrink.
- Method 4 (variant ⚠): the group enters stochastic integer programming with its own algorithm, not with a benchmark, and judges it on the rivals' own published test sets and numbers with machine-independent counts, without reruns under identical conditions or a library of certified optima (pp. 18-22).
- Heuristic 1 (evidence ✅): a named special class (pure-integer recourse, discrete distributions, deterministic T) whose structure yields finiteness (pp. 4-6). Heuristic 8 (evidence ✅): Schultz et al.'s constancy insight is kept and their enumeration replaced (pp. 4, 8).
- New-pattern candidates: *Change variables so the nonconvexity becomes axis-aligned, then branch only on it* (pp. 6-10, 14-15); *Machine-independent work counts against published baselines* (pp. 20-21).

**Transferable techniques**:
- Move the search to the linking (tender) variables χ = Tx: discontinuities oblique in x become axis-parallel in χ, so rectangular branching can isolate them (pp. 6-10).
- Lower-corner bound: for a nondecreasing, piecewise-constant ψ on half-open boxes (l, u], solve the subproblems at l + ε with ε computed in advance from the data; a box without a breakpoint is then fathomed in one step (pp. 12-14).
- Branch at p_j = min_s{(D^s y^s)_j − h^s_j}, the value at which the current scenario solutions become infeasible (p. 14).
- Prove finiteness by Horst-Tuy finite consistency (Lemmas 3-4, p. 15).
- Against published baselines on other hardware, report counts of the expensive oracle calls plus LINPACK ratings (pp. 20-21).

**Quotes**:
- "Since the discontinuities are, in general, not orthogonal to the variable axes, there would always be some rectangular cell that contains a discontinuity in the interior." (p. 6)
- "The issue of finiteness is not only of theoretical significance – our computational experiments using standard test problems indicate faster convergence of the proposed algorithm in comparison to existing strategies in the literature." (p. 4)

### S003 · A polyhedral branch-and-cut approach to global optimization (Mathematical Programming 2005, doi:10.1007/s10107-005-0581-8)
Read level: **full** (pp. 1-25; reference list pp. 24-25 skimmed).
**Role**: core · **Coauthors**: Mohit Tawarmalani (Purdue) · **Position in trajectory**: SKILL.md signature work 2 and the source of Method 5's stated evidence; the SKILL.md Honest Boundary lists this full text as not read, so this is the first full read. Math. Program. Ser. B 103, received June 19, 2004, accepted November 19, 2004 (p. 1); funded by ExxonMobil Upstream Research, NSF and NIH (p. 1); extends the authors' 2004 paper [21] from univariate and bivariate to multivariate convex functions (pp. 1-2); implemented in BARON 7.2 (p. 15).

- **D1 Problem and entry point**: A reliability gap between solver technologies. Nonlinear (including semidefinite) relaxations have potential that "can be realized only if they can be solved with sufficient speed and reliability", but NLP codes are "significantly slower and numerically unstable compared to linear programming software" (abstract, p. 1); local NLP implementations "often suffer from serious numerical issues making them inadmissible for solving convex relaxations" inside global algorithms (p. 1). Polyhedral relaxation of univariate convex functions (their [21]) gives up some tightness but cuts the cost of bounds and inherits LP reliability (pp. 1-2). The open gap: sandwich algorithms converge quadratically in one dimension, while multivariate outer approximation is recent theory that "has thus far not resulted in any implementations" (p. 2).
  - Transferable: enter from the reliability of the subsolver rather than from relaxation strength: ask how to keep most of a stronger relaxation's bound while solving only with the robust technology (pp. 1-2).
- **D2 Core idea and algorithm design**: Outer-approximate the decomposed form h = g∘f by linearizing g and each f_i in lifted variables (S2(h)) instead of linearizing h directly (S1(h)). S2(h) ⊆ S1(h) by the chain rule (Thm. 1, pp. 3-4); the two coincide when f is affine (Prop. 2, p. 4) or when g is linear with one nonlinear inner function (Prop. 3, pp. 5-6); S2 is strictly tighter in examples (x^4 as (x^2)^2: bound 15 vs 9 at x = 3, Fig. 2, pp. 5-6); for separable functions S1 needs supporting hyperplanes at r^n points to match S2 built at r points (Prop. 5, p. 7). Consequence: convexity provable by composition rules is exploited without being detected, and eight known detection rules are special cases (§3.1, pp. 9-10). Further pieces: cuts from convex underestimators of x/y (§3.2, pp. 10-11); better relaxations of products of convex functions once domain reduction bounds the auxiliary variables (§3.3, p. 11); a convex non-decreasing minorant L_g whose composition is the convex envelope of g(f(x)) for coercive univariate f and g (Props. 6-8, Thm. 3, pp. 12-14); for convex expressions the rule cannot see (log-sum-exp, x^2 + y^2 − xy), a user declaration and a random grid of points on the epigraph refined by subgradients (§3.4, pp. 14-15). Implementation (§4, p. 15): BARON 7.2 with automatic differentiation; four initial supporting hyperplanes per univariate function, placed by angular trisection, chosen "after extensive experimentation"; then cuts at the LP solution only when violated, used in all relaxation and probing LPs and kept local to the node; the implementation is "albeit preliminary" and resembles separation in integer programming. Kept: the factorable decomposition and LP-based B&B. Changed: no NLP solver at the nodes. Claimed as "the first general-purpose primal branch-and-cut solver" for global NLP and MINLP (p. 2).
  - Transferable: before linearizing a composite convex function, introduce a variable for each inner function and linearize layer by layer; prove containment with the chain rule and look for a separable case where the single-step version needs exponentially many cuts (pp. 3-7).
- **D3 Assumptions and model**: Factorable functions, decomposed into sums and products of univariate functions (p. 9); g convex and non-decreasing in the range of each non-affine f_i (p. 2); differentiability, with a non-constructive extension through the subdifferential chain rule (§2.1, pp. 8-9); finite bounds, e.g. x^L, y^L > 0 for x/y (p. 10). BARON 7.2 handles products, powers, logarithms and exponentials (p. 18). No convexity information was given to the solver in the computational study (p. 17), so §6 tests only the automatic part.
  - Transferable: state which classes the new cuts cannot help (bilinear and concave quadratic programs, which generate no cuts here) and exclude them from the test set in writing (p. 18).
- **D4 Analysis and proof devices**: Convexity of compositions by projecting a lifted convex set (Prop. 1, pp. 2-3); containment by the chain rule (Thm. 1, pp. 3-4); equality cases (Props. 2-3) next to strict-gap counterexamples with numbers and plots (Remarks 2-3, Figs. 1-2, pp. 4-6); Fourier-Motzkin elimination to show that S2 equals S1 built on r^n points (Prop. 5, p. 7); the subdifferential chain rule of Hiriart-Urruty and Lemaréchal (Lemma 1, Thm. 2, pp. 8-9); a conjugate characterization L_f = sup over s ≥ 0 of ⟨s, x⟩ − f*(s) (Prop. 7, p. 12); an envelope result for coercive univariate compositions, with counterexamples when bounds or coercivity fail (pp. 13-14); the asymptotic volume results of Gruber and of Böröczky and Reitzner as motivation for random grid points (pp. 14-15).
  - Transferable: pair every containment theorem with an equality case and a numerical strict-gap example, so the reader sees when the new construction matters (pp. 4-6).
- **D5 Numerical experiments**: Two worked examples from actual BARON 7.2 runs, with the root bound after each cut round: an x/y objective, 85.5% of the root gap closed in 6 rounds, 7 vs 47 nodes (p. 16); log-sum-exp declared convex through CONVEX EQUATIONS, 99.5% gap reduction, 35 vs 1793 nodes (p. 17). The study: one Dell Precision 530 with a 1.7 GHz Xeon (p. 17); 87 problems (40 globallib, 47 minlplib) left after stated filters: trivial, too large, unsupported functions, bilinear or concave QPs, unbounded domains (p. 18). Root gaps with and without cuts, up to 10 rounds, one cut per nonlinear term per round (p. 19), reported per library: globallib gap reduction averages 48% (0.05-100%), lower-bound improvement averages 115%, maximum 2000% (p. 19); minlplib gap reduction averages 20%, with one large deterioration explained (the relaxation's point started a local search that found a worse upper bound), 27% without it, lower-bound improvement up to 41357% (pp. 19-21). Full solves: 26 problems chosen as nontrivial (> 5 CPU s) and likely solvable within hours by at least one strategy; tolerances 10^-6 absolute and 10^-9 relative; 25,200 s limit (p. 21); nine problems time out without cuts, none with cuts (p. 21); mean reductions of 93% in CPU, 99% in iterations and 98% in memory (p. 23); Table 5 counts effect classes (CPU at least 2× better for 15 problems, 58%) (p. 23); tls4 slows down because the cuts shrink the tree "at the expense of larger and more time consuming LP relaxations" (p. 22). Table 6 prints the global values, marks problems never solved before, a new optimum for tls4 (8.3 vs 9.3 in minlplib), and the case of ex8_4_7, whose value 28.6032 is feasible only at the default 10^-5 tolerance and becomes 29.04731 at 10^-6 (p. 23). Baseline: the same solver with cuts off; no other solver. My reading of the tables: by Table 4, elf (31 → 95 s), ex6_2_14 (7 → 38 s), himmel16 (27 → 81 s) and tls4 (4106 → 12295 s) slow down about 3-5×, yet Table 5's "Worse by a factor at least two" row is 0 in every column, and ex1233 also slows (922 → 1246 s) although the text names tls4 as the only nontrivial slowdown (pp. 22-23); the nine capped runs make up about 82% of the no-cut CPU total behind the 93% mean (Table 4, p. 22); five of the 26 solved problems (elf, ex1233, ex6_2_14, himmel16, parallel) are not in the 87-problem lists of Tables 1-2, although §6.3 introduces the 26 as a subset (pp. 18, 21-22).
  - Transferable: report an on/off ablation as counts of effect classes (≥ 2× better, 30-100% better, < 30%, 30-100% worse, ≥ 2× worse) for iterations, memory and CPU separately, and explain each loss (pp. 22-23).
  - Transferable: when a reported optimum depends on the feasibility tolerance, print both values with both tolerances (p. 23).
- **D6 Literature positioning**: Continues the McCormick factorable line and the authors' own [21] (pp. 1-2, 9); claims the decomposition can improve classical convex-programming outer approximation (Kelley, Griffith-Stewart, Duran-Grossmann) (p. 2); recasts the convexity-detection literature (Maheshwari-Neumaier-Schichl, Chinneck, Fourer et al.) as largely subsumed by the composition rule, while granting detection a role in producing smaller relaxations (pp. 9-10, 14); distinguishes itself from class-specific branch-and-cut (Audet et al., Vandenbussche) and Lagrangian approaches (Nowak) (p. 2). Criticism is by subsumption, not by attack.
- **D7 Writing and rhetoric**: The stance (LP over NLP, for speed and reliability) opens both the abstract and the introduction (p. 1); a section-by-section contribution map follows (p. 2); theorems alternate with tiny counterexamples and plots (Figs. 1-3, pp. 5-6, 13), framed as "counterintuitive properties" (p. 2). Hedges attach to the implementation ("Preliminary computational results", p. 2; "albeit preliminary", p. 15; "apparently", p. 22). The prose summary is stronger than its table: "about two thirds" of the problems get "at least an order of magnitude improvement" (p. 22), while the top row of Table 5 counts problems at least 2× better (p. 23). The conclusion repeats the headline numbers (over 93% less time and memory; nine problems not solvable before within seven CPU hours, p. 24).
- **D8 Contribution and limits**: Theory (lifted outer approximation; the composition rule subsumes detection rules), software (branch-and-cut in BARON 7.2; the CONVEX EQUATIONS construct, p. 15) and computation (87 root studies, 26 full solves, new or first-reported optima, pp. 19-23). Limits written: the cuts do not always yield the convex envelope (p. 13); multivariate convex bodies outside the rule need the modeller (p. 14); no cuts for bilinear and concave QPs (p. 18); the tls4 slowdown (p. 22). Future: the effect on classical convex programming, "the optimal mix of cutting and branching in terms of frequency and number of generated cutting planes", and partial convex hulls from feasibility and optimality arguments (p. 24).

**Method links**:
- Method 5 (evidence ✅): the stated rationale (abstract, p. 1) is carried through the body: an entirely polyhedral relaxation (pp. 1-2, 15), four initial hyperplanes chosen by experiment (p. 15), cuts only when violated and kept local (p. 15), and the one acknowledged nontrivial loss explained in time per node (tls4, p. 22). Correction for SKILL.md's Signature Work Anatomy: the operative insight of this paper is the lifted (decomposed) outer approximation (Thm. 1, Prop. 5, pp. 3-7); "constructive convex envelopes" appears only as Prop. 8 (pp. 13-14).
- Method 2 (evidence ✅): the ideas are "implemented in BARON 7.2" (p. 15) and judged as BARON with cuts on and off on one machine (pp. 17-23), reported library by library (pp. 19-21); CONVEX EQUATIONS ships as an option in the same year's manual (S012 p. 12).
- Method 1 (evidence ✅): domain reduction comes before relaxation (x and y reduced to [0, 129.77] and [1, 129.77] before the first LP, p. 16), supplies the auxiliary-variable bounds that the product underestimator needs (p. 11), and the cuts feed the probing LPs (p. 15).
- Method 4 (variant ⚠): certified values for public-library problems are published, including first solutions and a corrected optimum (Table 6, p. 23), but the comparison is a self-ablation on a test set filtered to where the cuts apply (p. 18) and on a solve set chosen by likely solvability (p. 21).
- New-pattern candidates: *Lift, then linearize (outer-approximate the decomposed form)* (pp. 2-7, 9-10); *A modeling channel for knowledge the solver cannot infer* (CONVEX EQUATIONS, pp. 14-15, 17; also S069 and S012); *Ablation reported as effect-class counts per metric* (Table 5, pp. 22-23).

**Transferable techniques**:
- Linearize composite convex functions layer by layer in lifted variables; for separable sums this reaches what direct linearization needs r^n cuts to reach (pp. 3-7).
- Start each convex univariate term with a few supporting hyperplanes (four, by angular trisection), add a cut at the LP solution only when violated, and keep cuts local to the node (p. 15).
- Before claiming that cuts help, exclude in writing the classes for which they generate nothing (p. 18), and report root-gap effects per library (pp. 19-21).
- Report ablations as counts of effect classes per metric (Table 5, p. 23) and explain every slowdown by mechanism (p. 22).
- Give tolerance-dependent optima with both tolerances (p. 23).

**Quotes**:
- "This problem is mostly linear and the cutting planes, apparently, reduce the size of the search tree at the expense of larger and more time consuming LP relaxations." (p. 22)
- "Yet, the above analysis shows that automatic detection of convexity is not essential for constructing polyhedral outer approximators of convex functions recognizable using Proposition 2." (p. 10)

### S012 · BARON 7.2.5: Global optimization of mixed-integer nonlinear programs (User's manual 2005, no DOI)
Read level: **full** (pp. 1-13; the GAMS solver-manual chapter "BARON", dated 31 March 2005, documenting v. 7.2.5, p. 3).
**Role**: core (software manual: the voice of its two authors and of the firm's product; it documents behaviour and defaults, not research results) · **Coauthors**: Mohit Tawarmalani (Purdue) · **Position in trajectory**: the GAMS manual of the BARON generation used in S003 (BARON 7.2) and S069; the log banner names "The Optimization Firm, LLC" as owner and UIUC as the origin of parts of the code (p. 3). The earliest manual read for this skill; the manual quotes in SKILL.md come from v. 2026.9.10.

- **D1 Problem and entry point**: The manual opens with the guarantee and its price: traditional NLP and MINLP algorithms converge "only under certain convexity assumptions", while BARON's branch-and-bound is guaranteed to give global optima "under fairly general assumptions", which "include the availability of finite lower and upper bounds on the variables and their expressions" (p. 1). The user's model comes first: §2 "Model requirements" precedes output and options (p. 2).
  - Transferable: open a solver manual with the model properties the guarantee depends on, before any option (pp. 1-2).
- **D2 Core idea and algorithm design**: Branch-and-reduce: branch-and-bound "enhanced with a variety of constraint propagation and duality techniques for reducing ranges of variables" (p. 2). The option list mirrors the algorithm (§5, pp. 7-13). Relaxation: LP relaxation by default (nlpdolin = 1; nonlinear relaxation is the option), four outer approximators per convex univariate function, four per variable for multivariate convex functions, four rounds of cuts, 20 grid points (p. 9). Five range-reduction families, each with its own switch and all on by default: nonlinear-feasibility ("poor man's NLPs", tdo), marginals (mdo), linear-feasibility ("poor man's LPs", lbttdo), optimality-based (obttdo) and probing on all branching variables (pdo = −1) (p. 9). Probing is rationed by depth and frequency (pstart, pend, pfreq = 3, i.e. every third level) and kept off binaries (pbin = 0) (p. 10). The reduce/re-relax loop is capped: at most maxredpass = 10 reduction calls before a new relaxation, at most maxnodepass = 5 relaxations per node, repeated only while the bound improves by redreltol/redabstol = 0.1 (p. 10). Branching: dynamic variable and point rules, with ω-, bisection- and convex-combination points (convexratio 0.7) (pp. 10-11), on original variables only by default (numbranch = 0, p. 11). Local search: a dynamic rule and ten preprocessing local searches (numloc = 10, p. 11). Node postponement exists but is off (p. 13). Features: no starting point needed (p. 5); the best K or all feasible solutions found in a single search tree instead of user-coded integer cuts (numsol, pp. 5-6); BARON as a multistart heuristic (numloc, maxiter = 0), where the preprocessor's range reduction "increases the likelihood of finding high quality local optima" (p. 6).
  - Transferable: give each reduction family its own switch and cap the reduce → re-relax passes per node with an improvement threshold; one mechanism then serves both rationing and ablation (pp. 9-10).
- **D3 Assumptions and model**: Finite bounds on all nonlinear variables and expressions; 1/x on [0, 1] shows that bounded variables do not bound expressions (p. 2). If the preprocessor cannot infer bounds, global optimality "is not guaranteed", and BARON may terminate when no numerically stable lower-bounding problem can be built (p. 2). Allowed functions: exp, ln, x^α, β^x, x^y, |x|; no trigonometric functions (p. 2). A licensed LP solver is required and an NLP solver optional (p. 2). Declared constraint classes (relaxation-only, convex, convex relaxation-only) are used as declared (equclass, p. 12); the 2005 text does not say they are checked.
  - Transferable: give each model requirement a one-line counterexample (1/x on [0, 1], p. 2).
- **D4 Analysis and proof devices**: n/a (no proofs; the guarantee is asserted, p. 1). In their place: a termination taxonomy that pairs every status with a user action (pp. 4-5), and return codes saying where the best solution came from (−3 none, −2 user-supplied, −1 preprocessing, i a tree node) (p. 4).
- **D5 Numerical experiments**: None beyond one annotated log (gear.gms: 46 iterations, 0.13 s, time split into parsing, preprocessing, navigating, relaxed, local, tightening, marginals and probing; pp. 3-4) and the numsol example (a small integer program with 18 feasible solutions, pp. 5-6). Defaults that shape any run at defaults: epsa = 1e-9, epsr = 0.1 (equivalent to GAMS optcr), maxtime = 1200 s, constraint tolerance 1e-5, box tolerance 1e-5, integrality tolerance 1e-6 (pp. 8-9). Cross-check with the papers of the same year: S069 speaks of "BARON's default 10−6 optimality tolerance" in BARON's own language (S069 p. 9), S003 sets 10^-6 and 10^-9 explicitly (S003 p. 21), and S003's default feasibility tolerance of 10^-5 (S003 p. 23) matches contol here (p. 8).
  - Transferable: print time per component (tightening, marginals and probing next to relaxation and local search) in every solver log (p. 3).
- **D6 Literature positioning**: Contrasted only with "traditional NLP and MINLP algorithms" (p. 1) and with the integer-cut practice for multiple solutions (p. 5); points to the Tawarmalani-Sahinidis book for details (p. 5).
- **D7 Writing and rhetoric**: Imperative and user-facing; statuses are written as instructions: numerical difficulties "should be reported to the developers" (p. 4); with missing bounds the user must "fix the formulation, or be content with the solution provided", which "may not be globally optimal" (p. 5). The best bounds are "physically meaningful bounds" supplied by the modeller (p. 7). Usage tips sit inside option tables, e.g. that first-order optimality conditions added as relaxation-only constraints often expedite convergence (p. 12). Small slips: "See §4 on the BARON options" points to §5 (p. 2); "lpttdo" on p. 6 vs "lbttdo" in the table (p. 9).
- **D8 Contribution and limits**: Documentation of a commercial solver with academic roots (p. 3). Limits written: missing bounds void the guarantee (pp. 2, 5); no trigonometric functions (p. 2); numerical difficulties go to the developers (p. 4); memory (32 MB by default, room for 198,200 nodes on gear, pp. 3-4). Not written: that "*** Normal Completion ***", described as "solved within tolerances" (p. 4), allows a relative gap of up to 0.1 at the GAMS default (p. 8); that declared classes are unchecked (p. 12); the multistart section carries no warning that its value is uncertified, unlike the 2026 wording quoted in SKILL.md Heuristic 7 (p. 6). No future directions.

**Method links**:
- Method 1 (evidence ✅): all five reduction families on by default and individually switchable (p. 9); probing rationed by level (pfreq = 3) and kept off binaries (p. 10); the reduce → re-relax loop capped per node (maxredpass, maxnodepass, p. 10); range reduction even in multistart preprocessing (p. 6). Heuristic 7 (variant ⚠): proof and evidence are kept apart for missing bounds (pp. 2, 5) but not spelled out for the loose default gap or for multistart (pp. 4, 6, 8).

### S069 · Accelerating branch-and-bound through a modeling language construct for relaxation-specific constraints (Journal of Global Optimization 2005, doi:10.1007/s10898-004-2705-8)
Read level: **full** (pp. 1-24 of the Kluwer preprint, footer "rlxn.tex; 5/02/2004"; references pp. 22-24 skimmed).
**Role**: core · **Coauthors**: Mohit Tawarmalani (Purdue) · **Position in trajectory**: companion of S003 in the BARON 7.x period; the source SKILL.md cites for Heuristic 2's relaxation-only constraints and Workflow B1 step 4, now read in full; its §2 is the most detailed account of the branch-and-reduce loop in this batch (pp. 3-7).

- **D1 Problem and entry point**: Entered from a convention of the tools: "In the tradition of modeling languages for optimization, a single model is passed to a solver for solution." (abstract, p. 1). The observation: nonlinear reformulations can tighten the relaxation while making local search much harder (p. 2). A one-variable demonstration: for a degree-50 polynomial on [1, 2] taken from Moore, adding the stationarity condition lets BARON prove globality at the root instead of after 29 nodes, while MINOS, which finds the global solution in 5 iterations without it, declares the problem locally infeasible after 15 iterations with it (pp. 8-9).
  - Transferable: open with a one-variable case where the same constraint helps one solver component and hurts another, with node and iteration counts (pp. 8-9).
- **D2 Core idea and algorithm design**: Let the modeller pass two models. RELAXATION ONLY EQUATIONS go through BARON's reformulator, relaxation constructor and constraint propagation but stay out of the local-search model; LOCAL ONLY EQUATIONS are proposed for full separation (p. 9). Three sources of redundant but tightening constraints: two RLT product families (3)-(4) for pooling, giving the pq-formulation (pp. 10-12); first-order conditions for box-constrained univariate polynomials, with the endpoints handled separately (pp. 15-16); problem-specific optimality conditions for SAT, every clause term set to zero (pp. 18-19). Kept: the whole branch-and-reduce engine, described in §2: an almost-separable reformulation that retains bilinear terms (p. 3); a relaxation that dominates McCormick's by recognizing common subexpressions, adopted by gProms and LINGO, and by default outer-approximated further into "an entirely polyhedral outer-approximator" (p. 4); root preprocessing by min/max LPs over the linear constraints, interval propagation, random multistart inside the reduced box, the objective cut f(x) ≤ f* propagated whenever the incumbent improves, and preprocessing LPs approximated by Fourier-Motzkin elimination one constraint at a time [25] (pp. 4-5); node postprocessing by marginals-based reduction and by probing LPs solved only for variables that contribute significantly to the gap, with cheaper tightening for the rest (pp. 5-6); branching on original variables chosen by the apportioned underestimation gap with violation transfer, at a convex combination of the relaxation point and the midpoint, or at an interior incumbent for finiteness (p. 6); node selection by least lower bound at least occasionally, by small violation to find feasible points early, and LIFO under memory pressure (p. 6); cheap reductions at every node (p. 7). Changed: only the modeling interface.
  - Transferable: give the solver a separate channel for constraints that are redundant for the model but tighten the relaxation, so the local solver never sees them (p. 9).
  - Transferable: spend probing LPs only on the variables that carry the relaxation gap at the current solution, and use propagation for the rest (pp. 5-6).
- **D3 Assumptions and model**: Factorable objective and constraints (p. 3); all variables bounded (p. 4). The validity of relaxation-only constraints is the modeller's responsibility: they are described as "redundant from the modeling point of view" (p. 20), and the text describes no check on them (pp. 9-10). Runs are limited to 32 MB of memory (pp. 14, 20) and, for pooling, to 1200 s (p. 16).
- **D4 Analysis and proof devices**: n/a for theorems; the dominance over McCormick's relaxation and the finiteness of the branching rule are cited ([35] p. 4; [25] p. 6). Mechanisms are explained instead: the root proof of §4 is attributed to "feasibility-based range reduction in conjunction with the objective function cut" (p. 9); the local solvers' failures to the nonconvexity of the first-order condition (p. 17); the SAT comparison is split into total, preprocessing and in-tree local-search time (pp. 20-21).
- **D5 Numerical experiments**: One machine (Dell Precision 530, 1.7 GHz Xeon, 32 MB) (pp. 14, 20); three strategies per application: (1) the original model, (2) the strengthened model, (3) the strengthened model through the construct (pp. 13, 17, 20); the local solvers CONOPT and MINOS measure the harm (pp. 12-14, 17). Pooling (14 literature problems): pq makes CONOPT find worse local optima on 8 of 14 with CPU almost doubled, and costs MINOS 30% more CPU (p. 12); BARON on the q-formulation hits the 1200 s limit on six problems, while pq solves all, most at the root (pp. 14, 16); strategies 2 and 3 take no more than five times the local-search time (p. 15); strategy 3 is slower than 2 on foulds3 (1 → 5 s), and Table IV's totals are 10 s for strategy 2 vs 12 s for strategy 3 (pp. 14, 16). Polynomials (7 problems from Ryoo-Sahinidis [20]): with the condition, the local solvers report infeasibility on p2 and p3 and do worse on p5 and p7 (Table V, p. 17); BARON needs 90% fewer nodes (305 → 29), CPU negligible (pp. 17-18). SAT (10 DIMACS instances from SATLIB): strategies 2-3 vs 1 cut nodes by 60%, memory by 94% and CPU by 57%; strategy 3 vs 2 differs by under 1% in nodes and about 3% in CPU, but preprocessing and in-tree local-search times fall from 44 and 20 s to 2 and 3 s; ii8a2 is called "a pathological case" (pp. 20-21). Stated aim for SAT: "not necessarily to provide a competitive algorithm" (p. 19). No other global solver is compared.
  - Transferable: when the claim is that global search is unchanged while local search gets cheaper, report total, preprocessing and in-tree local-search times separately (Tt, Tp, Tl), so the claim can be checked even when totals barely move (pp. 20-21).
  - Transferable: express global-solve time as a multiple of a local solve on the same instances (p. 15).
- **D6 Literature positioning**: The modeling-language tradition (GAMS, AMPL) and global-optimization modeling languages (BARON, NUMERICA, NOP-2; gProms, MINOPT) (p. 2); BARON's history and the naming of branch-and-reduce (p. 2); McCormick's relaxation recast and claimed dominated (p. 4); Sherali-Adams RLT as the source of the pooling constraints, via the authors' book (pp. 10, 12); first-order conditions were used before only for exclusion tests in interval solvers (GlobSol, Numerica), and the paper claims "the first such computational experimentation" for relaxations (p. 15); symmetry-breaking constraints (Sherali-Smith) named as a further case (p. 18).
- **D7 Writing and rhetoric**: The abstract gives one result sentence per application (p. 1); the "two models" framing recurs (abstract p. 1, pp. 2, 9). The conclusion concedes the point at stake, that the construct's CPU gains over simply adding the constraints are not significant for global search, and then rests the case on what the construct may motivate modellers to try (p. 22). Hedges: "apparently" (p. 9), "Apparently" (p. 17), "seems to serve its purpose" (p. 20), "We conjecture" (p. 22). Small slips: the construct is spelled "RELXATION" twice (pp. 9-10); strategy 3's memory rises from 56 to 69 nodes against strategy 2 while the text says global search is not compromised (Table VII, pp. 20-21).
- **D8 Contribution and limits**: Software and modeling (a construct in BARON's language), three demonstrations, and a public description of BARON's algorithm (pp. 3-7). Limits written concretely: no significant global-search gain over plain addition (p. 22); the foulds3 and ii8a2 exceptions (pp. 14, 20); not a competitive SAT solver (p. 19). Future: automate RLT's reformulation step and combine it with RLT relaxations of first-order conditions and constraint filtering; generate relaxations of optimality conditions automatically for any model; convexify relaxation-only constraints and give them to local search, stated as a conjecture (p. 22).

**Method links**:
- Method 1 (evidence ✅): stated, "Because considerable emphasis is placed on the reduction of variable bounds, the overall methodology is referred to as branch-and-reduce" (p. 2); practised: cheap reductions at every node (p. 7), probing rationed to gap-carrying variables (p. 5), the incumbent cut propagated at every new upper bound (p. 5), and the §4 gain explained by range reduction (p. 9). The Fourier-Motzkin approximation of bound LPs, credited to Shectman and Sahinidis 1998 (p. 5), is an early form of the Fourier-Motzkin presolve that SKILL.md lists for 2023-2026.
- Method 5 (evidence ✅): the default relaxation is polyhedral because it "can be solved efficiently and reliably via linear programming techniques" (p. 4); the construct is judged by what the constraints cost the local solvers (pp. 12-21).
- Method 2 (evidence ✅): modeling languages for global optimization "facilitate the automation and systematic testing of global optimization algorithms" and serve as a vehicle for testing new language concepts (p. 2); specialized modules for special classes came first, then the modeling language with factorable reformulation, then a considerable rewrite of solver and language (p. 7); the feature is evaluated as three strategies inside BARON on one machine (pp. 13-21) and ships in the same year's manual (S012 p. 12).
- Heuristic 2 (evidence ✅): the paper itself; problem knowledge (RLT products, stationarity, clause conditions) is passed to the relaxation (pp. 9-20). Heuristic 1 (evidence ✅): specialized modules for special classes preceded the general modeling language (p. 7).
- New-pattern candidates: *Two models for one problem: relaxation model vs local-search model* (pp. 1-2, 9; S012 p. 12; S003 p. 15); *Redundant constraints that tighten relaxations without entering local search (RLT products, stationarity, problem-specific conditions)* (pp. 10-20).

**Transferable techniques**:
- Declare constraints that are valid but harmful to local search as relaxation-only (pp. 9-10); candidates are RLT products (pp. 10-12), first-order conditions (pp. 15-17) and problem-specific optimality conditions (pp. 18-20).
- Run three arms (original, strengthened, strengthened relaxation-only) and report the local solvers on the strengthened model next to the global solver (Tables II-VII, pp. 12-21).
- Split CPU time into total, preprocessing and local search (pp. 20-21).
- Propagate the objective cut f(x) ≤ f* each time the incumbent improves (p. 5).
- Approximate the bound LPs by one-constraint Fourier-Motzkin steps when only a few bounds have changed (p. 5).

**Quotes**:
- "The work is motivated by the observation that nonlinear problem reformulations can often tighten the relaxation process of a branch-and-bound algorithm while making local search considerably more difficult." (p. 2)
- "CPU time gains by using this construct as opposed to merely adding the nonlinear constraints to the nonlinear formulation were not significant as far as global search is concerned" (p. 22)

### S015 · GPU-BLAST: using graphics processors to accelerate protein sequence alignment (Bioinformatics 2011, doi:10.1093/bioinformatics/btq644)
Read level: **full** (pp. 1-7; reference list p. 7 skimmed).
**Role**: core · **Coauthors**: Panagiotis D. Vouzis (CMU Chemical Engineering, p. 1) · **Position in trajectory**: the CMU computational-biology and GPU-computing line (Sahinidis is also listed with the Lane Center for Computational Biology, p. 1); outside optimization; received June 3, 2010, accepted November 12, 2010 (p. 1); open-source (abstract, p. 1). 06-trajectory.md places it in the group's 2008-11 GPU work.

- **D1 Problem and entry point**: Impact first: BLAST has "over 53 000 citations" and became a verb, so any speed-up matters (abstract, p. 1). Large existing speed-ups need custom hardware or supercomputers, which most BLAST users cannot reach (p. 1). Commodity alternatives change the answers: PLAST is up to 5.6× faster but its alignments differ by up to 5.9%; Ling and Benkrid's GPU code (1.7-2.7×) is not guaranteed identical; Liu's GPU code (6×), run by the authors at defaults, gave different alignments for all 51 test queries (pp. 1-2). The adoption constraint: users are reluctant to use a BLAST whose alignments are not identical to NCBI-BLAST's (p. 2). Problem: GPU acceleration on a desktop machine (about $1500 for a PC plus GPU, p. 1) with the same interface and identical output.
  - Transferable: turn the users' acceptance criterion (identical output to the reference code) into the design constraint, and test the rivals against it on your own query set (p. 2).
- **D2 Core idea and algorithm design**: Build "directly on top of the NCBI-BLAST code" (p. 2). Profile first: seeding and ungapped extension take over 95% of the time for ungapped and 75% for gapped alignments, so only those steps are parallelized (Fig. 1, pp. 2-3). Place each data structure by size and access pattern: presence bit vector and substitution matrix in shared memory, the query in constant memory, index and overflow tables and the database in global memory (Fig. 2, pp. 3-4). One database subject per GPU thread; the database is sorted by length once, at formatting, to cut warp divergence (p. 4); small fixed slots (up to 3 word locations, up to 2 high-scoring pairs per subject), with the overflow handed to the CPU (p. 4); the CPU aligns a predetermined fraction of the database concurrently, the fractions fixed "after extensive experimentation" (p. 5). "-gpu F" returns to the NCBI-BLAST execution path (p. 5). Kept: the BLAST algorithm and most data structures; changed: the mapping onto hardware.
  - Transferable: profile the reference code by phase and move only the dominant phases; their time shares then bound the achievable speed-up (pp. 2-3, 6).
  - Transferable: sort work items once, offline, so the threads of a warp receive similar work (p. 4).
- **D3 Assumptions and model**: An NVIDIA Fermi C2050 GPU (448 cores at 1.15 GHz, 3 GB) with a six-core 2.67 GHz Xeon host and 12 GB (p. 5); CUDA only, hence NVIDIA only, with OpenCL promised (p. 5); blastp only (pp. 5, 7); the GPU database is built once per database and its cost "amortized over thousands or millions of future queries" (p. 5); database creation cannot use multiple threads (p. 5).
- **D4 Analysis and proof devices**: n/a (no proofs). Analysis by accounting: peak GFLOPS about 8× the CPU's against an observed speed-up of about 4×, attributed to warp divergence (p. 6); ungapped faster than gapped because 95% vs 75% of the work moves to the GPU (p. 6); lower speed-ups for short queries because seeding and extension are a smaller share there (p. 6).
- **D5 Numerical experiments**: The env_nr protein database (6,031,291 sequences, 1.3 GB, October 2010) and 51 mouse queries of length 2-4998 from UniProt, shipped in the distribution's 'queries' directory (p. 5). Baselines: NCBI-BLAST with one and six threads (Fig. 4A), one to six CPU threads beside the GPU (Fig. 4B), and speed-ups relative to a single CPU thread (Fig. 5) (pp. 5-7). Timing: start-to-finish wall clock, including writing the output file (pp. 6-7). Losses reported: single-threaded GPU-BLAST is faster except on the length-2 query; six-threaded GPU-BLAST pays only for sequences longer than 500 amino acids (p. 6); NCBI-BLAST itself scales sublinearly (under 4× on six threads), and GPU-BLAST "inherits some of these limitations" (p. 6). One database and one GPU model; no timing comparison with the other GPU codes. Headline figures depend on the baseline: "mostly between 3 and 4" (abstract, p. 1), "up to 4 times" vs single-threaded and "nearly twice" vs six-threaded NCBI-BLAST (p. 2), "nearly six" for six-threaded GPU-BLAST vs one CPU thread (p. 6).
  - Transferable: ship the benchmark inputs with the code so the speed-up study can be rerun (p. 5).
  - Transferable: report speed-up against instance size and thread count, and say where it stops paying (p. 6).
- **D6 Literature positioning**: Custom hardware (Sotiriades and Dollas), Blue Gene (Lin et al.), multicore BLAST+ (Camacho et al.), PLAST (Nguyen and Lavenier) and the GPU BLASTs of Ling and Benkrid and of Liu (pp. 1-2); a list of GPU successes in bioinformatics (p. 1); a caution, citing Elble et al. 2010, that algorithms that perform well on a CPU may not on a GPU (p. 1). Rivals are judged on output identity first and speed second (pp. 1-2).
- **D7 Writing and rhetoric**: A structured abstract (Motivation, Results, Availability) with the code URL (p. 1); citation counts as the impact argument (abstract, p. 1); "identical results" repeated as the contribution (abstract p. 1, pp. 2, 6); speed claims hedged ("mostly", "nearly", "likely to facilitate the adoption", pp. 1-2); future work hedged with evidence: PSI-BLAST's profile is almost identical to Fig. 1B, so similar speed-ups "are likely" (p. 7).
- **D8 Contribution and limits**: Software and engineering: open-source GPU-BLAST with output identical to NCBI-BLAST (abstract p. 1, pp. 2, 6). Limits written: blastp only, NVIDIA only, the inherited sublinear CPU scaling, no gain for short sequences at six threads (pp. 5-6). Future: PSI-BLAST and other BLAST methods; OpenCL (pp. 5-7).

**Method links**:
- Method 2 (variant ⚠): the new component is built inside an existing production code and carries an exact on/off switch ("-gpu F" follows the NCBI-BLAST path, p. 5), and the evaluation is the same code with the component on and off (pp. 5-7). The host code is NCBI's, not the group's, so this matches Method 2's lone version (contribute a module to an open code) rather than the BARON pattern.
- Method 4 (variant ⚠): the yardstick is the reference implementation's exact output, an analogue of certified ground truth, and a rival was run against it on the same 51 queries (p. 2); there is no head-to-head speed benchmark of the existing GPU codes.
- Research Taste mark 1 (evidence ✅): the source code is freely available (abstract, p. 1), and the queries ship with it (p. 5).
- New-pattern candidates: *Profile, then accelerate only the dominant phases* (pp. 2-3, 6; per-component time accounting also in S012 p. 3 and S069 pp. 20-21); *Identical output to the reference code as the acceptance test* (pp. 1-2, 6).

**Transferable techniques**:
