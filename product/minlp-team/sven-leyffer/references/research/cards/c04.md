### S020 · Numerical experience with solving MPECs as NLPs (Numerical Analysis Report NA/210, Department of Mathematics, University of Dundee 2002, no DOI)
**Read level**: full: body pp. 1–18 and references pp. 18–20 read line by line; Appendix A (problem characteristics, pp. 21–23) and Appendix B (iteration counts and CPU times per problem, pp. 24–29) skimmed with spot checks of individual rows.
**Role**: core · **Coauthors**: Roger Fletcher · **Position in trajectory**: the benchmarking companion to the local-convergence analysis of SQP for MPECs (Fletcher, Leyffer, Ralph, Scholtes, NA/209, cited as [19], p. 19) and the launch document of the MacMPEC library; the report is the forerunner of the OMS 2004 paper S013 (different title, per the work list note).

- **D1 Problem and entry point**: Enters by contesting a received verdict: MPECs violate MFCQ, so the multiplier set is unbounded, which has been taken as an argument against NLP techniques for MPECs (§2.1, p. 2); previous numerical experience with the NLP formulation was "rather disappointing" (Bard reports 50–70 % failures; §2.2, p. 3). Problem stated as MPEC (1.1) with control z0 and state pair (z1, z2) under 0 ≤ z1 ⊥ z2 ≥ 0, then as the equivalent NLP (1.2) with z1ᵀz2 ≤ 0 (pp. 1–2). The aim, stated as such: use off-the-shelf NLP solvers on large MPECs (abstract, p. 1).
  - Transferable: open a computational paper by quoting the theoretical objection that is used to dismiss your approach, then cite the theory that neutralises it (strong stationarity of (1.1) ⇔ KKT multipliers for (1.2), p. 2) before showing numbers.
- **D2 Core idea and algorithm design**: No new algorithm; the idea is that a careful formulation plus a reliable SQP solver suffices. Three formulation choices carry it: (i) general complementarity rewritten in form (1.1) by slacks, with the claim that nothing is lost in CQs or second-order conditions (p. 1); (ii) z1ᵀz2 ≤ 0 instead of z1ᵀz2 = 0, without which SQP cannot in general converge quadratically near a strongly stationary point (p. 3); (iii) relaxing the linearization of the complementarity constraint plus a restoration phase instead of an elastic mode, since QPs can be inconsistent arbitrarily close to a strongly stationary point (p. 3; perturbation (3.4) with δ, κ, p. 6). Implemented as filterMPEC, an AMPL interface that turns AMPL's `complements` structure (3.1) into NLP (1.2): equality when bounds coincide, slacks otherwise, no slack when F is already a simple bound, a single summed nonlinear complementarity equation; modifications to constraint, gradient and Hessian evaluation described as relatively minor, overhead negligible with sparse storage (§3, p. 5). Advantages over writing the NLP in AMPL directly: transparency, presolve for complementarity, one code for NLP and MPEC (pp. 5–6). Solver options: initial slack, compl_tol (smoothed mode ε), delta, kappa (p. 6).
  - Transferable: add a structure-aware front end (here an AMPL solver hook) to an existing solver so the user writes the problem class natively and the reformulation (slacks, aggregation) is hidden and done the same way every time (pp. 5–6).
- **D3 Assumptions and model**: Problems of form (1.1) with smooth f, c (p. 1). Theory relied on (from [19], not proved here): MPEC-LICQ gives a ray of multipliers with a minimal (basic) multiplier (2.2); SQP converges quadratically to it provided all QPs remain consistent, an assumption shown to hold for a class with vertical complementarity 0 ≤ G(z) ⊥ H(z) ≥ 0 (p. 3). Admitted: all NLP solvers assume some CQ, so without MFCQ convergence cannot be expected (§5.1, p. 9). Interface restriction admitted: complementarity yi ⊥ lF ≤ Fi ≤ uF with lF < uF not handled; the authors say it is not clear how best to model it within an NLP (p. 5).
  - Transferable: when your evidence depends on a convergence theory whose key hypothesis (QP consistency) is not guaranteed, name that hypothesis and the subclass where it is known to hold (p. 3).
- **D4 Analysis and proof devices**: No theorem is proved in this report; results are recalled from [19] and Anitescu [1] (pp. 2–3). Devices used: (a) a two-variable worked example, min z1 + z2 s.t. 0 ≤ z1 ⊥ z2 ≥ 0 from z(0) = (1, 1), where writing z1z2 = 0 gives iterates z(k) = 2^{-k} z(0) (linear rate, multiplier diverging) while z1z2 ≤ 0 converges in one iteration (p. 3); (b) explicit unbounded-multiplier construction: any ν̂1, ν̂2, ξ̂ keeping τ1 = ν1 − ξ z2, τ2 = ν2 − ξ z1 fixed also satisfy (2.1) (p. 2); (c) a one-dimensional pathological instance (dempe) analysed by hand: lower-level solution z(x) piecewise, two local minima x = 1 and x = 0, the latter violating MFCQ and not even B-stationary (pp. 11–12).
  - Transferable: before a benchmark, show on a two-variable instance with closed-form iterates why the formulation choice matters (here, = vs ≤ in the complementarity constraint, p. 3).
- **D5 Numerical experiments**: 137 MPECs from the new MacMPEC library (83 LCP, 15 NCP, 39 KKT lower levels; size quantiles in Table 1, pp. 7–8), four NEOS solvers: filterMPEC (trust-region SQP, filter, exact Hessian), KNITRO, LOQO (interior point), SNOPT (line-search SQP, quasi-Newton, elastic mode) (p. 9). Failure taxonomy: catastrophic (1000 major iterations or step/trust region too small at a non-stationary point, likely MFCQ-related) vs soft (locally inconsistent termination, not MFCQ-related); only catastrophic ones count as problematic (§5.1, p. 9). Table 2: catastrophic/infeasible = filterMPEC 0/7, KNITRO 19/6, LOQO 20/0, SNOPT 1/4 (p. 9). Attribution control experiment: rerun each IPM failure with complementarity replaced by z1ᵀz2 ≤ 10⁻² (Tables 3–4): LOQO still fails 11 of 20 and solves only 7 correctly; KNITRO solves 13 of 19; conclusion that IPM failures are "not solely due" to MFCQ failure (pp. 10–12). Dolan–Moré performance profiles by iterations and by CPU time, with the stated reason for using both (iterations isolate algorithm from linear algebra; CPU compares solver classes); catastrophic failures set to 1E6 iterations / 1E8 s so they appear as an asymptote, infeasibility exits not penalized (§5.2, p. 12; Figs. 1–2, pp. 13–14). A theory-motivated diagnostic profile: relative size of the complementarity multiplier ξ, restricted to problems all solvers solved to the same solution (Fig. 3, pp. 13–15); IPM multipliers several orders of magnitude larger, and the curves track the iteration profile (p. 13). Stationarity type of filterMPEC limits checked: strongly stationary except ex9.2.3, ralph1, ralphmod, scholtes5 (B-stationary with linear rate on the two known to lack strongly stationary points) (pp. 13–14). Comparison against special-purpose MPEC solvers by iteration counts copied from the literature, labelled "tentative": Fukushima–Luo–Pang (Table 5, regenerated random instances with the MATLAB generator published online, p. 15), Facchinei–Jiang–Qi AS (Table 6, p. 16), Dirkse–Ferris BUNDLE and PIPA-B (Table 7, p. 17) with a name-mapping table (p. 17). Per-problem iteration counts and CPU times in Appendix B (pp. 24–29).
  - Transferable: split failures into failures of the algorithm vs ordinary exits before counting, and penalize only the first in the profiles (pp. 9, 12).
  - Transferable: to test whether a suspected cause explains failures, rerun only the failed instances with that cause removed (here complementarity relaxed to ≤ 10⁻²) and tabulate the outcome per instance (Tables 3–4, pp. 10–11).
  - Transferable: plot the quantity your theory singles out (multiplier size) as a profile next to the performance profiles, on the subset where all solvers agree (Fig. 3, p. 13).
  - Transferable: when comparing to results you cannot rerun, publish the instance generator, map problem names, say why per-iteration work is comparable, and call the comparison tentative (pp. 14–15, 17).
- **D6 Positioning**: Continues [19] (local SQP convergence for MPECs) and Anitescu's elastic-mode global convergence (p. 3); surveys smoothing (Ferris–Kanzow, Scheel–Scholtes), penalization, Facchinei et al.'s smoothed min-function, Jiang–Ralph Fischer–Burmeister SQP, PIPA, implicit programming, and Dirkse–Ferris–Meeraus's 23 smooth reformulations, marked with "(!)" (p. 4). Direct correction of named predecessors: Conn et al. and Ferris–Pang attribute LANCELOT's failure on LUBRIF to complementarity, but the model minimizes complementarity and has no complementarity constraint; the authors suspect local inconsistency (p. 3, repeated p. 10: earlier studies have sometimes drawn erroneous conclusions by blaming MFCQ failure). PIPA can converge to non-stationary points, citing Leyffer's own NA/208 (p. 4). Closing claim: SQP solvers provide the benchmark against which the efficiency and robustness of MPEC solvers should be measured (p. 18).
  - Transferable: when correcting a published attribution, go back to the model file and state what it actually contains (p. 3).
- **D7 Writing and rhetoric**: Key claim stated in the abstract with a time stamp: SQP methods "at present outperform Interior Point solvers both in terms of speed and reliability" (p. 1); contribution sentence at the end of the introduction: the paper demonstrates that a large class of MPECs can be solved successfully as NLPs (p. 2). Hedging is concentrated on the literature comparison (tentative comparisons, conclusions by necessity tentative, pp. 14–15, 17) and on causes (suspected, possibly due to, pp. 3, 12–13); surprise marked openly ("!" on the robustness of SQP vs specialised solvers, p. 17). Theory is recalled briefly and only where it explains a numerical observation (p. 3, p. 12).
  - Transferable: put the time stamp ("at present") into the comparative claim itself in the abstract (p. 1).
- **D8 Contribution and limits**: Contribution levels: software (filterMPEC interface), test library (MacMPEC, classification scheme XXX-XX-CCC-n-m-p extending the CUTE scheme with model origin and complementarity type, §4.1, p. 7; models online with comments and references, p. 6), empirical (benchmark, pp. 9–17). Concrete limits: perturbation (3.4) properties stated to be under investigation and linear convergence for κ = 0 (p. 6); interface does not handle one complementarity form (p. 5); literature comparisons on non-identical instances (p. 15); IPM improvements in progress (pp. 13, 18); filterMPEC converges only linearly to B-stationary points when no strongly stationary point exists (p. 14). Future directions: IPM modifications based on the multiplier observation, more comparisons, MPEC solvers matching NLP robustness (pp. 13, 17–18). Library motivation stated twofold: test own ideas, motivate research by others (p. 7). Novel models: inverse QPs following Scholtes; water networks where a big-M MINLP model with binaries is replaced by a complementarity disjunction 0 ≤ q⁺ ⊥ q⁻ ≥ 0 (p. 8).
  - Transferable: when building a library, add a classification string that records origin (academic / modelling / real) and the structural type relevant to your algorithms, so conclusions can be drawn per class (§4.1, p. 7).

**Transferable techniques**:
