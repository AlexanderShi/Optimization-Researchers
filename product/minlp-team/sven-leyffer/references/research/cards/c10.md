### S028 · On branching rules for convex mixed-integer nonlinear optimization (Journal of Experimental Algorithmics (JEA) 2013, doi:10.1145/2532568)
**Read level**: full, of the TR version (pp. 1–21 read in full; appendix tables pp. 22–34 skimmed: headers, Table 1 instance list, a sample of rows of Tables 2–6). First-page check: the file is "More Branch-and-Bound Experiments in Convex Nonlinear Integer Programming", Pierre Bonami, Jon Lee, Sven Leyffer, Andreas Wächter, Preprint ANL/MCS-P1949-0911, 5 October 2011 (TR p. 1). Same four authors as the JEA paper; the SKILL.md source list already ties this preprint (optimization-online 2011/09/3191) to doi:10.1145/2532568. The JEA journal text, with its changed title, is not read.
**Role**: core · **Coauthors**: Pierre Bonami (Marseille), Jon Lee (Michigan), Andreas Wächter (Northwestern) (TR p. 2) · **Position in trajectory**: "MINLP as team science" period (2006–2013, Turn G); a direct sequel to his own 2001 SQP-in-B&B paper (ref [28], TR p. 21) and to the Bonmin/FilMINT line, with Fletcher's BQPD at the core (acknowledgement, TR p. 19).

- **D1 Problem and entry point**: Entry by revisiting an abandoned method: B&B for convex MINLP was "largely given up on" in favour of OA-based branch-and-cut that solves LPs at nodes, and the paper asks whether it "can still be made viable" (TR p. 3). The gap is dated: the last systematic branching study for MINLP B&B is Gupta and Ravindran, "approximately 25 years" earlier, which tested only priorities, most-fractional and pseudo-costs with a GRG solver (TR p. 3). Three goals are listed: (i) is B&B viable, (ii) guidance for B&B code developers, (iii) a state-of-the-art B&B code usable as is and as a starting point (TR p. 3). Scope is cut explicitly: stronger relaxations "not addressed here"; only tree building and exploration (TR p. 4).
- **D2 Core idea and algorithm design**: First transfer the MILP branching toolbox (random, most-fractional, strong, pseudo-cost, reliability with list-r and lookahead-ℓ limits) into NLP-based B&B unchanged (§3, TR pp. 6–8); then diagnose why strong branching is too slow in the nonlinear case: no analogue of dual-simplex hot starts, and every NLP iteration refactorizes Jacobian and Hessian (TR p. 11). The new idea: replace each strong-branching child NLP by a QP built at the parent's solution (x*, y*) with H* ≈ ∇²L, so the KKT matrix is constant and BQPD can be hot-started from a stored factorization for every candidate (TR pp. 11–13). An LP (outer-approximation) variant gives valid bounds but loses curvature (TR p. 15); an ECP-augmented LP was tried and "did not lead to improved performance" (TR p. 16). What is not changed: node selection (best parent bound), no heuristics, branching on single variables only (TR p. 5).
- **D3 Assumptions and model**: f and gᵢ convex and twice continuously differentiable (TR p. 4). The QP's optimal value equals the NLP relaxation value "provided that a constraint qualification holds at x*" (TR p. 12; same for the LP, TR p. 15). By convexity, QP infeasibility implies NLP infeasibility, so infeasible QP children can still fix variables or fathom, but QP child values "are not reliable lower bounds" and cannot be used for fathoming; LP child values are valid bounds (TR pp. 12, 15). The strong-branching score weight μ is set to 0.7 before and 0.1 after the first incumbent, with no justification given (TR p. 7).
- **D4 Analysis and proof devices**: No theorems; the paper says outright that for integer programming "there is no guidance coming from theory" for preferring a branching rule (TR p. 5). Devices used: (a) convexity argument for which approximate child values are valid bounds and which are only guides (TR pp. 12, 15); (b) a linear-algebra account of the hot start: null-space factors [A : V] = LU, Y and Z with AᵀY = I, AᵀZ = 0, an L̃DL̃ᵀ factorization of the reduced Hessian ZᵀH*Z, and the block inverse of K written through W, T, U, none formed explicitly; the factorization at the parent QP is stored and restored for each candidate and updated by pivoting (TR p. 13).
- **D5 Numerical experiments**: All rules implemented in C++ inside Bonmin (revision 1714 of trunk) with filterSQP and BQPD (TR p. 5). Test set: about 150 instances from MacMINLP, MINLPLib, the CMU-IBM set and a personal communication; filtered to 88 by removing instances solved in under 1000 nodes by all tested B&B methods and those unsolved by all in 3 hours (TR p. 5; Table 1, TR pp. 22–24). Performance profiles in both CPU time and node count (Figs. 1–4, TR pp. 9–12), scatter plots for NLP vs QP strong branching (Figs. 5–6, TR pp. 14–15) and hot vs cold QP (Fig. 7, TR p. 16); per-instance CPU and node tables with "> 10800" time-outs kept (Tables 2–6, TR pp. 25–34). Findings: full strong branching gives the smallest trees but is not competitive in time; NLP-reliability with k_rely = 1 is the best basic rule; list and lookahead settings make no significant difference (TR pp. 9–10); QP strong branching gives up to 10 times more nodes but almost always less time, with two named outliers CLay0304M/H (TR p. 14); hot starts halve time per candidate (4.23×10⁻⁴ s vs 8.08×10⁻⁴ s, TR p. 14); LP strong branching does not improve runtime (TR p. 15); most-fractional solves only 51% vs more than 92% for the strong-branching variants (TR p. 17). Final comparison with Bonmin's OA "Hybrid": on this B&B-filtered, admittedly biased set, OA fails on 27 of 88 problems (TR p. 18, Fig. 12 p. 21). Some experiments are mentioned but "we do not report here" (TR p. 16), and the reliability setting was chosen "because it seemed slightly better than others" on the same set (TR p. 17).
- **D6 Positioning**: Continues Gupta–Ravindran 1985 (TR p. 3) and imports MILP branching work (Benichou et al.; Applegate et al.; Achterberg et al.; Glankwamdee–Linderoth, TR p. 3). Notes its terminology differs from Achterberg et al. (TR p. 8). Reports a finding that departs from MILP: most-fractional is significantly better than random in the nonlinear setting, whereas for MILP they performed "equally badly" (TR p. 9). Concedes that OA-based methods usually beat B&B in earlier experiments (FilMINT, Bonmin) (TR p. 18), then reframes B&B as "an indispensable tool for solving some difficult MINLPs" (TR p. 19). Own earlier work cited as one of few B&B advances ([28], TR p. 3).
- **D7 Writing and rhetoric**: Contribution stated as numbered goals early (TR p. 3); a plain roadmap paragraph (TR p. 4). Negative results are stated flatly ("Unfortunately, the reduction in the time required to solve (LP) compared to (QP) does not result in overall runtime improvements", TR p. 15). Hedged conclusion: QP-fullstrong is "a viable option and worth trying on difficult problems" (TR p. 18), not "best". Preprint slips visible: "32 MB of RAM" (TR p. 5), "the four problems not solved" followed by five names (TR p. 18), Fig. 8's caption naming NLP reliability while its legend shows three full-strong variants (TR p. 17); whether the JEA version fixes them is not read.
- **D8 Contributions and limits**: Levels: empirical (first systematic modern branching study for NLP-BB), algorithmic (QP/LP strong branching with hot starts), software (code in Bonmin, goal iii, TR p. 3). Limits written specifically: stronger relaxations out of scope (TR p. 4); heuristics and node-selection interactions switched off because they are "not controllable" (TR p. 5); test-set bias toward B&B stated (TR p. 18). Future direction: adapt QP-reliability to OA-based algorithms (TR p. 19).

**Method links**: Method 1 ✅ evidence: the speed-up comes from owning the inner solvers: storing and restoring BQPD's KKT factors, and reading the parent NLP's (x*, y*, H*) as the data for a cheap child model (TR pp. 11–13); confounding solver features turned off for a clean comparison (TR p. 5). Method 5 ✅ evidence: same-framework baselines (TR p. 5), CPU and node meters side by side (TR p. 9), time-outs kept in the tables (TR pp. 25–34), filter and its bias stated (TR pp. 5, 18), losses reported (LP, ECP, outliers; TR pp. 14–16), hedged class-level conclusion (TR p. 18). Method 5 ⚠ variant: parameters (k_rely = 1, μ values) picked on the same 88-instance comparison set, stated openly (TR pp. 7, 17), the tuning/comparison overlap already recorded for FilMINT. Method 2 ⚠ variant: the transfer runs in the other direction, MILP techniques into the NLP-based tree, with the SQP-style QP model as the home-toolkit piece (TR pp. 3, 11–12). Also Heuristic 1 (plain baseline, code revision recorded, TR p. 5), Heuristic 7 (active-set solvers preferred for warm starts, TR p. 4; hot-start benefit measured, TR p. 14), and Taste 2 (revives a method "largely given up on", TR p. 3).
New-pattern candidate: "cheap local model for look-ahead decisions": replace an expensive look-ahead subproblem by the solver's own local model (QP or LP from the parent's derivatives), and keep track of which outputs are valid bounds and which are only guides (TR pp. 11–15).

**Transferable techniques**:
- To speed strong branching in a nonlinear tree, build the child subproblems as QPs from the parent's solution and Hessian and hot-start an active-set QP solver from one stored KKT factorization; use QP infeasibility for fixing/fathoming but never QP values as bounds (TR pp. 11–13).
- Before comparing branching (or any search) rules, switch off heuristics and fix node selection so the rule is the only variable; record the solver revision (TR p. 5).
- Filter the test set by "too easy for all / too hard for all" with explicit thresholds, then say in the conclusion whom the filter favours when you compare with another method class (TR pp. 5, 18).
- Report both a work meter (nodes) and a time meter (CPU) for every comparison, plus a scatter plot for the head-to-head pair, so a rule that trades more nodes for cheaper nodes is visible (TR pp. 9–16).
- Measure a hot-start claim directly as average time per candidate with and without it (TR p. 14).

**Quotes**:
- "Though largely given up on, there is the possibility that B&B can still be made viable for convex MINLP, and that is the subject of the present investigation." (TR p. 3)
- "Unfortunately, the efficiency of the dual simplex method for hot-starting LPs does not have an analogue for general convex NLPs." (TR p. 11)

### S006 · Addressing failures in exascale computing (The International Journal of High Performance Computing Applications 2014, doi:10.1177/1094342014522573)
**Read level**: full, of the workshop-report version dated 3/25/2013 (pp. 1–52 and Appendix A pp. 65–66 read in full; reference list pp. 52–64 skimmed, only the optimization entries [32], [51], [64], [101], [115] checked). First-page check: title "Addressing Failures in Exascale Computing" and "Sven Leyffer" among 29 authors (p. 1). The IJHPCA journal text is not read.
**Role**: core · **Coauthors**: Marc Snir, Robert W. Wisniewski, Jacob A. Abraham, Sarita V. Adve, Saurabh Bagchi, Pavan Balaji, Jim Belak, Pradip Bose, Franck Cappello, Bill Carlson, Andrew A. Chien, Paul Coteus, Nathan A. Debardeleben, Pedro C. Diniz, Christian Engelmann, Mattan Erez, Saverio Fazzari, Al Geist, Rinku Gupta, Fred Johnson, Sriram Krishnamoorthy, Dean Liberty, Subhasish Mitra, Todd Munson, Rob Schreiber, Jon Stearley, Eric Van Hensbergen (p. 1) · **Position in trajectory**: the HPC side line (2001–2016 side lines, Turn F): report of an ICiS workshop at Park City, 4–11 August 2012 (pp. 1, 6). **Attribution caveat**: sections carry no authors. Only the passages on derivative-free and noisy simulation optimization (§5.3, pp. 30–31), Newton merit-function error detection (§5.4.2, pp. 33–34), branch-and-bound and Newton recovery (§5.6.4, pp. 39–40) and the Newton "top-down" view (§6.5, p. 44) use optimization; that they come from Leyffer (or Munson, the other Argonne optimizer on the list) is inferred, not stated. The rest (hardware, OS, MPI, checkpointing) is other authors' material.

- **D1 Problem and entry point**: Entry by listing the assumptions behind today's global checkpoint/restart (checkpoint time and restart time ≪ MTBF, checkpoint correct, committed output correct) and showing why each will fail at exascale (MTBF falling faster than checkpoint and recovery times, more frequent silent data corruptions, real-time use) (p. 2). The question is policy: which of three design points (business as usual, system-level resilience, application-level resilience) to invest in (pp. 2–3, §1.3 p. 7).
- **D2 Core idea and algorithm design**: The report refuses to pick a design point: "we do not have enough information to choose one approach now" (p. 2). It recommends measuring first (Rec. 1: SDC rates and failure logs), costing hardware options with industry (Rec. 2), investing first in technologies needed or useful under any scenario (Rec. 3), and preferring generic application-level methods over point solutions (Rec. 4) (p. 3; §8 pp. 49–52). The optimization passages give algorithm-level ideas: use the Newton sufficient-reduction test on the merit function p(x) = ‖F(x)‖² as an error detector, with a reduced trust region as recovery (p. 33); check gradients through the invariant ∇p = ∇F·F computed by automatic differentiation (p. 33); treat a failed simulation in derivative-free parameter estimation as a simulation failure and use partial information in interpolation models (p. 30); use a smaller word size or variable precision guided by Newton precision bounds (p. 31); recover B&B from the tree, restarting a lost subdomain solve on another node (p. 39); checkpoint only the computational graph, or for B&B only the root node of each distributed solve as two binary vectors (p. 40); resume Newton from a checkpoint without message replay because only the final solution matters (p. 40).
- **D3 Assumptions and model**: Taxonomy adopted from Avizienis et al. (fault → error → failure; detected/latent/masked; §2, pp. 9–12). Metrics: workload efficiency Tsolve/Twallclock, availability, MTBI/MTTI/MTTR, FIT (pp. 12–14). The i.i.d.-exponential failure model is called "clearly false over long periods"; LANL data fit Weibull/gamma with decreasing rate (pp. 14–15). Hardware projections to 11 nm carry stated caveats: particle strikes only, no near-threshold circuits, "order-of-magnitude (at best)" (p. 19; Table 2 p. 20). Resilience mechanisms usually assume a single fault at a time, which needs flawless error-handling software (p. 41). In the Newton passage, errors in low-order mantissa digits are treated like rounding errors, while errors in sign, exponent or sparsity structure must be caught (p. 44).
- **D4 Analysis and proof devices**: Appendix A (pp. 65–66): (a) a renewal/epoch argument: epochs end at a failure or a completed checkpoint, useful work per epoch is τ − C or −R, so utilization = E[Comp]/E[Time] by the law of large numbers, an exact formula (4) that, as the appendix notes, involves no approximation and no assumption on the failure distribution (pp. 65–66); (b) then Poisson failures with MTTF normalized to 1, a first-order condition e^{−τ} = 1 − τ + C, utilization 1 − τ + C − R, solved numerically (p. 66); (c) a three-term Taylor expansion gives τ_opt = √(2CM) and its validity condition C ≪ M (p. 66). In the body: an a posteriori containment bound, error spread to at most ⌈n/k⌉³ nodes after n nearest-neighbour iterations (p. 36); a scale-invariance remark that utilization depends only on checkpoint and recovery times relative to MTTF (p. 46).
- **D5 Numerical experiments**: No algorithm experiments. Evidence used: 382 days of Intrepid (Blue Gene/P) failure data with MTTI 7.5 days vs a 7-day 2006 prediction, reached only after replacing two problem components; the total was predicted within 10% but the per-component split was wrong ("errors canceled each other") (Table 1, pp. 17–18); FIT estimates and protection overheads (Tables 2–3, pp. 20–21); utilization maps (Figs. 5–6, pp. 46–47): more than 80% utilization needs checkpoint time 1–2% and recovery time 2–5% of MTTF, i.e. about 20 s checkpoints and 1 min recovery for a 30-minute MTTF (p. 46).
- **D6 Positioning**: Builds on seven recent reports (DARPA 2009, Blue Waters/TeraGrid 2009, DOE/DOD 2010 and 2012, NCSA/INRIA 2009, CCC 2011, DOE workshop, IESP roadmap) (pp. 8–9) and notes fault tolerance is "as old as computers are", ENIAC's two-day MTTF (p. 9). The optimization passages cite Fletcher's textbook for the sufficient-reduction condition [51], Conn–Gould–Toint for trust regions [32], Moré–Wild on noisy simulations [115] and Linderoth–Wright on asynchronous stochastic programming [101] (pp. 30, 33, 40; refs pp. 54, 56, 59, 60).
- **D7 Writing and rhetoric**: Executive summary with four numbered recommendations before the contents (pp. 2–3); section epigraphs (Wittgenstein p. 6, Mitchell p. 9, Kelvin p. 12); heavy, explicit hedging ("It was not clear that these assumptions are currently satisfied", p. 2; the "pleasant errors" vs "nasty errors" split is offered as a hypothesis still to be validated, p. 48); one joke (exascale systems in "abandoned SSD tunnels or repurposed atomic shelters", p. 26). The optimization passages use one worked mechanism each (a formula, an invariant, a data structure) rather than surveys.
- **D8 Contributions and limits**: Contribution: a shared taxonomy, error-rate estimates, three scenarios and an investment ordering (pp. 2–3, 45–52). Limits written specifically: estimates are order-of-magnitude (p. 19); application-level techniques "are specific to one or to a family of algorithms" (p. 49); checksums not generalized to multigrid (p. 33). Open problems from the optimization passages: analysis of hybrid Newton/Gauss-Jacobi methods after failures (p. 40); "the integration of hardware error models into the convergence analysis of these sampling methods" (p. 34).

**Method links**: Method 2 ✅ evidence (attribution inferred): the home NLP toolkit is carried into a new field: the merit-function sufficient-reduction test and trust-region fallback become a fault detector and recovery (p. 33), the B&B tree becomes the recovery state (pp. 39–40), and noisy-simulation DFO ideas become fault tolerance (pp. 30–31). Method 1 ⚠ variant: "algorithm-level checkpointing can be more efficient than system-level checkpointing" (p. 40), the same move as integrating at the iteration level instead of relying on the packaged layer, here set against the operating system rather than a packaged solver. Trajectory: evidence for the 2001–2016 HPC and inexact-computing side line (variable-precision Newton, p. 31), which he later left without comment (SKILL Turn F); the 2013 "billion-way concurrency" anti-pattern quote does not appear in this report.
New-pattern candidates: "the convergence safeguard as a fault detector": reuse an algorithm's existing acceptance test (sufficient reduction, KKT check) to detect corrupted computations instead of adding redundancy (pp. 33, 44); "checkpoint the minimal algorithmic state": store what the algorithm needs to restart (B&B root bounds as two binary vectors, the computational graph), not the machine state (p. 40).

**Transferable techniques**:
- In a Newton-type solver run on unreliable hardware or inexact linear solves, test each step against the sufficient-reduction condition p(x_k) − p(x_k + s_k) ≥ σ(‖F‖² − ‖∇F s + F‖²); a negative right-hand side flags a failed solve, a failed test triggers a reduced trust-region recompute (p. 33).
- Classify which numerical errors an algorithm tolerates (low-order digits of Jacobian values, residual norm in the line search) and which it must not (sparsity structure, the norm in the convergence test, sign changes that break definiteness) before asking the lower layers for protection (p. 44).
- For a distributed branch-and-bound, checkpoint only each subtree root's variable bounds; a lost node solve is recomputed elsewhere from the tree (pp. 39–40).
- For checkpoint-interval questions, write utilization as E[useful work per epoch]/E[time per epoch] before choosing a failure distribution; only then specialize (Poisson, Taylor) to get √(2CM) and its validity condition (pp. 65–66).

**Quotes**:
- "We can use this condition to detect errors during the computation of the (approximate) Newton step." (p. 33)
- "Similarly, branch-and-bound schemes need only to checkpoint the root node of each distributed solve, which can be stored by using two binary vectors." (p. 40)
