# DFO Team · 决策启发式

每条 = 触发场景 → 规则 → 依据 ID。

## H1 选型三问（最常用）

场景：拿到一个黑盒问题。先问：
(a) f 光滑吗（底层是光滑模拟还是本质非光滑/不连续）？
(b) 评估带噪吗？什么噪声（确定性计算噪声 / 随机噪声）？
(c) n 多大、预算多少次评估、单次多贵？

| 情形 | 建议 | 依据 |
|------|------|------|
| 光滑、低噪、n ≲ 100、评估贵 | 模型型信赖域（Powell 谱系 / CSV 框架） | [DFO-S2] 基准证据 + [DFO-S16] 理论 |
| 非光滑或硬约束、需要可证收敛 | MADS 类网格自适应直接搜索 | [DFO-S14] |
| 高维、随机噪声、可接受期望保证 | 随机 zeroth-order（两点估计优先） | [DFO-S4, S21] |
| 病态、多峰、预算充足 | CMA-ES | [DFO-S6, S8] |
| 噪声主导、需要先搞清噪声 | 先做噪声估计（ECNoise），再定差分区间 | [DFO-S22, S3] |

## H2 永远用评估次数计费

报告/对比里的 x 轴是函数评估次数（必要时加 wall-time 第二轴）。
注意 (d+1) 口径：把 simplex 梯度算一次还是 d+1 次评估会改变算法排名——
这是用户自己项目里实证过的 [DFO-L1：「rankings are sensitive to this
accounting convention」]。报告必须声明口径。

## H3 基准测试纪律

- data profiles + performance profiles，两者都给 [DFO-S2]。
- fixed-budget 和 fixed-target 两个视角都看 [DFO-S8]。
- 多起点/多种子，报告不确定性；单次运行的最终值排名不可信 [DFO-S2 content]。
- 测试集声明维度范围与问题类别；结论限定在测过的范围内。

## H4 噪声下的差分区间

前向差分的区间要平衡 Taylor 截断误差与噪声（定性：h 随噪声水平升高而增大）；
自适应区间估计以额外评估为代价换可靠的梯度近似 [DFO-S3 content]。
不要在带噪问题上使用为无噪设计的固定小 h。

## H5 Nelder–Mead 不做免检默认

可以用 NM 做快速基线，但 (a) 引用它时声明「无一般收敛保证」[DFO-S10]；
(b) 任何正式对比里 NM 之外至少再放一个有保证的方法（MADS 或模型型）。

## H6 梯度近似方式是设计变量

有限差分 / 插值模型 / 随机平滑三类估计在样本数、半径、偏差、方差上的
权衡各不相同 [DFO-S7 content]，选哪种要和噪声模型、预算一起定，
不能默认「差分=唯一选择」。

## H7 报告规范（用户固定约定）

- 一律 min f(x) 形式。
- 算法对比：先伪代码 + 五步逐迭代手算示例，再谈结果。
- 收敛声明：定理 + 假设 + proved-vs-cited 标注（见 04-results）。
- 比较报告的固定顺序：文献综述 → 算法推演 → 收敛证明 → 数值表现。
